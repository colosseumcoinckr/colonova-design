# ColoNova Design 기능 목록 — 관리 문서

앱이 지원하는 기능을 한 장에서 본다(2026-11-03 사용자 요청). **앞으로 이 프로젝트의 기능 관리 — 목록 · 상태 ·
계획 · 걷음 표시 — 는 이 문서로 한다.** 이 문서는 색인이다. 사용자 면의 문장은 [GUIDE](GUIDE.md), 동작의
상세는 [DEVELOPERS](DEVELOPERS.md) 가 정본이고, 여기에는 기능의 이름 · 하는 일 · 상태를 줄 단위로 싣는다.
기능을 검토하거나 계획을 세울 때 이 목록에서 훑는다. 문서 위치는 `docs/FEATURES.md`이며 상대 링크는 이 위치를 기준으로 한다.

**정리 기준: 2026-11-13 · 데스크톱 0.9.2 · 소스 `4ccbf1e`.** 사용자 요청으로 기존 목록 전 영역을 다시 읽고,
기획서·화면·설치 및 운영의 주요 구현 경로를 코드와 대조했다. 모든 기능 행을 실행하거나 모든 분기를 검사한 것은 아니다. 아래는 현재 체크아웃의 기능 목록이며, 배포된 앱이 모두 같은 상태라는 뜻은 아니다.
이번 작업은 문서 정리다. 앱 실행·전체 시험·실제 Confluence 발행·GitHub 제출은 수행하지 않았다.
기존 검증 기록은 해당 범위와 함께 유지했고, 새로 찾은 기능은 `🔎 코드 확인`으로 표시했다.
2026-11-13 정리로 날짜 붙은 계획 · 방향 · 설계 · 검토 문서를 걷었다 — 남은 근거는 이 문서와 GUIDE · DEVELOPERS · `intend.md` · AGENTS 가 이어받고, 역사는 git 이 지킨다.

## 이 문서를 관리하는 법

- 기능을 더하거나 바꾸거나 걷는 변경은 **같은 변경에서 이 문서의 해당 줄**을 고친다(AGENTS.md 의 문서 규칙과
  같다). 걷힌 기능의 줄은 [일부러 만들지 않은 것](#일부러-만들지-않은-것) 절로 옮기거나 지운다 — 역사는 git 이 지킨다.
- 상태와 근거는 아래처럼 읽는다. 코드 확인만으로 시험 통과나 실제 사용 완료로 올리지 않는다.

| 표 | 뜻 |
| --- | --- |
| ✅ | 기존 문서에서 동작으로 관리하는 기능. 견본·실앱 등 별도 단서가 있으면 그 범위가 우선이며, 이번 정리에서 재실행한 결과는 아니다 |
| 🧪 | 기존 시험 통과 기록이 있는 구현. 실제 앱·외부 서비스에서 남은 검증은 해당 행에 적는다 |
| 🔎 | 구현 코드 확인. 이번 정리에서 실행 결과를 확보하지 않았으므로 동작·시험 통과를 단정하지 않는다 |
| 🚧 | 계획됨 — 임계 · 관찰 뒤에 열린다 |
| ✖️ | 일부러 만들지 않았다 |

- 검증 근거는 **환경·방법·확인한 범위·남은 범위** 순으로 적는다. 견본 화면 확인, 자동 시험, 실제 앱·외부 서비스 사용은 서로 대신하지 않는다. ✅도 행의 단서와 근거를 확인해야 하며, 근거가 없는 행은 배포 승인 근거로 쓰지 않는다.
- 결정에는 날짜와 출처를 적는다(레포 규칙). 2026-11-03 정리로 걷힌 계획 문서(같이 고치기 · 기획서 칸 · 화면
  자리 · 기획 대화 · 홈 걷기 · 프로젝트별 자격)의 상태는 이 문서가 이어받는다.
- 새 기능을 만들 때: 여기 줄이 없으면 기능이 아니다 — 먼저 줄을 만들고 상태를 🚧 로 단다. 구현하고 시험 통과 근거를 확보하면 🧪,
  눈 검증을 마치면 그 환경과 범위를 적고 ✅ 로 바꾼다. 코드만 확인했으면 🔎 로 둔다.

## 한눈에

- **말과 문서를 서비스의 진짜 화면으로** — 비개발자가 말로 주문하면 AI(Claude Code, Agent SDK)가 연결
  레포의 실제 화면을 고치고, `제출` 한 번으로 풀 리퀘스트를 연다(0.9.2 · macOS Apple 실리콘 · Windows x64).
- **셸은 두 자리** — `기획서` · `화면`(2026-10-31 홈 걷기). 화면 자리는 미리보기가 가운데, 대화 · 기획서 ·
  작업 기록이 오른쪽 칸이다(2026-10-31 화면 자리 개선 S15).
- **기획 SSOT 는 Confluence** — 앱은 읽어 오고, 본문·제목 고침은 이 컴퓨터의 초안에서 AI 와 함께, 발행은 사람이
  확인 창을 지나 한다. 화면에서 바뀐 결정은 곁줄 카드로 물은 뒤 사람이 눌러 이어진 기획서의 초안까지
  반영한다(2026-11-03 A안 — 옛 「자동으로 되돌아간다」(2026-10-30) 문구를 2026-11-11 대조 문서에서 고쳤다).
- **일의 한 바퀴** — 말하고 → 찍고 → 제출 → 개발자 코멘트 · 검사 확인 → 반영 → 받아오기. 저장 버튼은
  없다 — 답마다 저절로 보관된다.
- 패키지 — `packages/protocol`(선로 v19) · `daemon`(세션 · 레포 · 감독자) · `web`(UI, `src/next/`) ·
  `desktop`(Electron). 데이터는 `~/.colonova-design/` 하나.

문서에서 쓰는 위치 이름: **자리**는 `기획서`·`화면` 탭, **국면 알**은 화면 작업 상태 표시,
**작업 독**은 입력창 위 진행 줄, **결과 띠**는 AI 답 끝의 변경 결과, **곁줄**은 화면 대화의 기획서 관련 카드다.
`S`·`U`·`C`·`F`로 시작하는 번호는 기존 설계·조사에서 항목을 추적하던 식별자이며 사용자 조작 순서가 아니다.
`U-번호`는 2026-11-12 UI 조사와 수정 기록에서, `㉮–㉳` 결정은 같은 날 설계에서 왔다(원문 문서는 2026-11-13 정리로
걷었다 — 역사는 git 이 지킨다). 옛 `S`·`C`·`F`·`1A` 단계의 현재 설명은
[사용 설명서](GUIDE.md)·[개발자 안내](DEVELOPERS.md), `G0–G5`는 개발자 안내의 Confluence 실측 절을 본다.
이전 원문이 남지 않은 식별자는 이 문서가 이어받은 이력이며, 현재 시험 결과를 증명하는 링크가 아니다.

## 실제로 쓰는 흐름과 저장 범위

| 하려는 일 | 앱 안의 흐름 | 결과와 다음 손 |
| --- | --- | --- |
| 처음 사용 | 도구 준비 → AI 연결·초대 파일 → 프로젝트 준비 | 연결된 서비스 화면이 열린다. 기획서를 쓰려면 Confluence를 추가 연결한다 |
| 기획서 작성 | 문서 읽기·새 문서 → 직접 또는 AI로 초안 고침 → 전후 검토 → 발행 | 발행 전에는 이 컴퓨터의 초안이다. 사람이 발행하면 Confluence 원본에 반영된다 |
| 화면 수정 | 말·첨부·찍기 → AI 수정 → 자동 보관 → 실제 미리보기 확인 | 보관된 작업은 이 컴퓨터에 있다. 다른 대화로 옮겨도 같은 프로젝트의 화면을 이어 쓴다 |
| 개발자에게 전달 | 제출 내용 확인 → 제출 → 코멘트 확인·추가 요청 → 개발자 반영 → 최신 내용 적용 | 제출은 GitHub 요청을 만든다. 개발자가 반영하며, 서비스 공개 여부는 앱이 알지 못한다 |
| 기획서와 화면 맞추기 | 근거 보내기·연결 → 자동 판정 또는 직접 맞춰 보기 → 카드 선택 | 화면 요청 또는 기획서 초안으로 이어진다. 초안을 원본에 싣는 발행은 사람이 한다 |
| 잘못된 변경 복구 | 화면은 작업 기록, 기획서는 초안 판 선택 → 되돌림 | 이미 발행한 문서는 되돌린 초안을 다시 발행한다. 화면 되돌림은 다음 제출에 포함된다 |

| 동작 | 쓰는 곳 | 다른 사람에게 전달되는 시점 |
| --- | --- | --- |
| 화면 보관·되돌리기 | 이 컴퓨터의 연결 레포와 작업 기록 | 사람이 `제출`할 때 |
| 직접·AI·화면에서 온 기획서 고침 | 이 컴퓨터의 `plans/` 초안·판 기록 | 사람이 `발행`할 때 |
| Confluence 가져오기 | 이 컴퓨터의 읽기 전용 `confluence/` 사본 | 원격 원본을 고치지 않는다 |
| 라벨·코멘트·복제·이동·휴지통·복구 | Confluence에 직접 쓰기 | 해당 동작을 실행할 때. 본문 초안 발행과 별개다 |
| 문서와 화면 연결 | 연결 레포의 `plans-map.json` | 레포의 보관·제출 경로로 공유한다 |
| 앱의 대화·설정 | 각자 PC의 앱 데이터와 사용자 설정 | 다른 사용자와 실시간 공유하지 않는다 |

Confluence 쓰기는 데스크톱에서 기본으로 열리며 단독 데몬은 환경 설정이 필요하다([13.1](#131-발행)).
원격 쓰기 권한은 연결한 계정에 따른다. 라벨·코멘트·문서 관리를 초안에 모으는 설계는 아직 구현된 것으로 보지 않는다.

### 1.3 국면 알과 상태 줄

| 기능 | 하는 일 | 상태 |
| --- | --- | --- |
| 국면 알 하나(S1) | 옛 여정 세 점 대신 알 한 문장 — `제출 전 · 화면 N곳` · `개발자 확인을 기다려요 · 코멘트 N` · `반영을 기다려요` · `개발자 반영 완료`(막히면 빨강) | ✅ |
| 알 점 색 | 국면색(제출 전 파랑 · 확인 호박 · 반영 초록 · 막힘 빨강), AI 작업 중 숨쉼(S2) | ✅ |
| 새 내용 배지 | 새 내용이 있으면 알림 — 누르면 `이번 작업`의 최신 내용 적용 칸. 커밋 수는 표시하지 않음 | 🧪 [8.3의 검증 범위](#83-최신-내용-적용) |
| 기다림 날짜 | 코멘트 없으면 `· 2일째`(제출한 날 = 1일째, 자정 경과마다 +1). 승인 · 변경 요청 · 닫힘엔 안 붙음 | ✅ |
| 승인 판정 | 리뷰어별 마지막 판정. 「LGTM」 승인도 코멘트 아님. 변경 요청 1명이라도 남으면 승인 아님 | ✅ |
| 알 접힘 | 두 단계 — 폭이 줄면 글자가 접혀 배지 · 점만. 알의 말과 `제출` 은 900px 아래에서도 유지 | ✅ |
| 국면 판정 | 전부 기계 신호(보관 여부 · 요청 상태) — 사람이 임의로 못 바꿈 | ✅ |
| 제출 단추 다섯 얼굴 | idle · running · retrying · done · failed 한 줄 전환, 폭이 글에 맞음 | ✅ |
| 잠긴 제출 | 공통 꺼진 단추 모양(`aria-disabled`), 이유 툴팁 → 누르거나 초점 주면 말풍선(`aria-describedby`, 초점 중 유지) | ✅ |

## 계획·보류와 남은 검증

계획은 지원 완료 기능이 아니다. 구현된 기능의 실사용 검증이 남은 경우도 새 기능 계획과 구별한다.

| 항목 | 현재 위치 | 다음 조건·근거 |
| --- | --- | --- |
| 미결 읽기 | 🚧 문서 머리·화면 옆 기획서의 `미결 N`부터, 전체 모아 보기는 이후 | 실제 사용자 한 바퀴와 기존 연결 기능 굳히기 뒤. [의도](../intend.md) |
| 화면에서 기능설계서 화면 절 초안 뽑기 | 🚧 다음 후보 | 연결 기능을 굳힌 뒤 연다. [의도](../intend.md) |
| 연결 표 밖 자동 대상 찾기 | 🚧 C1 및 뒤따르는 단계 | 정확도·비용 측정 뒤. 찾기는 세 층(확실 신호 · 로컬 색인 · 목차 판정 — 2026-11-03 방향) — 채택된 후보는 연결 줄로 굳고, Rovo 는 핵심 경로 밖 꼬리의 선택이다. [14.2](#142-같이-고치기와-맞춰-보기) · [현행 의도](../intend.md) |
| 설계의 조건부 조각 열셋 | 🚧 첫 실사용 기록에 막힘이 있을 때만 하나씩 검토 | 화면 옆 직접 편집·다른 사람 요청 표시·발행 뒤 자동 비교는 의도 변경 없이 열지 않는다. [의도](../intend.md) |
| Confluence 기능 정렬 | 🚧 라벨·코멘트·문서 관리의 직접 쓰기는 현행 유지 | 본문과 함께 초안에 모으는 흐름은 후속 설계. [발행·관리의 현행 설명](GUIDE.md) |
| 발행·같이 고치기·맞춰 보기 | 🧪 구현·기존 시험 및 일부 여정 기록 있음 | 실제 Confluence와 각 분기의 남은 검증은 9·13·14절 및 [개발자 안내](DEVELOPERS.md) |
| 최신 기준 준비·의미 단위 보관 | 🧪 구현·로컬 시험 기록 있음 | 실제 Electron·Windows·원격 GitHub 여정은 확인 밖이다(계획 문서는 2026-11-13 정리로 걷었다) |
| 실제 사용자 첫 한 바퀴 | 별도 실사용 검증 | 자기 PC·계정으로 첫 발행과 첫 개발자 반영까지. 걷는 법과 기록 칸은 [개발자 안내](DEVELOPERS.md)의 초대 절. 과거 MVP 완료와 구별 |

없는 것이 빠진 것이 아니라 결정이다. 새로 없애면 이 절로 옮긴다.

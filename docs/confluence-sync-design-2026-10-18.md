# Confluence 기획서 동기화 — 구현 설계

2026-10-18. "만들어지면 실제로 어떻게 나오는가"를 적은 설계 문서다. 배경 · 판단 근거 · 범위 결정은
[계획 문서](confluence-sync-plan-2026-10-18.md)에 있고, 여기서는 반복하지 않는다. 파일 · 화면 이름은
구현 전 제안이며, 착수 때 확정한다.

## 한 화면으로 보는 동작

```
  Confluence (게시판 — 공식본)
      ▲                        │
      │ 발행 (버튼)             │ 가져오기 (자동 — 폴링)
      │                        ▼
  CDP 레포 docs/plans/ (책상 — 작업본)
      ├── 화면과 같은 방 → AI 가 문서·화면을 같이 본다
      └── 앱 오른쪽 칸에서 열람 · 고침 → 절 단위 발행
```

## 사용자가 보는 것

### 연결 — 설정의 `연결` 쪽에 한 덩어리

- `Confluence 사이트` 주소와 `Confluence 토큰` 입력 칸. 토큰은 키체인으로 바로 들어가고 화면으로는
  돌아오지 않는다(연결 코드와 같은 취급).
- 기준 페이지 고르기 — 기획 루트가 될 페이지 하나(예: `8.8 ColoNova`). 가져오기는 그 아래만 한다.
- 연결이 되면 상태 한 줄: `어제 가져왔어요 · 바뀐 문서 3개`.

### 기획서 목록과 보기

- 사이드바에 `기획서` 항목이 하나 더 선다(홈 · 찾기 아래). 누르면 오른쪽 칸이 미리보기에서
  기획서 보기로 바뀌고, `미리보기` 로 돌아오는 길이 위에 남는다.
- 목록은 Confluence 트리 그대로 — 폴더는 페이지 계층, 문서는 제목과 판(0.8 같은 단계 표시).
- 문서를 누르면 파생 마크다운이 렌더된다. Confluence 코멘트 중 안 풀린 것은 문서 위에 같이 보인다 —
  읽기는 1단계, 달기·답글은 2단계다(아래 「코멘트 — Confluence 가 정본」).
- 매크로가 든 절은 `이 절은 Confluence 에서 고쳐요` 표시가 붙고 편집 칸이 열리지 않는다 —
  도구가 표현할 수 없는 것을 덮어쓰지 않게 하는 규칙이다(계획 문서 「Confluence 실측」).
- 새 기획서 만들기 — 조직의 전역 템플릿에서 복제해 시작한다(`솔루션 기획양식` 등 — 2026-10-18 실측으로 존재 확인).

### 고치기와 발행

- 편집 가능한 절에서 `고치기` → 절 하나가 편집 칸(마크다운)으로 열린다. 절 단위가 편집과 발행의
  단위다. 새 절 덧붙이기도 절 단위다.
- 상태 줄의 `제출` 옆 감각으로 `발행` 단추가 선다(기획서 화면을 볼 때만). 누르면 확인 창(겹판)이
  열린다 — 바뀐 절 목록 · 목표 판 단계(같은 단계 개정이 기본, 승급은 여기서 고른다) · 발행 대상 문서 수.
- 발행은 문서마다 절 단위로 날아가는데, 몸은 **저장 포맷 절 스플라이스**다 — 정본(storage.xml)에서 해당 절만
  갈아 끼워 넣는다. 마크다운 왕복은 앵커와 매크로를 잃으므로(2026-10-18 실측), 편집 칸의 마크다운을 저장
  포맷으로 바꿔 끼우되 앵커가 든 문단은 정본에서 그대로 이식한다. 끝나면 문서마다 `발행됨 · 판 N` 이
  원장에 적힌다. 정본 전체를 다시 싣는 전체 재발행도 저장 포맷이면 무손실이다(2026-10-18 실측) — 절
  스플라이스가 기본이고, 절 경계가 흐트러진 큰 개정은 전체 재발행으로 간다.

### 충돌 흐름 — 스펙 §5 그대로

```
  A 가 문서를 가져옴 (판 5)  →  B 가 Confluence 에서 판 6 으로 바꿈  →  A 가 [발행]
      → 발행이 409 로 멈춘다
      → 확인 창: "그 사이 누가 고쳤어요 · 판 5 → 6"
      → Confluence 판 차이(공식 diff)를 보여 준다
      → A 는 편집 칸에서 둘을 합치고 다시 발행 → 판 7
```

- 판 검사는 발행 직전에 원장의 판과 Confluence 의 판을 비교해 하는 이중 검사다(409 가 와도 같은
  화면으로 흘러 들어온다).
- 코멘트는 판을 안 올리므로 충돌로 치지 않고, 가져오기 때 따로 받는다.

### 코멘트 — Confluence 가 정본

- 코멘트의 정본도 Confluence 다. 앱은 읽고 쓰는 창일 뿐 사본을 만들지 않는다 — "사본은 두 벌뿐"을 지킨다.
- 문서에서 글을 선택해 `코멘트` — 인라인 코멘트는 Confluence 와 같은 앵커 모델(본문 텍스트 선택)이라
  Confluence 화면에서도 같은 자리에 붙는다(2026-10-18 실측). 바닥글 코멘트와 답글 스레드도 그대로 온다.
- 매크로가 든 절은 읽기만 된다 — 앱에서 고칠 수 없는 자리에는 새 코멘트도 달지 못하게 막는다.
- 코멘트는 판을 안 올리므로 충돌 흐름과 얽히지 않고, 가져오기가 따로 받는다(실측 · CONFCLOUD-82395).

## CDP 레포에 생기는 것

기획서 폴더는 사이클 브랜치 안의 `docs/plans/`(배치 A 안 — 2026-10-18 권고). AI 는 이것을 그냥
파일로 읽는다 — 문서와 화면이 같은 방이다.

```
docs/plans/
  confluence.json                          # 원장 — 동기화의 정본
  COLO/8.8-ColoNova/01-시스템분석/
    <페이지-제목>.md                        # 보기·고치기용 파생 마크다운 (frontmatter 아래)
    <페이지-제목>.storage.xml               # 정본 — Confluence 저장 포맷 원문
```

문서 파일의 머리(예시):

```yaml
---
confluence:
  pageId: "1818591273"
  space: "~63dcb628491b20ef64b9cd71"
  title: "ColoNova 데이터 모델 — 기획 참조용 (SSoT)"
  version: 1
  updatedAt: "2026-06-16T01:32:32Z"
stage: "0.8"          # 조직의 판 단계 표기 — Confluence 판 번호와 별개
---
```

원장 `confluence.json`(예시):

```json
{
  "site": "https://colosseum.atlassian.net",
  "roots": ["933068815"],
  "lastSyncAt": "2026-10-18T00:40:00Z",
  "pages": {
    "1818591273": {
      "path": "COLO/8.8-ColoNova/…/SSoT",
      "version": 1,
      "sections": [{ "heading": "도메인 지도", "macro": false }],
      "comments": { "unresolved": 2 }
    }
  }
}
```

- 어디서 끊겨도 다음 시작이 이어받는다(cycle.json 원장의 규칙과 같다).
- 제출(풀 리퀘스트)에서 기획서 폴더는 빠진다 — `saveable-paths` 거름에 규칙 한 줄.
- Confluence 는 페이지 ID 가 이동해도 변하지 않는다(2026-10-18 실측 — 이동 시 판도 안 오른다). 원장은
  ID 로 문서를 추적하고, 폴더 경로는 가져올 때마다 트리에서 다시 계산한다. 복제는 판이 1 로 다시 시작되는
  새 문서다 — 새 기획서 만들기(템플릿 복제)가 이 길을 쓴다.

## 데몬의 새 부품

| 파일(제안) | 하는 일 | 따르는 선례 |
| --- | --- | --- |
| `confluence-client.ts` | REST 호출 — 페이지 · 트리 · diff · 코멘트. fetch 기반 | `github.ts` |
| `confluence-sync.ts` | 가져오기 루프 — 바뀐 페이지만 CQL 로 찾아 폴더에 내려쓰고 원장을 고침 | 감독자 관찰 틱 · `repo-bringup` |
| `plans-publish.ts` | 발행 — 저장 포맷 절 스플라이스 PUT, 판 검사, 원장 표식 | `repo-publish.ts` 의 표식 먼저 · 멱등 키 |
| `credentials.ts` (덧붙임) | `confluence-pat` 항목 + `COLONOVA_DESIGN_CONFLUENCE_TOKEN` 오버라이드 | 기존 `pat` 항목과 같은 모양 |

- 가져오기 간격 — 앱을 켤 때 · 창이 앞으로 올 때 · 10분 간격(레포 최신화와 같은 감각). CQL
  `lastModified > 마지막 동기` 로 바뀐 페이지만 내려받는다(실측 통과). 코멘트도 결과에 섞여 오므로
  질의에 `type=page` 를 묶는다.
- 파일 쓰기는 git-lane 을 지난다 — 데몬의 git 쓰기는 이미 한 줄로 직렬화되므로 턴 도중에도 겹치지 않는다.
- 토큰은 데몬만 안다. 화면 쪽 코드로는 절대 가지 않고, AI 세션 환경에도 싣지 않는다 — 발행은 앱(데몬)의
  일이지 AI 의 일이 아니다.

## 선로에 더하는 것 (모두 선택 필드 — 버전은 안 올림)

- `DaemonStatus.confluence?` — 연결 여부 · 사이트 · 마지막 가져오기 · 발행 대기 수.
- 명령 `confluence.connect { site, token }` · `confluence.importNow` · `confluence.publish
  { path, expectedVersion }` · `doc.save { path, content }` · `doc.comment.add { pageId, body,
  anchorText?, parentId? }` — 웹은 디스크를 만지지 않으므로 문서 고치기와 코멘트 달기도 명령으로 간다.
  멱등 키 규칙은 기존 명령과 같다.
- 기획서 상태는 `ProjectSummary` 의 선택 필드로 목록에 실린다.

## 보안과 가드

- 토큰 — 사용자 각자의 API 토큰을 각자의 키체인에. 수집 · 전달 없음(정책 절과 같은 선上).
- AI — 기획서 폴더는 읽기 전용 사본이다. D1(폴더는 보관 · 제출에서 빠진다)로 AI 가 고친 글은 아무 데도 가지
  않으므로, Claude 의 파일 쓰기 도구는 쓰기 가드(`write-guard.ts`)가 거절하고 셸 쓰기와 Codex 는 공통 규칙의 한
  구절이 맡는다(2026-10-19 — 이 줄의 옛 문장 「그냥 변경이고 자동 보관이 `docs:` 커밋으로 담는다」는 D1 전의 것이다).
  AI 에게 Confluence 토큰·도구는 주지 않는다(1단계 방침).
- 제출 거름 — 기획서 폴더는 풀 리퀘스트에 안 탄다. 화면 변경의 기록만 개발자에게 간다.

## 시험 (CI 는 순수 시험만 — 프로세스 시험은 로컬)

- 저장 포맷 ↔ 파생 마크다운 변환(표 · 목록 · 매크로 절 판정 포함).
- 절 나누기와 절 단위 발행 본문 만들기.
- 판 검사 — 낡은 판이면 충돌 상태로(409 와 같은 길).
- 닻 탐지 — 인라인 코멘트가 든 절을 교체하려 하면 경고 상태.
- 코멘트 앵커 — 선택한 문장이 저장 포맷 문단과 맞아 떨어지는가(한글 본문 포함).
- 거름 — 기획서 폴더가 보관 · 제출 목록에서 빠지는가.
- 원장 — 깨진 값 버리기 · 이어받기(parse* 계열 선례와 같다).
- 라벨 — `가져오기` · `발행` · `기획서` 단어 추가와 금칙어 시험 갱신.
- 실제 Confluence 와의 맞춤(인증 · 닻 보존)은 로컬 확인 목록 — 계획 문서의 사전 검증 2가지.

## 문서 갱신 (코드와 같은 변경에서)

README(기능 소개 한 덩어리) · GUIDE(`기획서` 화면 절 + 설정 연결 쪽 + 자주 묻는 질문) ·
DEVELOPERS(동기화 · 발행 · 충돌 · 토큰 · 환경 변수 · 시험 절) · ux-survey 개정 이력 ·
AGENTS.md 의 꼭 알아야 할 것(기획서 폴더 한 줄).

## 착수 순서 (1단계)

1. `confluence-client.ts` + 인증 검증(사전 검증 1) — 실제 사이트로 읽기 확인.
2. 토큰 항목 + 설정 `연결` 쪽 입력 칸 + `confluence.connect`.
3. 가져오기(트리 → `docs/plans/` + 원장) + 파생 마크다운 변환.
4. 기획서 목록 · 뷰어 화면 + 라벨 · GUIDE.
5. 코멘트 보기 + 인라인 코멘트 닻 전수 조사(사전 검증 2) — 2단계 발행과 코멘트 달기 설계의 입력.

# 기획 올인원 작업공간 — 최종 구현 계획

2026-10-22 전면 재검토, 2026-10-23 검토 반영. 출처: 사용자가 설명한 현재 회사 업무 흐름, 기획 올인원 전환 완료 목표, Confluence SSOT 위치와 직접 편집 유지 조건. 목표와 원본 위치는 사용자 결정이다. 아래 구현 방식과 순서는 그 목표를 위한 재검토 권고이며, 외부 조건은 실측으로 닫는다.

**요청 해석:** Claude Desktop에서 AI와 기획서를 쓰고, Confluence에 올리고, 별도 도구에서 데모를 만든 뒤 CDP로 옮기던 작업을 ColoNova Design 안에서 끝낸다. Confluence를 대체하거나 로컬 문서를 새 원본으로 삼는 전환이 아니다. 이번 변경은 계획 개정이며 기능 구현·Confluence 쓰기·릴리스가 아니다.

이 문서가 제품 범위·우선순위·완료 기준의 정본이다. 현재 제공하는 기능은 [사용 설명서](GUIDE.md)와 [개발자 안내](DEVELOPERS.md)를 따른다. [동기화 설계 이력](confluence-sync-design-2026-10-18.md)과 [화면 연결 설계 이력](plans-screen-link-plan-2026-10-19.md)의 상자·제안 API는 실행 대기열이 아니다. 기존 링크를 유지하려고 이 파일의 이름은 바꾸지 않는다.

**2026-10-23 결정(계획 검토 뒤):**

- 화면 AI가 사용자 자신의 MCP로 Confluence에 쓰는 것은 막지 않는다. 앱은 그 쓰기를 외부 편집으로 다룬다(§6 · §8). 사용자 결정.
- 기획 AI는 지정 SSOT 범위 안 캐시를 읽기 전용으로 조회할 수 있다(§6). 사용자 결정.
- F3는 F1 뒤 초안 기준으로 시작하고, 공식본이 필요한 부분만 F2를 기다린다. 기본 CRUD(휴지통 이동 포함)까지를 전환 완료 문턱에 둔다. 복제·위치 변경·복구·코멘트 쓰기는 범위에 남기되 전환 완료 뒤 후속(F4)이다(§12). 사용자 결정(검토 권고 채택).
- 업무 단계 표기가 1.0 이상인 문서의 발행은 조직 판 정책을 따르는 개정 발행이다. 표기는 안내와 추가 확인에만 쓰고 잠금에 쓰지 않는다(§7). 사용자 결정(검토 권고 채택).

## 1. 목표와 업무 흐름

> 기획자가 ColoNova Design에서 AI와 기획서를 작성·수정하고, Confluence 공식본으로 발행하고, 그 근거로 CDP의 실제 화면을 만들어 확인하며, 발견한 결정을 다시 기획서에 남긴다.

| 구분 | 흐름 | 남는 역할 |
| --- | --- | --- |
| 회사의 현재 흐름 | Claude Desktop에서 AI와 문서 작성 → Atlassian MCP로 Confluence 게시 → 사람이 Confluence에서도 추가·수정·삭제 → Claude Design에서 데모 구현 → 개발자가 CDP로 포팅 | 2026-10-22 사용자 설명을 기준으로 한다. 제품 이름이나 전달 방식을 임의로 바꿔 해석하지 않는다. |
| 기존 ColoNova Design MVP | Confluence 기획을 바탕으로 도구에서 연결된 CDP 레포의 화면을 직접 구현·확인·제출 | 별도 데모의 CDP 포팅 단계를 줄이는 화면 제작 기반이다. |
| 전환 완료 후 | 앱에서 AI와 기획 작성 → 사람이 변경안 채택·편집 → Confluence 발행 → 앱에서 CDP 데모 구현·확인 → 필요하면 기획을 다시 수정·발행 → 화면 제출 | Confluence는 공식 기록과 외부 편집 창으로 남는다. 개발자는 CDP 변경을 검토·수정·반영한다. 개발자 검토나 운영 배포를 없애는 목표가 아니다. |

문서 발행과 화면 제출은 별개다. 어느 쪽도 다른 쪽을 자동 실행하지 않는다. 기본 안내는 문서 발행 후 화면 제출이다. 초안으로 화면을 먼저 검증할 수도 있지만 미발행 상태를 숨기지 않는다.

올인원 완료는 편집기와 미리보기를 나란히 놓는 것이 아니다. **새 기획을 AI와 시작하는 일부터 문서·화면·개발자 전달까지, 필수 경로에 Claude Desktop·Claude Design·수동 복사·별도 데모 포팅이 없어야 한다.** Confluence에서 사람이 직접 고치는 길은 계속 유효하다. 코멘트 쓰기와 복제·위치 변경·복구는 이 필수 경로 밖이다. 전환 완료 뒤 후속(F4)으로 앱에 들이고, 그동안 Confluence에서 한다(2026-10-23). 미리보기 성공은 운영 적용이나 정책 준수의 자동 판정이 아니다.

## 2. 원본 범위와 확인한 근거

### Confluence SSOT

- 사이트: `https://colosseum.atlassian.net`, 공간: `PROD`.
- 기준 페이지: [SSOT 정책서 & 기능설계서](https://colosseum.atlassian.net/wiki/spaces/PROD/pages/1767604270/SSOT), ID `1767604270`.
- **기획 SSOT는 이 기준 페이지의 하위 문서다.** 기준 페이지 자체는 탐색·안내 문서다. 임의의 COLO 릴리스 페이지나 사이트 전체를 기준 범위로 바꾸지 않는다. 프로젝트 설정에 이 연결을 기록하며 제품 코드에 회사 주소를 하드코딩하지 않는다.
- 문서 ID와 콘텐츠 종류로 식별한다. 제목·URL의 제목 부분·로컬 경로는 식별자가 아니다. 링크가 가리킨다는 이유만으로 범위 밖 문서를 발행 대상으로 편입하지 않는다.

2026-10-22 현재 MCP 계정으로 하위 트리를 읽었다. `depth=10`, `limit=250`의 결과는 다음 페이지 링크 없이 235개 항목이었다. 실제 최대 깊이는 4다. **기준 페이지를 제외하고 페이지 223개, Confluence 폴더 12개이며, 페이지 94개는 폴더를 조상으로 둔다.** 이는 해당 계정에 보인 시점별 관찰이지 영구 문서 수나 앱 자격의 접근 보장이 아니다.

최상위는 `[PD] Platform Admin`, `[TD] SETTING`, `[TD] WMS`, `[TD] OMS` 페이지와 `OMS·WMS_공통 설계` 폴더다. 정책서와 기능설계서뿐 아니라 공통 가이드·상태 정책·참조 문서가 함께 있다. 한 정책 절만 AI에 넘기는 것으로 모든 작업 맥락이 충족된다고 가정하지 않는다.

## 3. 기존 계획 재검토 판정

| 판정 | 대상 | 이유와 새 기준 |
| --- | --- | --- |
| 유지 | Confluence 공식본, 로컬 초안, 읽기 전용 `docs/plans/` | 원본은 하나다. 로컬은 작업·복구 수단이며 독립 기획 원본이 아니다. |
| 변경 | AI 제안·채택 제외 | Claude Desktop의 핵심 업무를 대체하지 못한다. AI와 대화하며 새 문서를 만들고, 변경안을 검토·부분 채택·거절·재요청하는 기능을 필수로 넣는다. 자동 채택·자동 발행은 제외한다. |
| 변경 | 기존 문서의 절 편집부터 시작 | 새 정책서·기능설계서 작성이 핵심 진입점이다. 빈 문서·밑그림으로 시작하고, 글·절·표의 추가·수정·삭제를 다룬다. 새 문서 생성을 마지막 부가 기능으로 미루지 않는다. |

| 변경 | 지원하지 않는 절은 Confluence로 보내면 완료 | 원문 보존을 위한 안전한 예외 경로는 필요하다. 그러나 대표 업무의 표·문단 편집이 계속 외부로 빠지면 올인원 전환은 미완료다. 지원 형식 실측을 먼저 한다. |
| 강화 | 판 검사와 충돌 처리 | 외부에서 게시한 변경뿐 아니라 Confluence의 미발행 초안도 위험이다. 게시 판 일치만으로 외부 편집 보존을 약속하지 않는다. |
| 강화 | 문서 한 장과 화면의 연결 | 사람이 선택한 정책서·기능설계서·공통 규칙을 문서 묶음으로 고정한다. 화면에서 돌아와 AI와 수정할 때도 이 근거를 쓴다. 자동 관련 문서 분석은 추가하지 않는다. |
| 유지 | 문서 발행·화면 제출 분리, 보존·복구·명시적 확인 | 기존 MVP의 계약을 유지한다. Confluence 쓰기와 개발자에게 보내는 화면 변경을 하나의 성공 상태로 합치지 않는다. |

현재 MCP 사용은 회사의 문서 전달 수단이다. 그것을 앱에 그대로 주입해야 한다는 요구는 아니다. **제품의 원격 쓰기는 기존 데몬의 Confluence REST 경로를 확장하는 방식을 권고한다.** 2026-10-20의 내장 MCP 미주입 결정을 유지하고, 화면 에이전트의 연결 레포 설정도 덮어쓰지 않는다. 사용자가 스스로 설정한 MCP로 화면 AI가 Confluence에 쓰는 것은 막지 않고 외부 편집으로 다룬다(2026-10-23 사용자 결정).

## 4. 현재 구현과 재사용 경계

MVP 검증 완료는 2026-10-21 사용자 통보를 따른다. [MVP 기록](MVP.md)의 과거 미실행 항목을 다시 차단 사유로 열지 않는다. 이번에 MVP 검증을 재실행하지 않았다.

2026-10-22 로컬 HEAD는 읽기 구현 `989ef22`다. 앞선 계획이 기록한 `origin/main`은 2026-10-21의 `46f8f47`이며, 이번 검토에서는 원격을 새로 가져오지 않았다. 착수 시 최신 main과 읽기 구현의 통합 상태를 확인하고 기준 SHA를 기록한다. 이미 존재하던 문서 수정과 삭제는 되돌리지 않는다.

데몬 파일의 약칭은 `packages/daemon/src/` 아래이며, 웹은 `packages/web/src/next/plans/`를 뜻한다. 파일·API를 먼저 늘리는 지시가 아니라 기존 책임에 붙일 변경 범위다.

구현상 먼저 닫을 간극은 다음과 같다.

- `confluence-client.ts`의 `listChildren`은 `/wiki/api/v2/pages/{id}/children`을 사용한다. [공식 문서](https://developer.atlassian.com/cloud/confluence/rest/v2/api-group-children/#api-pages-id-children-get)는 이 경로를 페이지 전용·폐기 예정으로 표시한다. 폴더는 응답에 없고, `confluence-sync.ts`의 `walkChildren`은 페이지로만 내려간다. 증분 검색이 원장에 없는 문서를 찾으면 걷기로 넘기지만 걷기도 그 문서를 담지 못한다. **따라서 폴더 아래 문서는 어느 경로로도 원장에 들어오지 못하고, 이때도 걷기는 완료(`complete: true`)를 낸다.** 코드와 API 계약에서 나온 결론이다(2026-10-23 검토). 앱으로 94개 누락을 재현하지는 않았다. 이 상태는 §5의 "조회 실패를 최신 상태로 표시하지 않는다"와 A1을 어긴다. 읽기 구현을 main에 합치기 전에 고친다. 2026-10-23 작업 트리에서 종류 있는 걷기로 고쳤다. 실사이트 대조(G0)와 폴더 아래 CQL 증분 실측은 남았다.
- AI 자식 프로세스는 데몬 환경 변수를 그대로 받는다(`one-shot.ts`, 화면 세션). 키체인 모드에서는 Confluence 자격이 환경 변수에 없다. 그러나 실사이트 검증에 쓰는 환경 재정의(`COLONOVA_DESIGN_CONFLUENCE_EMAIL/TOKEN`)에서는 자격이 AI 자식 환경에 실리고, 셸을 쓰는 화면 AI가 읽을 수 있다. `COLONOVA_DESIGN_REPO_PAT`도 같다. G0–G3 실측 전에 거른다. 2026-10-23 작업 트리에서 `withoutAppSecrets`로 AI 자식과 레포 명령의 환경을 걸렀다.
- `doc.list`는 로컬 원장을, `doc.read`는 원격 최신 본문을 읽는다. AI가 읽는 클론 사본도 별도 시점이다. 문서 선택 시 하나의 본문·판 스냅샷을 고정해야 한다.
- 가져오기 원장의 판은 갱신된다. 그 값을 초안의 편집 기준 판으로 재사용하면 안 된다. 초안·기준 XML·참조의 영속 저장은 아직 구현되지 않았다.

## 6. AI와 기획서를 쓰는 계약

### 사용자가 도는 한 바퀴

1. 기존 프로젝트에서 `기획서`를 열고 기존 문서 또는 새 문서를 고른다. 새 문서는 빈 문서나 사람이 고른 밑그림으로 시작한다. 기획 대화 자체를 CDP 설치·미리보기 기동에 종속시키지 않는다.
2. 참고할 정책서·기능설계서·공통 가이드와 필요한 절을 선택한다. AI에 전달할 문서·판·범위를 확인한다. 링크된 자료는 추가 선택할 수 있지만 읽지 않은 자료를 읽었다고 표시하지 않는다. AI가 범위 안 캐시에서 더 찾아 읽은 자료도 목록에 보인다.
3. AI와 요구·정책·예외·화면 조건을 대화로 다듬는다. AI는 설명과 문서 변경안을 구분해 반환한다. 사람이 직접 쓰는 것도 같은 초안을 고친다.
4. 변경안에서 추가·수정·삭제와 대상 문서를 확인한다. 필요한 변경만 채택하거나 거절·재요청한다. 채택은 로컬 초안에 반영하는 행위다.
5. 발행할 문서를 확인하고 Confluence에 반영한다. 화면을 먼저 검증하려면 명시적으로 그 초안을 기준으로 선택한다.
6. 같은 작업 맥락에서 CDP 데모를 요청한다. 화면에서 정책이 달라지면 연결된 문서로 돌아와 직접 고치거나 AI에게 변경안을 요청한다.

**복사해서 붙여 넣는 방법만 제공하면 AI 기획 작성 완료로 인정하지 않는다.** 대화·변경안·초안·화면 작업이 연결되고, 재시작 후에도 이어져야 한다.

### 실행 경계

- 기획 작성 요청과 화면 수정 요청을 명시적으로 구분한다. 사용자는 현재 AI가 문서를 제안하는지 코드를 고치는지 알아야 한다. 모드 전환만으로 요청을 보내거나 발행하지 않는다. 두 대화의 관계(한 대화 안의 두 실행자인지 별도 대화인지)와 각 AI가 보는 기록은 F1 착수 때 데이터 모델과 함께 정한다.
- 기획 생성은 기존 Claude 로그인·Agent SDK를 쓰되, 화면 수정 세션과 실행 권한을 분리한다. 앱이 고정해 제공한 자료에 더해 지정 SSOT 범위 안 캐시를 읽기 전용으로 조회할 수 있다(2026-10-23 사용자 결정). 셸·파일 쓰기·웹 조회·사용자 MCP·계정 커넥터 없이 변경안을 반환한다. 연결 레포의 화면 에이전트 설정은 그대로 둔다.
- 조회는 범위 안 캐시 밖을 읽지 못하고, 권한 상실을 확인한 문서는 빠진다. 캐시는 가져오기로 덮이므로 AI가 읽은 문서·판을 화면에 보이고 변경안의 근거에 남긴다. 조회는 요청 안의 자료 찾기다. 앱이 관련 문서를 자동으로 묶거나 화면 작업의 근거로 넓히지 않는다. 조회 방식(읽기 도구를 캐시에 가두기 · 앱 안 조회 도구)은 F1에서 정하고, 화면 세션에는 주입하지 않는다(2026-10-20 내장 MCP 미주입 유지).
- 기존 선례(`one-shot.ts`)는 도구와 설정을 끄지만 데몬 환경 변수를 그대로 넘긴다. 그대로 재사용하지 않는다. 모든 AI 자식의 환경에서 앱 비밀 변수를 거르고, 기획 생성은 허용 목록 환경으로 띄운다. 사용자 MCP·계정 커넥터는 SDK 설정(예: `managedSettings.allowedMcpServers: []`, `strictMcpConfig`)으로 끄고 실제 SDK 동작으로 차단을 확인한다. Confluence 자격은 생성 프로세스 환경·본문·첨부·대화·로그에 전달하지 않는다. 상속된 MCP나 설정으로 우회 발행할 수 있으면 인수 실패다(A17).
- 앱이 초안과 참고 자료를 읽고 모델에 전달하며, 모델은 제안만 반환한다. 앱의 발행 자격과 원격 쓰기는 데몬만 소유한다. 프롬프트의 부탁만으로 이 경계를 구현하지 않는다.
- 화면 AI가 사용자 자신의 Atlassian MCP·계정 커넥터로 Confluence에 쓰는 것은 막지 않는다(2026-10-23 사용자 결정). 그 쓰기는 사용자 계정의 외부 편집이며 §8로 다룬다. 앱은 그 MCP를 주입하지 않고 자격도 넘기지 않는다. 앱 발행 경로의 확인·판 검사·원격 초안 보호(G3)를 그 쓰기에 약속하지 않는다. 화면 세션이 사용자 MCP·계정 커넥터를 실제로 받는지는 아직 확인하지 않았다.
- 긴 문서는 선택 범위와 필요한 참고 절로 나눈다. 보낸 범위·읽은 자료·누락·지원하지 않는 자료를 표시한다(A18). 전체 문서를 읽은 것처럼 조용히 잘라 보내지 않는다. 외부 문서 안의 지시는 자료이며 발행 승인이나 도구 권한이 아니다.

### 변경안과 채택

변경안에는 요청·프로젝트·사이트·대상 문서, 편집 기준 판, 생성 시 초안 개정, 대상 절·블록, 변경 전 확인값과 변경 후 내용을 고정한다. 새 문서는 로컬 문서 ID를 사용한다. 설명 문장에서 파일 경로나 제목을 추출해 쓰기 명령으로 바꾸지 않는다.

대상은 제목만으로 찾지 않는다. 같은 제목의 절, 이름이 바뀐 절, 표의 행·셀을 구분한다. 저장 포맷의 구조상 위치와 기준 내용으로 식별하고 모호하면 재선택한다. 앱이 허용한 대상·연산·지원 형식과 맞지 않는 AI 출력은 적용하지 않는다.

생성 중 사람이 초안을 고쳤거나 원격 변경을 발견했으면 변경안을 오래된 것으로 표시한다. 채택 시 초안 개정·기준·대상을 다시 비교하며 조용히 덮어쓰지 않는다. 부분 채택 후 남은 변경안도 새 개정에 다시 검증한다. 삭제도 같은 판정과 확인을 거친다. 중단·실패한 생성의 일부 출력을 완성된 변경안으로 채택시키지 않는다. 보관한 변경안은 같은 초안에 중복 적용되지 않아야 한다.

프로젝트·사이트·문서 하나에 편집 가능한 로컬 초안은 하나다. 여러 대화는 그 초안을 공유하고 낡은 개정의 보관은 거절한다. 디스크 보관 완료 뒤에만 보관됨을 표시한다. 확정한 발행 의도는 두 번째 편집본이 아니다. 같은 원격 문서를 여러 프로젝트에서 다뤄도 대상 식별·발행 직렬화·원격 판 검사로 경합을 다룬다.

서로 다른 값을 합치지 않는다.

- **가져온 판:** 캐시의 실제 본문과 짝인 Confluence 정수 판.
- **편집 기준 판:** 초안을 시작하거나 충돌을 해결할 때 확정한 판과 원문. 가져오기로 바꾸지 않는다.
- **초안 개정:** 로컬 편집과 채택으로 바뀌는 번호. 확인 뒤 내용이 바뀌면 다시 확인한다.
- **원격 관찰 판:** 더 새 게시본을 발견했다는 정보. 그 번호만 옛 본문에 붙이지 않는다.
- **업무 단계 표기:** 제목·본문·개정 이력의 `v0.73` 같은 원문 표기. 서로 다르면 불일치를 보여 주고 사람이 결정한다. Confluence 정수 판과 다르다. 확인 창의 안내와 추가 확인에만 쓰고 자동 승급·정상화·잠금에는 쓰지 않는다.
- **CLOSED와 개정:** 조직 판 정책은 1.0을 런칭 스펙 CLOSED(수정에 사유)로, 1.01 이상을 사유 있는 개정(기획 오류·운영 요구·리소스)으로 둔다(「기획 리뷰 및 문서 작성법 및 워크플로우 안내」 PROD `1868496967`, 2026-10-17 조사 기록, 이번에 다시 읽지 않음). 앱은 이를 따른다. 표기가 1.0 이상인 문서의 발행은 개정 발행이다. 확인 창에서 사람이 새 단계 표기와 사유를 정해야 전송한다. 표기 반영은 초안의 변경으로 보여 준다. 표기를 읽지 못하거나 서로 다르면 사람이 정한다. 표기만을 이유로 쓰기를 막지 않는다. 다른 거절 사유(권한·형식·충돌·원격 초안)는 각 절을 따른다. 2026-10-19 화면 연결 설계의 "1.0 발행 잠금"과 2026-10-22판의 "새 문서 초안에서 개정 시작"은 채택하지 않는다. 같은 조사에서 v1.01 이상 제목이 18개였다. 개정을 같은 페이지에서 잇는 것으로 보고 G2 읽기 판정에서 확인한다(2026-10-23 사용자 결정(검토 권고 채택), A19).

처음 발행하지 않은 문서는 로컬 ID와 기준 판 `없음`을 가진다. 생성 성공 후 원격 ID·판을 연결하지만 과거 초안 참조는 그대로 보존한다. 선택 시 뷰어·클론 캐시 중 무엇을 봤든 실제 사용한 본문·판·출처를 한 스냅샷으로 고정한다.

연결은 현재의 한 기계·한 Atlassian 계정 경로를 기본으로 한다. 다른 사이트의 자격으로 요청을 보내지 않는다. 사용자가 선택한 프로젝트·사이트·기준 하위 소속과 읽기·쓰기 권한은 데몬에서 검사한다. 프런트엔드가 보낸 ID·판을 그대로 신뢰하지 않는다. 로그·통계에는 사용자 본문·파일 경로·비밀을 남기지 않는다.

## 8. 외부 편집과 동기화

자동 가져오기는 변경 감지 수단이다. 로컬 초안 덮어쓰기나 마지막 저장자 우선 병합이 아니다.

| 외부에서 일어난 일 | 앱의 처리 |
| --- | --- |
| 페이지·폴더 추가, 제목·위치 변경 | 콘텐츠 종류와 ID를 유지해 목록·계층을 조정한다. 폴더를 본문 페이지로 읽지 않는다. |
| 초안 없는 문서의 게시본 변경 | 캐시 본문·판을 함께 갱신한다. 과거 화면 작업 참조는 그대로다. |
| 초안 있는 문서의 게시본 변경 | 내 초안·편집 기준 원문·현재 원문을 보존하고 비교한다. 해결 전 낡은 초안으로 발행하지 않는다. |
| 외부에서 절·문장·표 삭제 | 단순 내용 차이와 대상 소멸을 구분한다. 옛 AI 변경안을 같은 제목의 다른 절에 적용하거나 삭제된 내용을 자동 부활시키지 않는다. |
| 페이지 삭제·범위 밖 이동·권한 상실 | 확인된 이유를 표시한다. 원인을 구분할 수 없으면 확인 불가다. 초안·참조를 자동 삭제하거나 다른 문서에 발행하지 않는다. |
| 본문 판이 같은 코멘트 변경 | 본문 증분과 별도로 조회한다. 못 읽음을 코멘트 없음이나 해결됨으로 표시하지 않는다. |
| 화면 AI가 사용자 MCP로 쓴 변경 | 다른 외부 편집과 같다. 초안이 있으면 비교·충돌 해결로 간다. 앱이 발행한 것으로 표시하지 않는다. |
| 사이트·기준 페이지 변경 | 미발행 초안과 연결을 먼저 알린다. 사용자가 보존·폐기를 정한 뒤 전환한다. 다른 SSOT 문서로 재귀속하지 않는다. |
| 오프라인·연결 만료 | 보관한 자료의 시점과 상태를 표시하고 로컬 작업을 보존한다. 원격 쓰기는 멈춘다. 권한 상실을 확인한 자료의 새 AI 전달·발행은 차단한다. |

계층은 종류를 보존하는 [direct-children](https://developer.atlassian.com/cloud/confluence/rest/v2/api-group-children/#api-pages-id-direct-children-get) 또는 [descendants](https://developer.atlassian.com/cloud/confluence/rest/v2/api-group-descendants/#api-pages-id-descendants-get) 계약으로 조회한다. 페이지·폴더가 섞여도 모든 페이지네이션을 끝내고 계층을 보존해야 한다. descendants의 `depth`는 기본 2·최대 10이다. 상한보다 깊은 계층은 가장 깊은 항목에서 이어 조회한다. 알 수 없는 콘텐츠 종류는 숨겨 누락시키지 말고 지원 상태를 표시한다.

본문 변경의 CQL 증분과 계층 재조정을 구분한다. 같은 판의 이동·삭제·권한 변화까지 판 번호 증분만으로 검출한다고 가정하지 않는다. 시작·수동 새로 가져오기·정기 동기화에서 계층을 재확인할 경로를 두고, 발행 직전에는 대상 소속·권한을 다시 확인한다. 읽기 상한·권한·네트워크 때문에 불완전한 결과는 완전한 목록으로 표시하거나 삭제 근거로 사용하지 않는다.

## 9. 발행과 실패 복구

### 저장 포맷과 지원 형식

발행은 **기준 저장 포맷에서 사람이 확인한 절·블록만 바꿔 구성한 페이지 본문**으로 한다. 사용자 편집 단위는 절·블록이어도 원격 갱신과 충돌 단위는 페이지다. 마크다운 전체 왕복이나 MCP 변환 HTML 전체 재발행을 사용하지 않는다. 공식 diff API가 있다고 가정하지 않고 보존한 기준·내 초안·현재 원문으로 비교한다.

기존 문서의 편집하지 않은 원문·매크로·첨부 참조·보존 가능한 인라인 앵커는 유지한다. 안전하게 바꿀 수 없는 블록은 발행 전에 거절한다. 매크로가 있다는 이유로 관계없는 일반 절까지 모두 막지 않는다. 앵커가 걸린 문장을 바꾸거나 보호 블록을 삭제하는 경우도 별도 판정한다. 조용히 앵커·이미지·표 구조를 지우거나 절 경계가 모호하다는 이유로 전체 문서를 손실 변환하지 않는다.

AI와 직접 편집이 읽고 쓰는 표현, 바꾼 블록을 저장 포맷으로 바꾸는 변환과 검증은 F0에서 정한다. 지금 코드에는 저장 포맷에서 뷰어용 마크다운을 만드는 쪽만 있다. G2 쓰기 검증은 AI가 고친 표 행·셀의 왕복을 포함한다.

G2는 위 대표 문서의 저장 포맷으로 편집 가능·보존 전용·지원 불가 범위를 기록한다. **대표 업무의 필수 문단·표 편집이 지원 불가이면 해당 지원을 구현하거나 사용자에게 범위 변경을 승인받기 전에는 전환 완료로 표시하지 않는다.** 모든 Confluence 기능을 복제한다는 약속도, 외부 링크만 열어 주면 완료라는 약속도 하지 않는다.

### 외부 미발행 초안

[Atlassian v2 Update page](https://developer.atlassian.com/cloud/confluence/rest/v2/api-group-page/#api-pages-id-put)는 게시본 갱신을 원격 초안에 병합하려 하며, 내용이 크게 다르면 기존 초안을 완전히 덮을 수 있다고 명시한다. 따라서 게시 판 확인과 409 처리만으로 Confluence에서 사람이 편집 중인 미발행 내용을 지킨다고 주장할 수 없다.

G3에서 앱 자체 자격으로 다른 사용자의 미발행 초안 감지·권한 가시성·실제 갱신 영향을 검증한다. 충돌하는 원격 초안이 있거나 안전 여부를 판정할 수 없으면 앱 발행을 막고 Confluence 편집을 마친 뒤 다시 가져오도록 안내한다. 같은 페이지의 실시간 공동 편집은 약속하지 않지만 순차적으로 양쪽에서 편집하는 길은 유지한다.

감지할 수 없는 동시 편집까지 무손실로 보장하는 기술 경로는 아직 확인하지 않았다. 실측으로 안전한 경계를 만들 수 없으면 발행 방식을 재설계하거나 페이지별 편집 순서 같은 운영 제약을 사용자와 확정해야 한다. 이 문제를 경고 한 줄이나 자동 덮어쓰기로 우회하지 않는다. G3가 닫히기 전에는 공유 문서 발행을 완료 기능으로 출시하지 않는다.

### 발행 절차

1. 확인 창에 프로젝트·사이트·대상 문서·부모 위치, 새 문서 여부, 기준 판·초안 개정, 변경·삭제 범위와 업무 단계 변경 여부를 보여 준다.
2. 데몬이 연결·하위 소속·권한·원격 게시 판·원격 초안 안전성·초안 개정을 다시 검사한다. 확인한 내용과 명령 ID를 발행 의도로 영속화한다.
3. 해당 문서의 발행 중 편집·추가 채택을 잠근다. 페이지 조건부 갱신으로 확인과 전송 사이의 게시본 변경도 막는다. 조건이 바뀌면 재확인 또는 충돌 해결로 돌아간다.
4. 같은 페이지의 채택된 변경을 한 본문으로 구성해 발행한다. 새 문서는 확인한 부모 아래에 생성한다. 다른 페이지까지 한 원격 트랜잭션이라고 표시하지 않는다.
5. 원격 ID·판·의도한 내용과 보존 대상의 결과를 확인한다. 문서별 성공을 기록하고 해당 초안만 완료 처리한다. 일부 실패를 전체 성공으로 표시하지 않는다.

네트워크 재시도와 명령 중복 방지는 별개다. 응답 유실·앱 종료 후 원격 상태와 저장한 의도를 대조한다. 적용을 확인한 요청은 다시 보내지 않는다. 적용 여부가 불명확하면 `결과 확인 필요`로 두고 자동 재전송하지 않는다. 생성·복제·코멘트도 같은 원칙으로 중복을 막는다. 생성은 응답 전에는 원격 ID가 없다. 의도에 공간·부모·제목·명령 ID를 남기고, 생성 결과를 무엇으로 찾을지 G1에서 정한다. 같은 공간의 제목 중복 허용 여부와 범위 밖 문서와의 제목 충돌도 G1에서 실측한다.

`결과 다시 확인`으로 적용이 확인되면 완료 처리한다. 미적용이 확인되면 기존 초안을 열고 새 확인 후 재시도한다. 계속 불명확하면 발행 내용과 원격 내용을 보여 준다. 사용자가 Confluence에서 결과를 확인해 연결하거나 `재전송 없이 종료`를 선택할 수 있다. 후자는 원격 취소·성공이 아니다. 의도·초안·기준을 `미확정 종료`로 보존하고 자동 재전송에서 제외한 뒤 편집 잠금을 푼다. 다음 쓰기는 현재 공식본과 대조한 새 사용자 확인으로만 진행한다.

### 문서 관리와 코멘트

새 문서는 로컬 초안으로 시작한다. 밑그림은 사람이 선택한 범위 안 페이지를 기본으로 하며 조직 템플릿 API의 지원을 전제하지 않는다. 없으면 빈 문서에서 시작할 수 있다. 복제·이름 변경·이동·휴지통·복구는 대상과 자식 영향 범위를 확인한다. 이름 변경·휴지통 이동은 F2, 복제·이동·복구는 후속 F4다. 미발행 초안이 있는 문서는 자동 정리하지 않는다. 삭제된 문서를 자동 재생성하지 않는다. 첨부 있는 복제는 실제 첨부 내용까지 확인한다.

코멘트는 Confluence에 기록한다. 코멘트 읽기는 지금 제공하고, 쓰기는 후속 F4다. 생성·답글·수정·해결은 권한과 현재 대상을 확인한다. 인라인 대상은 사람이 고른 문장을 원문에서 유일하게 식별할 수 있을 때만 연결한다. 모호하거나 바뀐 문장은 다시 선택한다. 코멘트 수정은 문서 본문 판 갱신과 같은 사건으로 취급하지 않는다.

## 10. CDP 데모와 개발자 전달

화면 작업에는 사람이 고른 문서 묶음, 각 문서의 ID·절·판·선택 내용, 초안이면 개정을 고정한다. 공통 가이드·정책서·기능설계서의 역할을 구분해 확인할 수 있게 한다. 관련 링크나 AI의 제안을 이유로 문서를 자동 편집 대상으로 넓히지 않는다.

CDP 화면은 기존 연결 레포·대화·미리보기·찍기·보관·복구 흐름으로 구현한다. 작업 중 가져오기가 돌거나 문서를 고쳐도 요청 당시 근거는 바뀌지 않는다. 지금 화면 AI는 10분마다 덮어쓰이는 `docs/plans/`를 그대로 읽고, 미발행 초안은 클론에 없다. 요청마다 근거의 불변 스냅샷을 화면 AI에 넘기는 경로를 F3에서 설계한다. 브리프에는 파일 경로를 쓰지 않는다(AGENTS.md). 이 경로 없이는 A10을 통과할 수 없다. 더 새 기획을 적용하려면 사람이 새 기준으로 작업을 요청한다. 실제 화면에서 정상·예외·권한·상태 조건을 확인하며 AI의 완료 답변을 확인 결과로 바꾸지 않는다.

화면에서 정책 변경을 발견하면 작업 기록의 문서 참조로 돌아가 직접 편집하거나 AI 변경안을 요청한다. 연결이 없으면 사람이 문서를 고른다. 수정한 정책으로 화면을 다시 확인하고, 필요한 문서 발행과 화면 제출을 각각 한다. 화면 AI의 공통 규칙 구절(`common-instructions.ts`의 "고치는 곳은 Confluence 다")은 F3에서 앱의 기획 작성도 안내하도록 맞춘다.

개발자에게는 확인한 CDP 변경과 공식 문서 URL·ID·기준 판·선택 절을 전달한다. 미발행 초안으로 먼저 제출한 경우에는 제목·미발행 상태와 기존 공식본 참조를 알리되, 로컬 초안 본문을 자동 공개하거나 개발자가 읽을 수 있다고 표시하지 않는다. 나중에 발행해도 과거 제출 근거는 소급 변경하지 않는다. 새 제출에서 공개할 공식 문서 참조를 다시 확인한다. 기획서 캐시·초안·토큰은 화면 제출에 포함하지 않는다.

## 11. 사용자 경험의 고정점

기존 사이드바·대화·오른쪽 기획서/미리보기 구조를 확장한다. 별도 대시보드나 두 번째 프로젝트 체계를 만들지 않는다. 문서를 열어도 미리보기의 입력·스크롤·찍기 상태를 유지한다.

- 기획 작성과 화면 수정의 현재 대상이 입력창 근처에 보인다. 문서·절·판·초안 여부를 확인하고 요청한다.
- 문서에는 공식본·로컬 초안·AI 변경안을 구분한다. AI 채택, 로컬 보관, Confluence 발행은 서로 다른 상태다.
- 미채택 변경안·보관 중·원격 변경·발행 중·충돌·결과 확인 필요에는 다음 행동을 둔다. 빈 문서는 AI와 시작하기와 직접 쓰기를 제공한다.
- 선택 문서가 바뀌거나 늦은 답이 도착해도 다른 초안에 표시·적용되지 않는다. 대화·초안·문서를 전환하고 재시작해도 작업이 이어진다.
- 실패·권한 없음·연결 만료는 색이나 아이콘만으로 표시하지 않는다. 키보드·초점·좁은 창의 기존 패턴을 유지한다.
- 문서 상태와 화면 제출의 상태 줄을 합치지 않는다. 사용자 문장은 `labels.ts`의 `L`에 두고, 실제 화면을 검증한 변경에서 GUIDE를 갱신한다. 발행·채택 같은 새 사용자 단어는 같은 변경에서 AGENTS.md의 사용자 단어 규칙("보관 · 제출 · 반영됨 뿐")과 `next-labels`·`vocab-sweep` 시험을 고친다. 보관→발행은 보관→제출과 짝을 이루게 쓴다.

**2026-10-23 구현 상태(커밋 전 작업 트리 · 오케스트레이터 기록):** F0–F4의 코드가 들어왔다 — 종류 있는 트리 걷기와 AI 자식 환경의 비밀 거르기(F0), 블록 편집 엔진 · 초안 저장소 · 기획 AI · 초안 편집기 · 기획 대화 · 변경안(F1), 발행 · 개정 발행 · 원격 최신본 맞추기 · 결과 재확인 · 새 문서 · 휴지통(F2), 근거 스냅샷 · 근거 보내기 · 제출의 기획 근거 절(F3), 복제 · 위치 옮기기 · 복구 · 코멘트 쓰기(F4). 상세는 [개발자 안내](DEVELOPERS.md)의 「기획 초안 · AI · 발행」이다. **어느 단계의 완료 문턱도 닫히지 않았다** — 순수 시험과 합성 fixture 의 통합 시험만 돌았고, G0–G5 실측 · 대표 문서 왕복 · 인수 증거(A1–A20)가 없다. 실제 Confluence 쓰기는 `COLONOVA_DESIGN_CONFLUENCE_PUBLISH=1` 일 때만 열리고 기본은 꺼짐이다(G1–G3 전 출시 금지를 코드로 지킨다).

**2026-10-23 사용자 위임 · 오케스트레이터 결정(F0의 「표현과 변환 방식을 정한다」):**

- 편집 표현은 저장 포맷의 블록 모델이다. 최상위와 레이아웃 셀을 블록으로 나누고, 사람과 AI는 블록의 좁은 마크다운 투영만 고친다. 고칠 수 없는 인라인은 토큰(통째로 지키는 조각 · 감싸는 모양 · 코멘트 닻)으로 남고, 바뀌지 않은 블록 · 셀 · 글은 원문 바이트 그대로 나간다. 마크다운 전체 왕복은 쓰지 않는다. 병합 셀 표 · 표 속 표 · 중첩 목록 · 매크로 블록은 보존 전용이다 — G2 읽기 판정에서 다시 본다.
- 기획 대화는 문서(초안)마다 하나이고 기획서 칸 안에 있다. 화면 대화와 섞지 않는다. 대화 기록 · 변경안 · 발행 의도는 클론 밖 프로젝트 데이터에 둔다.
- 인라인 코멘트의 대상은 원문에 한 번만 나오는 문장으로 좁혔다 — 화면의 글과 원문의 글은 세는 방식이 달라 몇 번째인지를 믿을 수 없다(G5에서 Confluence 의 세는 방식을 실측한 뒤 넓힌다). 서식 · 멘션이 든 코멘트는 앱에서 고치지 않는다.

F0는 G0를 닫고 G2의 읽기 판정인 저장 포맷 분류·필수 편집 범위를 확정한다. 읽기 구현은 트리 걷기를 고치기 전에 main에 합치지 않는다. G1·G2의 쓰기 검증·G3은 검증 환경 준비와 제한된 실험을 시작하되 F0 완료 조건으로 전부 통과시키지는 않는다. 실측은 AI 자식 환경의 비밀을 거른 뒤에 돌린다. F1은 그 형식 계약에 따른 로컬 작성 기능을 인수한다. F2의 원격 쓰기 인수 전에는 G1–G3과 G4의 휴지통·제목 항목을 닫아야 한다. 휴지통 이동을 F2에 둔 것은 2026-10-18의 기획서 관리(CRUD) 결정을 지키는 대가다.

F3는 F1 뒤 초안 기준으로 시작하고, 공식본이 필요한 부분만 F2를 기다린다(2026-10-23 사용자 결정(검토 권고 채택)). G3가 늦어져도 문서와 화면의 왕복은 진행된다. F4는 F2 뒤에 병행할 수 있지만 전환 완료 문턱(F5)에 들지 않는다. 번호는 기존 참조를 지키려고 유지한다. A15는 F0의 읽기와 F2의 쓰기에 함께 걸리는 공통 기준이다. F5까지가 이 레포의 전환 목표이고 F4는 그 뒤의 후속이다.

이번 검토의 MCP 읽기는 G0의 구조 조사 근거일 뿐 앱 경로 통과가 아니다. G1–G5의 새 원격 쓰기 실측은 수행하지 않았다. 쓰기 실측은 사용자가 대상·범위를 승인한 검증용 문서에서만 한다. 운영 SSOT를 시험용으로 고치거나 지우지 않는다. 인증 자료가 없거나 API가 지원하지 않으면 해당 게이트를 미확정으로 기록하고 우회 성공을 만들지 않는다.

F0 착수 때 구현 담당자가 앱 자격과 검증용 문서의 위치·범위를 준비하고, 기획 담당자가 대표 편집 과제와 복제 가능한 자료를 정한다. 사용자가 쓰기 실험 대상을 승인한 뒤에만 실측한다. G4의 휴지통·제목 항목은 F2 인수에 걸리므로 G1–G3과 같은 시기에 준비한다. G3의 별도 편집 계정 담당자, F5의 기획자·개발자와 양쪽 OS 검증 담당자도 함께 정한다. 현재 이 계정·대상·담당자가 확보됐다고 가정하지 않는다. 기존 자격 경로가 지원하지 않는 기능은 별도 인증을 조용히 추가하지 않고 해당 게이트에서 발행 방식·인증 설계의 변경 필요성을 보고한다.

| A20 | 자식이 있는 문서와 미발행 초안이 있는 문서를 휴지통으로 옮긴다 | 자식 영향 범위를 확인한 뒤에만 전송된다. 로컬 초안은 보존된다. 영구 삭제가 없고, Confluence에서 복구하면 앱이 다시 읽는다. |

기능 구현 때 `pnpm typecheck`, 빌드 포함 `pnpm test`, CI의 biome 검사와 실제 앱 조작을 수행한다. 영구 시험은 상태 전이·대상 식별·경계·내용 보존·복구를 다룬다. 문구나 명령 전달만 확인하는 시험은 인수 증거가 아니다. 새 기능 인수가 완료된 MVP를 다시 미완료로 돌리는 것은 아니다.

증거에는 후보 SHA·OS·계정 권한 범위·문서 ID와 판·사전 기대 결과·앱 화면·실제 원격 결과·판정을 남긴다. 민감한 본문·토큰은 일반 로그에 남기지 않는다. 실제 문서 규모에서 가져오기·큰 문서 열기·AI 생성·편집·발행 시간을 관찰하되 측정하지 않은 지연 상한이나 API 예산을 보장값으로 쓰지 않는다.

## 15. 문서 운영과 다음 실행 단위

- 범위·순서·완료 기준은 이 문서에서 관리한다. 단계 완료에는 기준 SHA와 인수 증거를 붙인다. 목표를 적은 것을 구현 완료로 바꾸지 않는다.
- README·GUIDE·DEVELOPERS의 현재 기능 설명은 구현 뒤 바꾼다. 계획만으로 AI 작성·발행을 이미 제공한다고 쓰지 않는다.
- 새 요구는 어떤 인수 기준을 위한 것인지 먼저 적는다. 분석·자동 발행·공동 편집 서버로의 확대나 포함 범위 축소는 별도 사용자 결정 없이는 하지 않는다.
- 다음 실행 단위는 F0다. 먼저 트리 걷기를 종류 있는 계층으로 고치고 AI 자식 환경의 비밀을 거른다. 그다음 최신 기준선과 읽기 구현을 통합하고, 지정 SSOT의 앱 자격 읽기·대표 저장 포맷·원격 초안 안전성을 검증한다. AI·직접 편집의 표현과 저장 포맷 변환 방식을 정한다. 그 결과 위에서 F1의 AI 기획 작업공간을 구현한다.
- 2026-10-23 갱신: F0–F4의 코드가 작업 트리에 들어왔다(§12 아래 구현 상태). 다음 실행 단위는 실측이다 — 앱 자격과 사용자가 승인한 검증용 문서 · 동료 계정을 준비하고 G0(폴더 아래 CQL 증분 포함) → G2 읽기 판정(대표 8개 문서의 블록 엔진 왕복 · 편집 범위) → G1 · G3 · G4(휴지통 · 제목) 순서로 닫은 뒤 발행 게이트를 켜는 결정을 받는다. 그다음 F2 · F3 인수와 F5다.

- 2026-10-23 사용자 결정: 화면 AI의 사용자 MCP 쓰기를 막지 않고 외부 편집으로 다룬다. 기획 AI의 범위 안 캐시 읽기 전용 조회를 허용한다. F3 순서·F4 위치·CLOSED 개정 발행은 검토 권고를 채택했다.

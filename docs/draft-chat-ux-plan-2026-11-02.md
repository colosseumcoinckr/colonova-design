## 0. 지키는 것

- 문서 판 왼쪽 · 기획 대화 오른쪽(2026-10-31 사용자 결정). AI 의 고침은 채택 없이 바로 초안에, 되돌리기는 판으로(같은 날 결정).
- 사용자 문장은 `labels.ts` 의 `L.drafts` 에만. 개발 어휘 금지(`next-labels` · `vocab-sweep`).
- 크기 · 색은 토큰만. 읽는 글 12px 미만 금지 · 반 픽셀 금지. 으뜸 색 바탕은 `보내기` 하나.
- 프로토콜은 안 고친다 — 말의 시각 `at` 은 이미 선로에 있다.
- 겹판은 공통 부품(`ui/Popover` · `nx-jump` · `nx-av`)을 쓰고 스크린 · 반경 · 모션을 다시 선언하지 않는다.

## 1. 지금 그림 — 진단

- **짧은 대화가 위에 매달린다.** 말 몇 개뿐인 대화는 머리 바로 아래서 시작해 입력창까지의 가운데가 텅 비고 만다
  (사용자 스크린샷). 시작 문장(Starters)도 위에 붙어 있다.
- **AI 말에 닻이 없다.** 화면 대화는 스파크 아바타(`nx-av`)에 첫 문장을 살짝 크게(`hasLeadSentence`) 하는데, 기획 대화는
  맨글이 그냥 떠서 답이 어디서 시작하는지도 말풍선과의 짝도 안 보인다. 같은 앱의 두 대화가 다른 말씨다.
- **머리가 엉킨다.** 대화 제목 · 문서 제목 · 긴 안내문이 한 줄 흐름에서 wrap 되고, CSS 가 숨긴 죽은 펼침 단추까지 자리를
  차지한다.
- **손이 보이지 않거나 없다.** 복사 · 다시 요청 · 고쳐 보내기는 hover 까지 기다려야 하고, 위로 올려 읽는 중에는 `맨 아래로`
  가 없으며, 말에 시각이 없다(`at` 은 있는데 그리지 않는다). 문서 카드의 `N곳은 직접 고르세요` 알약은 눌리지 않는다.
- **입력창이 고정 3줄이다.** 화면 대화 입력창은 글에 맞춰 자라는데(1~180px) 기획 대화는 비었을 때도 3줄, 길어지면 잘린다.
  근거 고르기 판은 입력창 위를 밀치듯 끼어든다.
- **죽은 것이 많다.** 버려진 `narrow` prop · 숨은 ChevronUp/Down 토글 · 안 쓰는 `ReadAsk.tsx` · 호출되지 않는 `adopt` 손,
  그리고 옛 820px 배치의 CSS 묶음(`.nx-dr-with` · `.nx-pl-view--draft/--read` · `.nx-dr-main` · 820/819px container 블록)이
  남아 있다 — 2026-11-02 스크롤 사고(입력창이 창밑으로 잘리던 것)의 원인이던 선택자들이다.

## 2. 항목

### 뼈대

- **D1 바닥 붙임** — 대화가 짧으면 입력창 위에서 시작한다(메신저 · Claude 앱의 관례). `.nx-dr-thread-log` 의 첫 아이에
  `margin-top: auto` — 길어지면 auto 가 0 으로 접혀 지금처럼 위에서 구른다. 시작 문장도 함께 아래로 내려온다.
- **D2 AI 말의 닻** — AI 말을 화면 대화처럼 `[아바타 | 몸]` 격자로 놓는다. 아바타는 `chat.css` 의 `nx-av`(스파크) 를 그대로
  쓰고 몸은 `nx-dr-msg-md` 를 지킨다. 스파크는 연속한 AI 말에서 첫 말에만(앞 말의 role 로 판단). 첫 문장 크게는
  `lib/answer-lead.ts` 의 `hasLeadSentence` 와 `.nx-dr-msg-md` 의 lead 변형 한 규칙. 도는 중 상자(`nx-dr-working`)도 같은
  들여쓰기로 맞춘다. 사람 말풍선(`accent-soft`)은 그대로.
- **D3 시각** — 말마다 끝에 작은 한 줄(`fs-cap` · `ink3`). `lib/format.ts` 의 `timeAgo` 를 `message.at` 에 쓴다.
- **D4 손 내놓기** — 마지막 말의 손(복사 · 다시 요청 · 고쳐 보내기)은 hover 없이도 늘 보이고, `@media (hover: none)` 에서는
  모든 말의 손이 늘 보인다.
- **D5 맨 아래로 / 새 내용** — 바닥에서 떠나 올려 읽는 동안 입력창 위에 떠 있는 단추. 화면 대화의 `nx-jump` 부품과
  unpinned/hasNew 상태를 이식한다 — 도는 중에 새 글이 오면 `새 내용` 으로 바뀐다.

### 머리 · 좁은 칸

- **D6 머리 세 줄의 위계** — ① 대화 제목 + `⋯` 메뉴 ② 문서 제목(말줄임) ③ 안내문 한 줄(말줄임, `title` 에 전문).
  숨은 펼침 단추 · `expanded` 상태 · `data-expanded` 는 걷는다. 좁은 대화 탭(칸 1100px 이하의 `대화` 탭)에서는 안내문을
  숨겨 머리를 줄인다 — CSS 만으로 하고 버려진 `narrow` prop 은 걷는다.

### 입력 · 근거

- **D7 입력창 자라기** — 화면 대화 `Composer` 와 같은 규칙: 글이 바뀔 때 높이를 다시 잡아 1줄부터 180px 까지 자란다.
- **D8 근거 고르기 팝** — `RefPicker` 를 입력창 위에 끼워 넣는 대신 `ui/Popover` 로 `+ 근거 더하기` 단추에 붙여 띄운다.
  `다른 문서로 옮기기` 의 같은 판은 `⋯` 메뉴 자리에 띄운다.

### 문서 카드

- **D9 남은 고침 이동** — `N곳은 직접 고르세요` 알약이 단추가 된다. 누르면 남은 걸음(stale op)의 블록으로 문서 판을
  열어 칠한다(`onShowInDoc` 재사용 — 문서 판의 남은 걸음 띠로 간다). 블록 뽑기는 `DraftEditor` 의 `keptStepOf` 와 같은 판정.
- **D10 요약 줄** — 적용된 문서 카드의 머리 아래에 `proposal.summary` 한 줄(`fs-sm` · `ink2` · 말줄임).

### 걷기

- **D11 죽은 CSS · 코드** — grep 으로 무참조를 확인하고 걷는다: draft.css 의 옛 배치 묶음(`.nx-dr-with` ·
  `.nx-pl-view--draft/--read` · `.nx-dr-main` · `.nx-pl-read-main` · 820/819px container 블록 · `.nx-dr-thread-toggle` 숨김
  규칙 · 걸음/채택류 `.nx-dr-prop*` · `.nx-dr-cmp*` · `nx-dr-pick-pulse`), `draft/ReadAsk.tsx` 삭제, `use-draft-thread.ts` 의
  안 쓰는 `adopt` 손과 그 전용 문장, `PlanChat` 의 `narrow` prop · 펼침 토글, `labels.ts` 의 짝 잃은 문장,
  `thread-model.ts` 의 시험 전용 내보내기는 짝 시험과 함께 정리한다. **단 `nx-dr-check` · `nx-dr-acts` · `nx-dr-kept` 등
  문서 판이 쓰는 classes 은 유지한다.**

## 5. 완료 기준

- 짧은 대화(말 하나둘)를 열면 말이 입력창 위에 붙어 있고 가운데가 텅 비지 않는다. 대화가 길면 위에서 구른다.
- AI 답마다 스파크 닻이 서고 첫 문장이 살짝 크다 — 화면 대화와 나란히 띄우면 같은 말씨로 읽힌다.
- 말 끝에 시각이 있고, 위로 올려 읽으면 `맨 아래로` 가 떠 도는 중에는 `새 내용` 이 된다.
- 마지막 말의 복사 · 다시 요청 · 고쳐 보내기가 hover 없이 보인다.
- 머리가 세 줄의 위계(제목+⋯ / 문서 / 안내문)로 읽히고, 좁은 대화 탭에서는 안내문이 숨는다.
- 입력창이 글에 맞춰 자라고, 근거 고르기가 `+` 단추에 붙은 팝으로 뜬다.
- `N곳은 직접 고르세요` 를 누르면 문서 판의 남은 걸음으로 간다. 적용된 카드에 요약 줄이 선다.
- `narrow` prop · 펼침 토글 · `ReadAsk` · `adopt` · 옛 820px CSS 가 코드에서 사라졌다.
- `pnpm typecheck` · `pnpm test` · `pnpm build` 를 통과하고, 다크 테마에서도 깨지지 않는다.

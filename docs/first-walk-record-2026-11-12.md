# 실제 사용자의 한 바퀴 — 기록 양식

`intend.md` 의 할 일 2 를 걷을 때 쓰는 양식이다(2026-11-12 설계 결정 — `docs/design-2026-11-12.md` §13).
지금까지의 확인은 개발자나 AI 가 했다. 실제 기획자 · UI/UX 디자이너가 어디서 막히는지는 아직 아무도 보지 못했다.
이 기록이 그 뒤에 무엇을 고치고 무엇을 지을지를 정한다 — 설계의 조건부 조각은 여기에 그 막힘이 적혀 있을 때만 연다.

## 걷는 법

- **누가** — 개발팀 밖의 기획자 · UI/UX 디자이너 두세 명. 기획서 자리를 쓰는 사람이 한 명 이상 든다.
- **무엇으로** — 자기 PC · 자기 계정 · 실제 앱 · 실제 Confluence · 실제 제출. 견본이나 가짜 서버를 쓰지 않는다.
- **어디까지** — 설치 → 첫 요청 → 기획서 한 장을 고쳐 **첫 발행** → 화면을 고쳐 **첫 제출** → 개발자 반영을 안 때.
- **곁에서 보는 사람** — 한 명이 적는다. 돕지 않는다. 참가자가 «막혔다»고 말하면 그때의 화면과 말을 적고, 참가자가 스스로 개발팀을 부를 때까지 기다린다.
- **시작 전에** — 개발팀이 참가자에게 설치 파일 · 초대 파일과 함께 창구를 알린다(아래 «개발팀이 보낼 말»). 이 양식을 사람 수만큼 준비한다.

## 개발팀이 보낼 말

초대 파일을 건넬 때 함께 보낸다. 초대 파일에 창구 칸을 적었으면 앱이 그 이름을 준비 화면 · 막힘 문장에 세운다(2026-11-12 결정 ㉱) — 그래도 막혔을 때 갈 곳은 이 말로 함께 전한다(초대 파일에 칸이 없을 수 있으므로).

> ColoNova Design 설치 파일과 초대 파일을 보냅니다. 초대 파일은 앱을 처음 켠 창에 끌어다 놓으면 됩니다.
> 쓰다가 막히면 (담당자 이름)에게, (대화방 이름)에서 물어 주세요. 앱의 `담당자에게 보낼 내용 복사` 를 눌러 붙여 넣으면 빠릅니다.
> 화면을 고쳐 `제출` 하면 (확인하는 개발자 이름)이 확인해 반영합니다. 기획서 발행 권한이 없다고 나오면 (Confluence 관리자 이름)에게 말해 주세요.

## 기록 — 참가자마다 한 장

| 칸 | 적는 것 |
| --- | --- |
| 누구 | 직무(기획자 / UI·UX 디자이너) · 기획서 자리를 쓰는지 · 운영체제 |
| 때 | 설치 파일을 연 때 · 첫 요청을 보낸 때 · 첫 발행(«발행이 반영됐어요»를 본 때) · 첫 제출 · 개발자 반영을 안 때 |
| 개발자를 부른 일 | 부를 때마다 한 줄 — 언제 · 왜 · 누구에게 닿았는지 · 닿기까지 걸린 시간 |
| 막힌 자리 | 막힐 때마다 한 줄 — 어느 화면 · 그때 읽은 말(그대로) · 무엇으로 오해했는지 · 어떻게 풀렸는지 |
| 누르기 전에 물은 것 | 첫 발행 · 첫 제출 직전에 묻는다 — «누르면 누가 보게 되나요?» 답을 그대로 적는다 |
| 다름 카드 | 본 카드마다 — 눌러 반영 · 건너뜀 · 끝까지 누르지 않음 · 판정이 맞았는지 |
| 헷갈린 말 | 끝난 뒤 참가자가 스스로 적는다 |

## 끝난 뒤 모으는 숫자

`intend.md` 의 «잘 가고 있는지 재는 것» 다섯이다. 함께 쓰는 서버가 없어 저절로 모이지 않는다.

| 재는 것 | 어떻게 얻나 |
| --- | --- |
| 한 바퀴에서 개발자를 부른 횟수 | «개발자를 부른 일»의 줄 수. 초대 파일을 받는 한 번이 바닥이다 |
| 설치부터 첫 발행까지 | «때»의 두 시각 |
| 다름 카드의 끝 | «다름 카드»의 줄을 셋으로 센다. 분모는 한 바퀴 동안 뜬 카드 |
| `FEATURES.md` 의 🧪 · «실사이트 미검증» 줄의 수 | 할 일 3 의 앞과 뒤에 센다 |
| 한 주에 두 자리를 다 쓴 사람 수 | 한 바퀴 뒤 주마다 참가자에게 묻는다 |

## 걸으면서 함께 확인할 것

지금 모양 그대로 확인한다(설계 §13 의 가). 여기서 실패한 줄은 고치거나 기능에서 걷는다.

1. 실제 Confluence 에서 발행이 되는가 — 표 · 매크로 · 코멘트가 남는지 Confluence 에서 직접 견준다.
2. 남이 먼저 고쳤을 때 혼자 맞추고 발행하는가 — 두 사람이 같은 문서의 같은 곳을 일부러 고친다.
3. 문서와 화면의 연결이 다른 PC 에 닿는가 — 한 사람이 연결만 바꿔 제출하고, 반영된 뒤 다른 사람이 받아와 화면 옆 기획서가 바뀌는지 본다. **아직 아무도 확인하지 않았다.**
4. 다름 카드가 맞는가 — 기획자가 미리 만들어 둔 어긋남과 정상 사례를 섞는다.
5. 막혔을 때 혼자 개발팀에 닿는가 — 초대 기간을 일부러 지나게 한 PC 로.
6. 서명 없는 설치를 혼자 넘는가 — Windows 한 대 이상.

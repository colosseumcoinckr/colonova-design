# 닿는 문서 찾기 — 세 층과 Atlassian 신호의 자리 — 2026-11-03 방향

화면을 고칠 때 연결 표(`plans-map.json`)에 없지만 내용이 실제로 닿는 기획서를 어떻게 찾을지, 그리고
Atlassian 신호(Rovo 검색 · 그래프 · Jira)를 어디에 둘지 정한 방향 문서다. 2026-11-03 대화에서 사용자가
물었고 그 답을 이 문서로 남긴다(사용자 요청). 구현 지시가 아니라 C1 을 열 때 적용할 구조의 결정이다.

## 문제 — 연결 표가 푸는 것과 안 푸는 것

연결 파일은 화면 주소 ↔ 문서의 점 연결이라 「이 화면의 기획서」 탭과 같이 고치기 대상은 푼다. 못 푸는 건 둘이다.

- **문서 ↔ 문서 구조** — PRD → 상세 기획 → 용어집처럼 기획끼리 이어진 관계. 한 문서의 결정이 여러 문서에
  퍼져 있고 화면 하나에도 여러 문서의 결정이 섞여 든다.
- **변경 ↔ 영향** — 화면을 고쳤을 때 연결 표에 없지만 닿는 문서. 줄이 없다고 영향이 없는 게 아니다.

## 방향

### 정본은 둘로 나눈다

- 화면 ↔ 문서는 연결 레포의 `plans-map.json` 그대로다(보관 · 제출로 팀이 공유).
- 문서 ↔ 문서 · 개념은 Confluence SSOT(페이지 링크 · 라벨 · 계층)에서 필요할 때 읽는다. 앱 안에 의존성
  그래프 원장을 새로 만들지 않는다 — 2026-10-30 연결 자리를 걷은 결정과 같은 결이다. 연결은 쓰는 곳에서
  생기고 보인다.

### 찾기는 세 층이다(같이 고치기 UX 계획 §C1 의 보충)

1. **확실한 신호(공짜 · 정확 · 이미 쌓이는 중)** — 이 대화의 근거 문서(`plans/refs.jsonl`) → 같이 고친
   기록(`plans/screen-sync.jsonl`)에서 이 주소에 닿았던 문서 → 연결 파일의 연결. 사람이 관리하지 않는다 —
   근거를 보내면 줄이 저절로 쓰이고 기록이 쌓인다.
2. **로컬 색인(공짜)** — 미러 원장 위의 낱말 매치다. IDF 로 흔한 조각을 낮추고 최소 점수를 둬 「후보 없음」이
   기본이 되게 한다(상위 10~15개). 데몬은 어차피 뿌리 아래 문서를 CQL 로 동기화해 두므로 Rovo 나 크레딧
   없이 매 턴 돈다.
3. **판정** — 후보의 목차만 주고 기획 AI 가 닿는 절을 고르고, 사람이 곁줄에서 채택 · 거부한다. 거부는 신호로
   저장돼 다음 후보에 반영된다.

**채택 회수(이 문서의 추가 결정)** — 채택된 영향 후보는 `plans-map.json` 줄로 굳는다. 확인된 영향이 1층으로
흘러들어가 찾기 질의가 점점 1층에서 명중하고 2 · 3층은 꼬리만 담당한다. 이 플라이휠이 「연결 맵 관리」
부담을 없앤다 — 관리하는 게 아니라 영향이 확인될 때마다 맵이 자란다.

### Rovo 는 핵심 경로 밖이다

Rovo 의미 검색에 의존하지 않는다. 이유 셋 — 비용(호출마다 Rovo 크레딧, C1 을 여는 문이 비용 임계) · 자격
(프로젝트별 PAT 를 데몬이 갖고 MCP 는 세션에 주입하지 않는다 — 2026-11-03 프로젝트별 자격 결정 · 2026-10-20
내장 MCP 비주입) · 재현성(결과가 흔들리면 「왜 이 문서가 후보에 들었나」를 기록으로 말할 수 없다). Rovo 가
도움 되는 곳은 꼬리뿐이다 — 같은 개념을 문서마다 다른 낱말로 써서 1 · 2층이 놓치는 경우.

### AI 는 Confluence 를 직접 고치지 않는다

AI 세션에 Atlassian MCP 를 줘서 조회 · 수정하게 하는 길은 만들지 않는다(2026-11-03 대화). 초안 → 사람 발행의
문을 지키고(C5 믿음 발행은 보류), 되돌리기 · 원장과의 경쟁 · 가드 구멍을 피한다. 화면 AI 가 참고로 읽는 것은
이미 가능하다 — context-mode MCP 에 팀 커넥터로 Atlassian MCP 를 붙이면 된다(2026-10-24 결정 안). 지키는 건
쓰기 문 하나다. 조회 신호가 필요하면 **데몬이** 프로젝트 PAT 로 REST 를 부른다.

### Atlassian 신호는 데몬이 다섯째 신호로 넣는다

- CQL `label =` · `ancestor =` — 개념 묶음 · 같은 뿌리 문서(공짜).
- 페이지 링크 — 연결된 문서에서 닿는 이웃 문서(REST 로 읽힌다).
- Jira 축 — 제출 PR → 이슈 → 이슈에 붙은 문서. 팀이 Jira 를 평소처럼 쓰면 저절로 생기는 신호다.

MCP 프로토콜은 필요 없다 — 데몬이 같은 API 를 이미 쓰고 있다(증분 동기의 CQL).

## 순서

1. C7 맞춰 보기의 정답표로 놓친 비율 · 잘못 짚은 비율을 잰다(0–4 단계 눈 검증이 먼저).
2. C1 을 1 · 2층(로컬만, Rovo 없이)으로 연다.
3. 놓친 비율이 남으면 다섯째 신호로 CQL 라벨 · 링크 · 계층을 데몬이 붙인다.
4. 그래도 남는 동의어 꼬리가 크레딧 비용을 감당하면 그때 Rovo 를 선택 사항으로 넣는다.

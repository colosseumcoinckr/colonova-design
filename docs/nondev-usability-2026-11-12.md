# 비개발자 사용성 토론과 반영

2026-11-12 사용자 요청 — «비개발자가 이 프로그램을 더 쉽고 효율적으로 쓰게 하려면»을 작업자들과 토론하고,
이어서 «오케스트레이터가 판단해 진행»하라는 지시로 일부를 반영했다. 무엇을 넣고 뺄지는 오케스트레이터의 판단이다 —
사용자가 항목별로 정한 것이 아니다. Confluence 원본 · 초안 보관 · 사람의 발행 · A안(판정 → 카드 → 사람이 누름)의
계약은 그대로다.

## 토론

Herdr 의 작업자 셋이 렌즈 하나씩을 맡아 코드와 문서를 읽었다(앱은 띄우지 않았다) — 첫 사용(GLM-5.3) ·
매일의 반복(SWE-2) · 개념과 회복(GLM-5.3-Flash). 1라운드는 따로 조사하고 2라운드는 서로의 제안을 반박했다.

뿌리 문제는 넷으로 모였다.

1. 끝남 · 대기 · 미발행 같은 «지금 내가 봐야 할 것»이 각 대화 · 각 자리 안에만 있다.
2. 기획서 길이 첫 사용 밖에 있다 — 연결한 뒤 `새로 가져오기` 를 누르지 않으면 문서는 다음 주기(10분)에 온다.
3. 되돌리기 어려운 누름(발행 · `건너뛰기` · `화면을 기획서대로`)에서 돌아오는 길이 화면에 보이지 않는다.
4. «지금 보는 글이 언제 판인가»를 곳곳의 문장이 따로 보증한다.

## 반영한 것

| 문제 | 반영 | 자리 |
| --- | --- | --- |
| 다른 대화를 보는 사이 끝난 답을 놓친다 — 목록 줄은 도는 중 · 묻는 중 · 실패만 그렸다 | 보고 있지 않던 대화의 답이 끝나면 줄에 파란 점과 `답이 끝났어요` 가 남고 열면 사라진다. 이 앱을 켠 뒤 본 전이만 단다 | `lib/unseen-done.ts` · `sidebar/ConversationList.tsx` |
| 연결에 성공해도 첫 가져오기가 돌지 않았다 | 실제로 쓰는 뿌리가 정해진 연결은 곧바로 가져오기를 건다(처음 연결 · 만료 뒤 재연결 · 뿌리만 바꿈) | `requests/confluence.ts` |
| 가져오기가 끝나도 목록이 그대로였다 — 웹은 요약의 마지막 가져온 시각이 바뀌어야 다시 읽는데 바퀴 끝에 방송이 없었다 | 원장을 새로 쓴 바퀴의 끝에 프로젝트 요약을 한 번 방송한다 | `confluence-sync.ts` · `server.ts` |
| 발행 직후에도 사본(본문 찾기 · 화면 옆 기획서의 재료)이 옛 내용이었다 | 발행이 적용으로 확인되면 가져오기를 건다 — 결과 불명 · 실패에서는 걸지 않는다 | `draft-service.ts` |
| 잘못 발행한 사람에게 돌아가는 길을 말하는 곳이 없었다 | 판 기록 창 머리에 한 줄 — 초안에서 발행 전 판으로 되돌린 뒤 다시 발행한다(코드로 확인한 길만) | `plans/view/DocHistory.tsx` · `labels.ts` |
| 다음 손을 말하지 않는 상태 문장 | 라벨 · 첨부 읽기 실패 · 맞지 않게 된 고침 · 화면 확인이 끝나지 않은 답의 자세한 줄에 다음 손을 덧붙였다. 조어 «걸음»을 걷었다 | `labels.ts` |

경로는 웹은 `packages/web/src/next/`, 데몬은 `packages/daemon/src/` 기준이다. 프로토콜은 건드리지 않았다.

## 넣지 않은 것

- **사용자가 정할 것** — 첫 화면 완료 문장에 기획서 길 한 줄(소개 페이지에도 같은 문장이 있다) · 문서 열기를
  «사본 먼저 + 조용한 갱신»으로 바꾸기(GUIDE 의 «그 자리에서 읽는다» 계약 — 대기 시간을 먼저 잰다) ·
  프로젝트 수준의 «지금 볼 것» 한 곳 설계(`이번 작업` 의 초안 칸 · `기획서` 줄의 도는 표시 · 같이 고치기 대기 표시가 여기에 걸린다) ·
  잘못 발행에서 `이 판 내용으로 초안 시작하기` 까지 갈지.
- **뒤로 미룬 것** — `건너뛰기` 는 연결로 이어진 짝만 거르고 근거로 직접 보내면 다시 본다. 확인 한 칸보다
  «다시 묻지 않는 짝»을 보고 푸는 곳이 맞는 답이라 설계 뒤로 미뤘다. 근거 칩의 `최신 판으로 다시 담기` ·
  제출 뒤 더 고친 것의 «미전달» 표시 · 미리보기의 로그인 벽 안내도 같다.
- **토론에서 걷어낸 것** — 초대장에 Confluence 주소 칸 · `연결` 낱말 교체 · 요금제 미리 알림 · `모두 고치기`(A안의 문을 옅힌다).
- **그대로 둔 문장** — `해결 여부를 확인하지 못했어요` 알약과 `저장된 AI 설정을 알 수 없어요` 칩은 좁은 자리라 절을 붙이지 않았다.

## 검증

- 작업은 원본의 사본에서 했다(원본에서는 앱이 돌고 있었다). 사본의 전체 빌드 통과, 전체 시험 3,017개 중 3,012 통과 · 실패 0 · 건너뜀 5
  (반영 전 기준은 3,006개 · 실패 0 — 새 시험 11개: 끝남 판정 8 · 연결 뒤 가져오기 1 · 발행 뒤 사본 1 · 바퀴 끝 방송 1). 바꾼 코드 21파일의 biome 검사 통과.
- 끝남 표시는 사이드바 견본(`dev/sidebar-fixture.html?case=b&done=m1&active=m2` — 도는 대화가 0.6초 뒤 끝난다)에서 밝은 · 어두운 테마로 보았다.
  처음에는 강조색 점이었는데 기본 팔레트에서 실패의 빨간 점과 닮아 파란 점으로 바꿨다. 보고 있는 대화(`active=m1`)에는 서지 않는 것도 보았다.
- 잘못 발행의 돌아가는 길은 코드로 확인했다 — 발행 뒤에도 초안과 초안 판이 남고(`draft-publish.ts` · `draft-store.ts`),
  되돌리기는 발행 도중만 거절한다(`draft-service.ts` 의 `restoreRevision`).
- 확인하지 못한 것: 실제 앱에서의 끝남 표시 · 판 기록 창의 한 줄, 실제 Confluence 에서의 연결 직후 가져오기 · 발행 뒤 사본 갱신
  (데몬 시험의 가짜 클라이언트로만 확인했다). 발행 뒤 가져오기가 마침 돌던 바퀴에 합류하면 그 바퀴는 발행 전 판을 쓸 수 있고, Confluence 의 검색이 새 판을 늦게 내줄 수도 있다 — 둘 다 다음 주기가 잇는다.
- 바퀴 끝의 요약 방송은 타이머 바퀴에도 선다 — 연결된 프로젝트는 10분마다 목록을 조용히 다시 읽는다(상한에 걸리지 않은 바퀴는 변화가 없어도 마지막 가져온 시각을 올린다).
- 끝남 표시는 데몬이 도는 중에서 곧바로 끝남으로 넘기는 것을 코드로 확인했다(`session-manager.ts` 의 `settledTurns` 가 상태 알림보다 먼저 선다).

# A안 실행 계획 — 양방향 루프 심화(2026-11-03)

사용자 결정 «A안으로 수정한다고 하면 수정 계획을 먼저 세워볼래»(2026-11-03)에 따른 실행 계획이다.
A안은 **자동은 화면→초안 한 방향을 유지하고, 반대 방향은 판정 카드와 사람의 손**으로 심화한다. B안(양방향
완전 자동)은 기각, C안의 요소(자동 판정)는 측정 임계 뒤 별도 승인으로 연다. 1차 검토(review-r1 ·
R1–R12) · 2차 검토(review-r2 · Q1–Q9) · 3차 검토(review-r3 · T1 — 클론 경량화 걷음)을 반영했다 — 회신은
같은 폴더 `reply-r1.md` · `reply-r2.md` · `reply-r3.md`.

근거 실측(코드 인용 전수 검증 완료) — `~/.hermes/workspace/colonova-strategy-2026-11-03/`
· `brief.md`(전략 브리프) · `n1-loop-map.md`(루프 지도) · `n2-confluence.md`(SSOT 통합)
· `n3-demo-speed.md`(데모 경로·병목) · `n4-direction.md`(제약·체크리스트) · `n6-verify.md`(독립 검증).
이 계획의 인용 중 `n3 …`·`n1 …` 표기는 그 문서를 가리킨다.

## 전제 — 이 계획이 어기지 않는 것

- 발행은 사람 · Confluence 원본은 AI 가 직접 안 건드린다. 자동 수정 · 자동 재제출 권고 없음.
- AI 의 Confluence 직접 쓰기 · 세션 MCP 주입 없음 — 조회 신호는 데몬이 REST 로(2026-11-03).
- 문서↔문서 정본은 Confluence SSOT · 화면↔문서 정본은 연결 레포 `plans-map.json` — 그래프 원장 새로 안 만듦.
- 프로토콜 버전 고정 — 선로는 선택 필드로만 확장.
- 사용자 문장은 `labels.ts` 한 곳 · 로그에 사용자 말·경로 남기지 않음.
- 기능 줄은 구현 변경과 같은 변경에서 `docs/FEATURES.md` 에(먼저 🚧).
- **루프의 실행은 양방향 모두 «판정 → 카드 → 사람이 누름»이다(2026-11-03 사용자 제안).** 화면→기획서는 같이
  고치기가 초안에 바로 쓰지 않고 카드로 먼저 묻고 눌러야 반영한다 — 2026-10-31 «채택 없이 바로 초안» 중
  같이 고치기 부분의 되돌림이다(기획 대화 안의 고침 — 사람이 먼저 말을 거는 일 — 은 현행 유지).
- **루프의 자동 판정을 설정에서 끌 수 있다(2026-11-03 사용자 제안).** 끄면 자동 판정 · 카드 · 반영이 멈춰
  추가 토큰이 들지 않고 양쪽 탭에서 루프 자리가 안 보인다. 사람이 부르는 맞춰 보기(C7) · 서로 답한다(C6)
  단추는 남는다. 연결 · 근거 기록은 유지해 다시 켜면 이어받는다. 옛 설계(걷힌 2026-11-02 계획 §8)는 환경
  변수 · 기본 꺼짐이었는데 이번에 설정 토글로 바꾼다.

- 전제가 틀렸다. n3 ② 는 «초대장이 `approveCommands` 를 실어 오지 않으면(기본) 무조건 한 번 막힌다»고 했지만 초대장 정규화는
  `approveCommands: entry.approveCommands !== false`(packages/protocol/src/invite.ts:324)다 — 초대장은 **기본이 승인**이고, 개발자가
  일부러 `false` 를 실은 초대장만 실행 허용 단추에서 멈춘다. 그 멈춤은 개발자가 고른 것이라 카드에서 건너뛰게 하면 그 뜻을 거스른다.
- 실행될 명령은 클론한 레포의 설정에서 읽힌다(packages/daemon/src/repo-bringup.ts:155–166 — 게이트가 «설치: … · 미리보기: …» 를
  싣는다). 초대 확인 카드는 클론 전이라 R7 의 «카드에 명령 목록을 그대로»를 지킬 수 없다.
- 결정 — **하지 않는다.** 초대장 없이 손으로 만든 프로젝트의 첫 실행 허용은 지금 길(오류 카드의 실행 허용 단추)이 명령을 보여 주므로 그대로 둔다.

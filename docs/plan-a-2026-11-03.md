# A안 실행 계획 — 양방향 루프 심화(2026-11-03)

사용자 결정 «A안으로 수정한다고 하면 수정 계획을 먼저 세워볼래»(2026-11-03)에 따른 실행 계획이다.
A안은 **자동은 화면→초안 한 방향을 유지하고, 반대 방향은 판정 카드와 사람의 손**으로 심화한다. B안(양방향
완전 자동)은 기각, C안의 요소(자동 판정)는 측정 임계 뒤 별도 승인으로 연다.

근거 실측(코드 인용 전수 검증 완료) — `~/.hermes/workspace/colonova-strategy-2026-11-03/`
· `brief.md`(전략 브리프) · `n1-loop-map.md`(루프 지도) · `n2-confluence.md`(SSOT 통합)
· `n3-demo-speed.md`(데모 경로·병목) · `n4-direction.md`(제약·체크리스트) · `n6-verify.md`(독립 검증).
이 계획의 인용 중 `n3 …`·`n1 …` 표기는 그 문서를 가리킨다.

## 전제 — 이 계획이 어기지 않는 것

- 발행은 사람 · Confluence 원본은 AI 가 직접 안 건드린다. 자동 수정 · 자동 재제출 권고 없음.
- AI 의 Confluence 직접 쓰기 · 세션 MCP 주입 없음 — 조회 신호는 데몬이 REST 로(2026-11-03).
- 문서↔문서 정본은 Confluence SSOT · 화면↔문서 정본은 연결 레포 `plans-map.json` — 그래프 원장 새로 안 만듦.
- 프로토콜 버전 고정 — 선로는 선택 필드로만 확장.
- 사용자 문장은 `labels.ts` 한 곳 · 로그에 사용자 말·경로 남기지 않음.
- 기능 줄은 구현 변경과 같은 변경에서 `docs/FEATURES.md` 에(먼저 🚧).
- **루프의 실행은 양방향 모두 «판정 → 카드 → 사람이 누름»이다(2026-11-03 사용자 제안).** 화면→기획서는 같이
  고치기가 초안에 바로 쓰지 않고 카드로 먼저 묻고 눌러야 반영한다 — 2026-10-31 «채택 없이 바로 초안» 중
  같이 고치기 부분의 되돌림이다(기획 대화 안의 고침 — 사람이 먼저 말을 거는 일 — 은 현행 유지).
- **루프 전체를 설정에서 끌 수 있다(2026-11-03 사용자 제안).** 꺼면 판정 · 카드 · 반영이 멈춰 추가 토큰이
  들지 않고 양쪽 탭에서 루프 자리가 안 보인다. 연결 · 근거 기록은 유지해 다시 켜면 이어받는다.

## 1단계 — 게이트 · 알림 · 속도(다섯 항목 서로 독립, 병렬 가능)

### 1-1 루프 게이트(양방향 카드)와 설정 토글 · 규모 M

- 무엇 — 루프의 실행을 양방향 모두 «판정 → 카드 → 누름 → 실행»으로 통일한다(2026-11-03 사용자 제안).
  - 화면→기획서: 같이 고치기가 초안에 바로 쓰지 않고 곁줄 카드 «초안을 고칠까요?» 로 먼저 묻는다 —
    손은 `고치기`(누르면 반영) · `건너뛰기`(짝을 기억해 다시 안 띄움 — 맞춰 보기 `compare-declines` 와 같은 결) ·
    `보기`(그 절 하이라이트). 판정 자체는 지금과 같은 quiet 실행이라 비용 변화가 없다 — 바로 반영 대신
    대기 상태로 바꿀 뿐.
  - 기획→화면: 화면 제안 카드(C8)의 `화면을 기획서대로` 손이 입력창 미리 채우기에서 «누름=보내기» 로
    바뀐다 — 누르면 브리프가 화면 대화로 바로 간다. 사람이 확인하고 요청하는 원칙은 유지되고 손이 하나 줄어든다.
- 설정 토글 — 라벨 후보 «기획서와 화면을 서로 맞춰요»(`labels.ts`). 자리 후보는 설정 AI 쪽(«AI 가 고치는 화면으로
  따라가기» 스위치 옆). 꺼면 판정 · 카드 · 반영이 전부 멈춘다(추가 토큰 0 — 판정 호출 자체를 안 돌린다) ·
  기획서 탭 · 곁줄의 루프 자리가 안 보인다. 연결(`plans-map.json`)과 근거 기록은 그대로 쌓는다 — 다시 켜면
  이어받는다. 다시 켤 때 «맞춰 보기로 쌓인 어긋남을 정리» 안내 한 줄.
- 고치는 곳 — `packages/daemon/src/screen-plan-sync.ts`(판정 결과를 반영 대신 대기로 — 기록
  `plans/screen-sync.jsonl` 에 대기 줄 상태) · `draft-service.ts`(`#adoptFromScreen` 을 카드 승인 뒤로) ·
  `mismatch-model.ts`(누름=보내기) · `machine-setting.ts`(토글 저장) · `packages/web/src/next/settings/*`(토글 UI) ·
  `packages/web/src/next/chat/PlanSyncLine.tsx`(카드) · `labels.ts` · `packages/protocol`(선택 필드 — 카드 상태
  방송, 버전 올리지 않음).
- 시험 — daemon(대기 상태 · 누름 반영 · 건너뛰기 짝 기억 · **토글 끔 때 판정 호출이 없음**을 증명 — 토큰 0 보장) ·
  web(카드 · 토글) · `next-labels`.
- 완료 기준 — 누름 없이는 초안 · 화면 어디도 바뀌지 않고, 토글 끔 상태에서 루프 비용이 0이다.
- 문서 — 같이 고치기 «바로 반영» 문구(F:675) · 곁줄 줄(F:676)을 게이트 모양으로 같은 변경에서 고친다.

## 승인 게이트 — 아직 구현은 시작하지 않는다

0단계(검증·측정) · 1단계(게이트 · 알림 · 속도) · 1.5단계(조건부 C1) · 2단계(별도 승인) 중 무엇을 언제 여을지

부분 승인으로도 시작할 수 있다.

# 화면 요청의 의미 단위 보관

2026-11-12 사용자 요청. 화면 요청을 한 덩어리로 보관하던 동작을, 독립적인 변경 단위의 커밋으로 나눈다.
분류는 Claude Haiku가 맡고 Git 쓰기는 데몬의 차선에 남긴다. 이 문서는 구현 결정과 검증 범위를 기록한다.

## 계약

- 사용자에게는 요청 하나의 결과다. 내부 커밋이 여럿이어도 같은 요청에 모두 연결하고 마지막 요청 전체를 되돌릴 수 있어야 한다.
- 기능 코드, 그 기능의 시험과 설명은 함께 묶는다. 파일별로 기계적으로 나누지 않는다.
- 같은 파일의 서로 떨어진 수정 구간도 분류할 수 있다. 구간 안에서 다시 코드를 재작성해 억지로 나누지는 않는다.
- 새 파일, 삭제, 바이너리와 파일 모드 변경 등은 불가분 조각으로 다룬다.
- 모델은 제목과 조각 ID, 순서만 반환한다. 패치를 만들거나 Git 명령을 실행하지 않는다.
- 분류 전 변경을 고정하고, 조각의 누락·중복과 중간 트리 구성, 마지막 트리의 원본 일치를 데몬이 검사한다.
- 분리된 중간 상태는 연결 레포가 선언한 검사로 확인한다. 검사가 없거나 실패하면 분리 성공으로 기록하지 않는다.
- 분류·검사 실패는 보관 실패와 다르다. 변경은 한 커밋으로 보관할 수 있으며 `fallback`과 이유를 기록한다.
- 준비 중 HEAD·index·파일이 달라지면 낡은 계획을 적용하지 않는다. 다른 변경을 덮는 복구는 하지 않는다.
- 원격 전송은 계속 사용자가 확인한 제출에서만 한다.

## 비용

기존 Haiku 단발 호출을 사용한다. 전체 대화 대신 요청과 변경만 보내고, 코드 재출력 없이 짧은 JSON을 받는다.
같은 기준·변경·요청·규칙에 대한 분류와 진행 중 호출은 재사용한다. 일반 소스가 입력 예산을 넘으면 잘라서
성공한 척하지 않는다. 큰 생성 자료는 분류 입력에서 요약하더라도 실제 보관에서 빠지지 않는다.
사용량은 종류와 숫자만 다룬다. 요청 원문과 경로를 통계에 남기지 않는다.

분류 캐시는 프로젝트별 메모리 32건이다. 진행 중 같은 입력도 한 호출에 합치며 적중은 호출 수를 다시 세지 않는다.
분류는 기본 한 번, 잘못된 JSON이나 조각 배치는 최대 한 번만 다시 묻는다. 검사 스크립트나 잠금파일이 없으면
분류 호출 자체를 생략한다. 분류가 제목도 만들므로 별도 제목 생성 턴은 실행하지 않는다.
실제 호출 수·SDK 재시도·입출력과 캐시 토큰·분류 시간·전체 보관 시간은 `atomic-save.jsonl` 최근 200행에 남긴다.

수정 모델에 별도 결과 형식을 요구하는 후보 수집, 장기 디스크 캐시, 실패한 그룹만 재분류하는 반복 호출은
첫 구현에 넣지 않는다. 먼저 한 번의 분류와 코드 검증을 측정한다. PR 설명은 기존처럼 커밋 제목과 최종 차이를 읽는다.

## 검증 기록

`pnpm typecheck`와 `pnpm test`의 전체 빌드가 통과했다. 전체 시험은 3,182개 통과·5개 건너뜀·실패 0개다.
변경한 소스·시험의 Biome 검사는 오류 0개이며 기존 `repo-publish.ts`의 `any` 경고 1개는 그대로다.

새 보관 경로 48개 시험을 통과했다. 실제 임시 Git에서 같은 파일의 수정 구간을 역순으로 묶는 경우, 바이너리·모드·추가·삭제,
누락·중복 거절, HEAD·index·파일 경쟁, 승인 범위 밖 staged 내용 보존을 확인했다. 중간 상태 검사가 실패하면 단일 보관으로
물러나고, 커밋 훅은 기존 경로에서 실행된다. 여러 커밋의 요청 전체 되돌리기, 기록 배치의 실패·동시 쓰기도 확인했다.
ref 이동 직후 결과 수신 실패와 재시작 복구, 다른 작업의 잠금 보존, 종료된 소유자의 임시 폴더 정리를 시험했다.
멈춘 smudge 필터는 시간 상한 뒤 자식 프로세스가 종료되고 임시 폴더·원래 파일 상태가 보존되는 것을 확인했다.

실제 Claude Haiku에는 합성 변경 두 개만 보내 한 번 호출했다. 검색 기능과 배경색 변경을 두 묶음으로 답했고,
같은 입력의 두 번째 요청은 호출 없이 캐시에 적중했다. SDK 보고 시간 3,839ms, 일반 입력 2·캐시 생성 1,620·출력 594토큰,
API 재시도 0회였다. 사용자 프로젝트의 실제 변경은 이 확인에 보내지 않았다. 한 사례의 수치이며 평균 절감률은 아직 측정하지 않았다.

검사는 레포 뿌리의 `check` 우선, 없으면 `typecheck`를 기존 설치된 패키지 매니저로 실행한다. 자식 패키지의 검사 명령을
자동 탐색하지 않으며 의존성을 새로 설치하지 않는다. 기존 모듈이 살아 있는 workspace 소스를 가리키면 단일 보관으로 물러난다.
커밋 훅이 있는 레포도 기존 단일 보관을 유지한다. 이 경우를 검증된 분리로 보고하지 않는다.
Electron에서 화면 요청부터 보관까지의 실제 여정, Windows 실행, 원격 GitHub 제출은 이번 확인 범위 밖이다.
의미적 독립성의 전부가 검사 한 번으로 증명되는 것은 아니다. 통과한 검사의 범위와 실제 실행을 구별한다.

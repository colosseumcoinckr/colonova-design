# 화면 작업의 최신 내용 적용

2026-11-12 사용자 결정 — 비개발자가 최신 `main`을 받을 때를 판단해야 하는 현재 흐름을 검토하고, 추천한 개선을 Herdr로 구현하도록 요청했다.

## 결정

새 화면 작업은 최신 기준을 준비한 뒤 시작한다. 진행 중인 작업은 유지하고, 사용자가 `최신 내용 적용`을 누르면 새 내용을 합친다. 제출할 때는 최신 기준을 확인하며, 적용으로 내용이 바뀌었다면 변경 목록을 다시 확인한 뒤 제출한다.

진행 중인 작업에는 자동 보관된 변경과 제출 이후의 추가 작업도 포함한다. 작업 폴더가 깨끗하거나 AI가 쉬는 것만으로 새 작업이라고 판단하지 않는다. 새 대화를 열어도 기존 화면 작업은 이어진다. 타이머와 창 포커스는 새 내용의 확인만 맡고 화면을 저절로 바꾸지 않는다.

이 결정은 2026-10-20의 «항상 수동으로 받아오기» 중 새 작업 시작과 제출 확인의 경계를 바꾼다. 기획서 발행과 문서·화면의 다름 카드에 관한 사람의 판단은 그대로다.

## 사용자 흐름

- 새 작업: 최신 내용을 확인하고 준비한 뒤 AI가 작업한다. 확인하지 못하면 최신이라고 표시하지 않는다.
- 진행 중: `개발자가 반영한 새 내용이 있어요`와 현재 작업을 유지한다는 안내를 보인다. 커밋 수는 사용자에게 보여주지 않는다.
- 적용: 현재 작업을 보관하고 복구 지점을 남긴 뒤 합친다. AI가 작업 중이면 끝날 때까지 기다린다.
- 충돌: AI의 정리를 시도하되 해결을 보장하지 않는다. 정리한 내용과 화면 확인이 필요함을 알린다.
- 제출: 최신 기준 확인과 사용자가 확인한 내용의 지문 검사를 함께 한다. 변경된 결과를 몰래 제출하지 않는다.

## 구현 경계

기준은 프로젝트의 `baseBranch`다. `main`을 고정하지 않는다. Git 쓰기는 기존 차선을 지나고, 원격 쓰기는 기존 제출 절차를 따른다. 기존 atomic 보관과 제출 SHA 고정은 보존한다. 프로토콜은 선택 필드로 확장하고 버전은 올리지 않는다.

감독자는 문서와 통합 검증을 맡고, Herdr 작업자 둘이 데몬·프로토콜과 웹 UI를 나눠 수정한다. 작업 전의 미커밋 변경은 보존한다.

## 완료 기준과 검증

새 작업의 최신 준비, 보관된 작업 보호, AI 작업 중 적용 대기, 원격 확인 실패, 제출 확인 이후 기준 변경, PR 병합 뒤 추가 작업 이월을 확인한다. 사용자 면은 새 내용 안내에서 적용과 제출 재확인까지 확인한다.

구현과 통합 검증을 마쳤다. 기존 사용자 변경을 보존했으며 커밋·원격 전송은 하지 않았다.

- `pnpm typecheck` 통과.
- `pnpm test` 통과. 전체 빌드 포함, 3,204건 중 3,199건 통과·5건 건너뜀·실패 0건.
- 마지막 충돌 안내 문구 보완 뒤 데몬을 다시 빌드하고 충돌·최신 적용 관련 시험을 재실행해 통과했다.
- 변경 영역 19개 파일의 Biome 검사와 `git diff --check` 통과.
- 로컬 git 하네스: 새 작업의 최신 기준 적용과 직전 HEAD 보존, 기존 사이클·미보관 변경·진행 중 턴 보호, 확인 도중 생긴 변경 보호, 원격 실패 거절, 적용 후 설치 실패와 재시도, 복구 지점 기록 실패 시 중단, 제출 직전 기준 변경과 원격 되감기 거절을 확인했다.
- 세션 시험: 직전 보관 → 최신 준비 → 실제 전달 순서, 준비 중 대기 요청, 공급자 재시도, 준비 실패 시 자동 반복 금지, 준비 중 대화 닫기를 확인했다.
- 브라우저 견본: `새 내용` 안내, 적용 전 제출 잠금, 적용 뒤 변경 목록 재조회와 제출, 적용 실패 시 잠금 유지, 충돌 정리 중 잠금과 완료 후 재조회, 560px 좁은 창을 확인했다. 제출은 견본 응답이며 실제 외부 제출은 아니다.
- 기존 전체 시험의 병합 뒤 이월·충돌 복구·제출 재시도도 통과했다. 확인 전 연결 실패와 확인 뒤 전송 실패를 나눠 기존 재시도 검증을 유지했다.

Herdr의 GLM-5.3과 SWE-2 작업 결과를 감독자가 검토·보완하고 검증했다. 작업자 창과 브라우저 시험 공간, 이 작업의 미리보기 서버는 정리했다.

## 확인하지 않은 범위

실제 사용자 설치본의 Electron, 실제 GitHub 원격과 PR 생성, 실제 AI의 충돌 해석 결과는 이번 검증에 포함하지 않았다. AI가 두 변경의 뜻을 함께 살릴 수 없다면 임의로 버리지 않고 판단할 내용을 남기도록 안내한다. 복구 참조는 개발자용이며 새로운 사용자 복원 단추를 추가하지 않았다.

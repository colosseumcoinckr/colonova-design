# 기획서 연결을 프로젝트 쪽으로 — 전역 설정과 프로젝트 설정 가르기(2026-11-13)

2026-11-13 사용자 결정 — 세 안(가 · 나 · 다) 가운데 «나»로 정했다(대화 · 추천안 채택).
설정 메뉴는 이 컴퓨터의 값을 두는 곳이고, 프로젝트마다 다른 값은 프로젝트 쪽(사이드바 전환기의 `프로젝트 정보`)에 둔다.

## 문제

설정 메뉴의 값은 하나만 빼고 모두 이 컴퓨터 전체의 것이다. 빠지는 하나가 기획서(Confluence) 연결이다.
사이트 · 계정 · 기준 페이지는 프로젝트마다 따로 저장된다(2026-11-03 프로젝트별 자격). 그런데 그 칸이 설정 → `연결` 쪽에
작성자 이름 · 연결 코드 · 전체 초기화와 나란히 있었다. 구분은 칸 머리의 프로젝트 이름 하나뿐이었다.
그래서 프로젝트를 바꾸면 설정의 같은 칸이 다른 값을 보인다는 것이 겉으로 드러나지 않았다.

## 지금 값의 자리 — 전역과 프로젝트

| 값 | 범위 | 저장 | 사용자가 고치는 곳 |
| --- | --- | --- | --- |
| 작성자 이름 · 개발팀 창구 · 연결 코드(GitHub) | 이 컴퓨터 | `machine.json` · OS 저장소(`pat`) | 설정 → `연결` |
| AI(로그인 · 모델 · 따라가기 · `기획서와 화면을 서로 맞춰요`) · 알림 · 테마 · 업데이트 · 개발자용 | 이 컴퓨터 | `machine.json` · 브라우저 저장소 | 설정의 각 쪽 |
| 전체 초기화 | 이 컴퓨터 | — | 설정 → `연결` |
| **기획서 연결**(사이트 · 계정 · 기준 페이지) | **프로젝트** | `machine.json` 의 `confluence…:<slug>` · OS 저장소 `confluence-pat:<slug>` | **이번에 옮김 → `프로젝트 정보` → `기획서 연결`** |
| 저장소 · 미리보기 · 목록에서 빼기 | 프로젝트 | `projects.json` | `프로젝트 정보` |
| 리뷰어 · 새 대화의 처음 값 · 사이클 수명 · 명령 승인 | 프로젝트 | `projects.json` | 초대 파일이 정한다(앱 안의 고치는 자리 없음) |

GitHub 토큰은 이 컴퓨터에 하나다. Confluence 계정은 프로젝트마다 따로이되, 처음 넣은 자격이 이 컴퓨터의 기본이 되어
같은 계정의 다른 프로젝트는 비워 두고 연결하면 물려받는다 — 계정만은 «반쯤 전역»이다. 칸을 둘로 쪼개지 않고 통째로
프로젝트 쪽에 둔다. 연결 검증이 사이트와 자격을 함께 쓰고, «비워 두면 기본 계정»이 그 자리에서 설명되기 때문이다.

## 세 안과 결정

| 안 | 내용 | 판단 |
| --- | --- | --- |
| 가 | 설정 `연결` 안에서 묶음 머리만 `이 컴퓨터` / `이 프로젝트` 로 가르기 | 자리가 그대로 섞인다 |
| **나** | 기획서 연결을 `프로젝트 정보` 쪽으로, 설정에는 그리로 가는 한 줄 | **채택(2026-11-13 사용자)** |
| 다 | 프로젝트 설정 장 신설 + 활성이 아닌 프로젝트 관리(`slug` 선택 필드) + 연결 끊기 | 지금은 열지 않는다 |

«다»를 미룬 까닭 — 지금의 무게는 굳히기다(`intend.md`). 실제 사용자는 프로젝트가 보통 하나라 활성이 아닌 프로젝트의
연결을 고칠 일이 아직 기록에 없다. 첫 한 바퀴의 기록(`docs/first-walk-record-2026-11-12.md`)에 그 막힘이 적히면 그때
조건부 조각으로 연다(2026-11-12 결정 ㉮와 같은 규칙).

## 모양 — 카드의 한 줄과 대화상자

`프로젝트 정보` 카드는 사이드바 폭의 팝이라 연결 폼(입력 셋 · 기준 페이지 찾기 결과)이 들어가지 않는다.
그래서 카드에는 `기획서 연결` 한 줄(상태 글)만 서고, 누르면 **기획서 연결 대화상자**가 뜬다. 폼은 설정에 있던 것을 그대로 쓴다.
사용자가 고른 것은 «칸을 옮기기»였고 새 겹판이 아니었다 — 폭 때문에 대화상자가 됐다는 것을 여기 남긴다(감독자 판단).

- 여는 길 셋이 한 대화상자로 모인다 — `프로젝트 정보` 의 `기획서 연결` 줄 · 기획서 자리의 연결 단추들(빈 상태 · 목록 ·
  사이드바 · 끊김 줄) · 설정 → `연결` 의 `기획서 연결` 줄의 `열기`.
- 설정에서 열 때는 설정이 실제로 닫힌 뒤에 연다 — 작성자 이름 저장이 실패하면 설정이 닫히지 않기 때문이다.
- 대상은 여전히 활성 프로젝트다. 선로 · 데몬 동작 · 프로토콜은 그대로다(데몬의 만료 문장 한 줄만 새 자리를 말한다).
- 문장은 늘 `기획서 연결` 이라 부른다 — `설정에서 연결하기` · `설정 열기` 같은 «설정» 안내를 걷었다.

- 시험 — 빌드 · 전체 순수 시험 3,213(통과 3,208 · 실패 0 · 건너뜀 5) · biome(바꾼 파일) 오류 0. 새 계약 시험

  대화상자의 폼 · nav 계약 · 설정 닫힘 뒤 열기 · 설정이 대화상자 아래에 깔리지 않음 · 입력 칸이 값을 받음 · 카드 줄 CSS 범위를 붙잡는다.
- 격리 셸(가짜 Confluence · 가짜 AI · 브라우저)로 걸었다 — ① 기획서 빈 상태 `기획서 연결하기` → 대화상자 → 연결 → 기준 페이지 고르기 →
  닫으면 문서 5개 목록 ② `프로젝트 정보` → `기획서 연결` → 대화상자 ③ 설정 → `연결` → `열기` → 설정이 닫힌 뒤 대화상자 ·
  그냥 닫은 설정은 아무것도 열지 않음 ④ 좁은 창 — 서랍이 닫히고 닫은 뒤 초점은 `메뉴 열기` ⑤ 틀린 토큰은 대화상자 안의 실패 문장 ·
  ⌘K 팔레트의 `설정` 은 대화상자를 닫고 설정을 연다.
- 검토(다른 모델)가 낸 일곱 가운데 여섯을 고쳤다(시험 · 제목 두 번 · 초기화 중 표식 · 설정이 아래에 깔림 · 만료 견본 · 견본 글꼴).
  수리 도중 사이트 칸의 입력이 막힌 것과 메뉴 전체에 걸린 글자 규칙을 감독자가 diff 에서 찾아 고쳤다.
- 확인 밖 — 실제 Electron · 실제 Confluence · 실제 사용자. 설정 왼쪽 목록의 `연결` 알약은 지금도 연결 코드만 세고 기획서 만료는 세지 않는다
  (옛 설정 칸 때도 같았다 — 만료는 카드 · 설정 줄 · 기획서 자리의 노란 줄이 말한다).

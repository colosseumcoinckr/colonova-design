# 기획자 체험과 반영

2026-11-12 사용자 요청 — «개발 지식 없는 기획자로 이 상태의 프로그램을 체험해 보고 개선». 같은 날의 두 검토
(`ui-ux-review-2026-11-12.md` · `nondev-usability-2026-11-12.md`)는 코드와 견본을 읽었고 앱의 흐름을 끝까지 걷지는 않았다.
이번에는 실제 셸에서 실제 AI 로 걸었고, **걷다가 실제로 막히거나 잘못 읽힌 것만** 고쳤다. 무엇을 고칠지는 오케스트레이터의 판단이다 —
사용자가 항목별로 정한 것이 아니다. Confluence 원본 · 초안 보관 · 사람의 발행 · 「판정 → 카드 → 사람이 누름」의 계약은 그대로다.

## 어떻게 걸었나

- 원본 작업 트리의 사본을 빌드해 격리 데몬을 띄웠다(임시 홈 · 사용자의 데이터와 떠 있는 앱은 건드리지 않았다).
  AI 는 사용자의 실제 Claude 로그인이다 — 턴 통계로 화면 요청 8번 · 되풀이를 재현한 첫 걸음의 AI 넘김 15번, 그리고 기획 대화 1번과
  앱이 스스로 돌리는 판정 · 요약 몇 번. 서비스는 견본 «회원 서비스»(로그인 · 회원가입 · 알림 설정 화면),
  Confluence 는 발행하면 판이 오르는 상태 있는 가짜 서버(문서 5장 · 코멘트 · 라벨 · 판 기록)다.
- 셸은 브라우저(Playwright)로 몰았다 — **Electron 이 아니다.** 미리보기는 웹뷰가 아니라 iframe 이라 화면 이름 따라가기 · 답 뒤 새로 고침 ·
  화면 확인 게이트는 보지 못했다. 실제 Confluence · 실제 GitHub 제출도 아니다.
- 걸은 길: 화면 고치기 → 보관 → 제출 창 → 제출 / Confluence 연결 → 기준 페이지 → 문서 읽기 → 기획 대화로 고침 → 견주기 → 발행 →
  판 고르기 → 직접 고침 → 되돌리기 / 다름 카드의 `화면을 기획서대로` / 대화 둘 사이의 끝남 표시 / 좁은 창.

## 걸어서 확인한 것

오전 문서가 «확인하지 못한 것»으로 남긴 항목을 격리 셸과 가짜 Confluence 에서 걸어 본 것이다 — 실제 앱 · 실제 Confluence 의 확인은
여전히 남는다.

| 항목 | 본 것 |
| --- | --- |
| 연결 직후 가져오기 | 기준 페이지를 고르자 곧바로 `방금 가져왔어요 · 문서 5개` — 목록이 스스로 따라왔다 |
| 발행 | 발행 창(점검 · 전후 표) → `Confluence 에 발행이 반영됐어요` → 원본이 판 2 로 오르고 고침이 들었다. 가짜 서버의 기록에 발행(PUT) 바로 뒤의 다시 읽기와 바뀐 문서 찾기가 남았다 — 발행 뒤 사본이 따라온다 |
| 끝남 표시 | 다른 대화를 보는 사이 끝난 답의 줄에 `답이 끝났어요` 가 서고 열면 사라졌다 |
| 초안에서 돌아가는 길 | 판 고르기 → 옛 판 → `N판으로 되돌리기` 로 직접 고침을 되돌렸다 |

Confluence 의 판 기록 창 머리 한 줄(잘못 발행에서 돌아가는 길)은 이번에도 보지 못했다.

## 막힌 곳과 고친 것

| 본 것 | 고침 | 자리 |
| --- | --- | --- |
| **보관 실패가 AI 에게 끝없이 넘어갔다.** 답 뒤의 자동 보관이 GitHub 계정 확인에서 실패하자 `보관에서 문제를 찾아 AI에게 맡겼어요` 카드 → AI «제가 고칠 수 없어요» → 다시 보관 → 다시 AI. 75초에 10번, 멈출 때까지 15번. AI 스스로 «아홉 번째로 같은 안내가 나왔어요»라고 답했다 | 이 기계 · 계정 쪽 원인(인증 · 권한 · 한도 · 네트워크 · GitHub 응답 없음 · 계정 정보 못 읽음)은 AI 에게 넘기지 않는다. 그 밖의 실패도 같은 내용으로 잇달아 두 번까지만 넘긴다. 넘기지 않은 실패는 그 대화에 `보관하지 못했어요 — 연결에 문제가 있어요. …` 같은 한 줄로 남는다(같은 실패는 한 번만 · 연결 코드와 권한 문제만 개발자에게도 알린다) | 데몬 `repo-publish.ts` · `submit-state.ts` · `developer-notice.ts` |
| 기획서 자리의 `설정에서 연결하기` · `설정 열기` 가 설정의 `AI` 쪽을 열었다 — 연결 칸을 스스로 찾아야 했다 | 설정이 처음 설 쪽을 받는다. 두 단추는 `연결` 쪽을 연다 | `Workspace.tsx` · `SettingsDialog.tsx` · `plans/` |
| 기획 대화 칸이 오른쪽으로 넘쳤다 — 긴 대화 제목이 칸 머리를 밀고, 답 아래 카드의 글 끝이 잘리고, 문서 판이 가로로 굴러 제목 왼쪽이 잘렸다 | 머리 · 글 몸 · 카드가 칸 폭 안에서 줄어들고 줄을 바꾼다 | `plans/draft/draft.css` · `ui/ui.css` |
| 초안을 보는 동안에는 코멘트로 가는 길이 보이지 않았다 — 발행 창은 `안 풀린 코멘트 1개` 라고 하는데 초안 머리와 `⋯` 어디에도 코멘트가 없다(목록에서 문서를 다시 눌러 읽는 화면으로 나가면 있다는 것은 나중에야 알았다) | 초안 머리에 `코멘트 N개` — 읽는 문서와 같은 서랍 | `plans/comments/DocDrawer.tsx` · `DraftEditor.tsx` |
| 발행을 마쳐도 목록 줄의 `초안` 점과 으뜸 `발행` 단추가 그대로였다 | 점은 발행할 것이 있을 때만. `발행` 은 발행할 것이 없으면 보통 단추. 발행할 것은 발행의 잣대 그대로 센다 — 고침 · 더함 · 지움 · 제목만 바꿈 · 새 문서 초안(사이드바의 `초안 N` 도 같은 잣대). 제목만 바꾼 발행 창은 `발행할 것이 없어요` 대신 `제목만 바뀌어요` | `plans/plans-list.ts` · `drafts-in-progress.ts` · `DraftEditor.tsx` · `PublishDialog.tsx` · 요약의 선택 필드 `titleChanged` |
| 견주기를 켠 채 발행하면 문서 대신 `발행본과 바뀐 곳이 없어요` 만 남았다 — 단추에 켜짐 표시가 없었다 | 견주기 단추가 눌린 모양으로 서고, 발행이 반영되면 꺼진다 | `DraftEditor.tsx` |
| 다름 카드의 `화면을 기획서대로` 는 알림만 잠깐 뜨고 줄은 그대로였다 — 다시 누르면 같은 요청이 또 간다 | 바로 보낸 줄은 단추 대신 `화면 대화로 보냈어요 — 답은 화면 자리의 대화에 와요` | `ui/MismatchCard.tsx` |
| 읽히지 않는 말 — `AI 로그인이 끝났어요`(마쳤다로도 읽힌다) · 판 고르기의 `정산` · 좁은 창 입력창의 `수정할 곳 선택`(다른 곳은 `찍기`) | `AI 로그인이 풀렸어요` · `자동 정리` · `찍기` | `labels.ts` |
| 발행 창의 좁은 표에서 `비밀번 / 호` 처럼 낱말 가운데가 꺾였다 | 표 칸은 낱말 단위로 줄을 바꾼다 | `draft.css` |

경로는 웹은 `packages/web/src/next/`, 데몬은 `packages/daemon/src/` 기준이다. 프로토콜은 초안 요약에 선택 필드 하나(`titleChanged`)만 더했다 — 버전은 그대로다.

## 고치지 않고 남긴 것

- **사용자가 정할 것** — 제출 창의 `화면에 드러나지 않은 변경 N건`: 화면의 단추 글자를 바꿨는데도 이 말이 섰다(견본 서비스는 화면 목록이 없어 고친 파일을
  화면에 잇지 못했다). GUIDE 는 «화면과 연결되지 않은 변경»이라 쓴다. 실제 프로젝트에서 얼마나 자주 서는지 보고 낱말을 정한다.
- **뒤로 미룬 것** — 초안 머리의 `이어진 화면` 서랍(읽는 문서 부품 안의 상태 150줄을 끌어올려야 한다) · 초안 머리의 라벨과 `화면과 맞춰 보기` ·
  기획서 자리에서 화면 AI 의 답이 끝났다는 표시(끝남 표시는 화면 자리의 대화 목록에만 선다 — 오전 문서의 «지금 볼 것 한 곳»에 걸린다) ·
  견주기의 전후 표에서 바뀐 칸만 짚어 주기 · `화면에서 확인` → `근거로 보내기` → `입력창에 담기` 로 이름이 세 번 바뀌는 것.
- **견본 탓이라 세지 않은 것** — 화면 고르기의 `화면 0곳`, 화면 이름이 `첫 화면` 에 머문 것, 답 뒤 미리보기가 새로 고쳐지지 않은 것, 제출이 끝나지 않은 것.
- 오전 문서와 UI/UX 검토가 «넣지 않은 것»으로 둔 항목은 다시 열지 않았다.

## 검증

- 고침마다 같은 걸음을 실제 셸에서 다시 걸었다. 보관 실패는 두 방아쇠에서 AI 넘김 0번 · 카드 0장을 보았다 — 계정 응답이 불완전한 방아쇠는
  한 줄을 더하기 전에 걸어 «아무 표시가 없다»는 빈틈을 찾았고, 대화의 한 줄은 GitHub 주소를 닫힌 포트로 돌린 오프라인 흉내에서 두 번 보았다
  (앞의 방아쇠의 한 줄은 시험이 본다). 웹은 넘침의 수치(대화 칸 379/379 · 글 몸 347/347 · 문서 판 1120/1120 · 카드 317 ≤ 317),
  설정이 `연결` 로 열리는 것, 발행 뒤 점과 단추, 견주기의 `aria-pressed`, 보낸 줄의 한 줄, 초안 머리의 코멘트 서랍(가짜 원본의 코멘트 1개)을 보았다.
  좁은 표의 줄바꿈은 견본에서만 보았다. 읽는 문서의 서랍 껍데기를 공통 부품으로 뺀 뒤 기획서 견본 시나리오 열(`test/cold/plans-ux.cjs`)이 통과했다 —
  읽는 문서의 코멘트 서랍을 손으로 다시 열어 보지는 않았다. 초안 점과 `발행` 은 다섯 경우(안 고침 · 제목만 · 더하기만 · 지우기만 · 새 문서)와 제목 발행 뒤를 걸었다 —
  제목만 바꾼 초안에서 점과 으뜸이 사라지는 회귀를 이 걸음에서 찾아 고쳤다.
- 작업은 원본의 사본에서 했다(원본에서는 앱이 돌고 있었다). 사본의 전체 빌드 통과, 전체 시험 3,030개 중 3,025 통과 · 실패 0 · 건너뜀 5
  (반영 전 3,017개 — 새 시험: 보관 실패의 갈림과 한도 · 실제 git 으로 끊김 → 복구 · 대화의 한 줄 · 보낸 줄의 흔적 · 초안 점과 초안 수의 판정). 바꾼 코드의 biome 오류 0.
- 확인하지 못한 것: Electron 에서의 같은 걸음, 실제 Confluence · 실제 GitHub, Windows. 한도로 멈춘 뒤의 한 줄(분류되지 않는 실패 세 번째)과
  연결 코드가 만료된 갈래의 한 줄 · 개발자 알림은 시험으로만 확인했다.
  보관 실패의 한 줄은 자동 보관을 부른 대화에 서고, 대화를 모르는 길(감독자의 뒤늦은 보관)은 마지막으로 쓰던 대화에 선다.

# 기획서와 화면 잇기 · 대조 — 후속 계획 후보

2026-10-23. 출처: 같은 날 사용자 제안(대화). "기획 문서와 화면을 연결하고 DAG 로 시각화한다. AI 로 실제 화면이
기획서대로 구현됐는지 판별한다." 이 문서는 그 제안을 지금 코드 위에서 짓는 순서로 옮긴 후보다.

**상태: 후보다. 실행 대기열이 아니다.** 범위 · 순서 · 완료 기준의 정본은
[최종 구현 계획](confluence-sync-plan-2026-10-18.md)이다. 정본 §5 · §11 · A11 이 이 제안의 일부를 막고 있다(2절).
채택하려면 사용자 결정과 정본 개정이 먼저다(정본 §15 "분석 · 자동 발행 · 공동 편집 서버로의 확대는 별도 사용자
결정 없이는 하지 않는다"). 정본의 다음 실행 단위(G0 → G2 → G1 · G3 · G4 실측)는 이 문서로 바뀌지 않는다.

## 1. 제안과 목표

- 기획서(문서 · 절 · 판)와 연결 레포의 화면(미리보기 주소)을 잇는다.
- 이은 관계를 보이게 한다. 문서에서 화면으로, 화면에서 문서로 오간다.
- AI 가 실행 중인 화면을 보고 기획서의 규칙과 대조한다. 결과는 사람이 확인한다.

정본 §1 의 목표 "근거로 CDP 의 실제 화면을 만들어 확인하며, 발견한 결정을 다시 기획서에 남긴다"를 돕는다.
돕는 인수 기준은 A10 · A11 이다. 다만 전환 완료(F5) 인수에는 넣지 않는다. A11 은 "자동 정책 일치 판정에
의존하지 않는다"이다. 대조는 있어도 되고 없어도 되는 도구로 둔다.

## 3. 이미 쌓이는 재료

2026-10-23 코드 기준이다. 새 저장 없이 문서 → 화면을 이을 수 있다.

| 기록 | 위치 | 담는 것 | 한계 |
| --- | --- | --- | --- |
| 근거 기록 | 프로젝트 데이터 `plans/refs.jsonl` (`plan-refs.ts`) | 시각 · 대화 id · 문서(제목 · 페이지 id · 초안 열쇠 · 판 · 개정 · 고른 절) | 근거 보내기로 첨부한 것만 남는다. 요청 순간에 굳는다(소급 없음). |
| 화면 지도 | 프로젝트 데이터 `screen-map.jsonl` (`screen-map.ts`) | 자동 보관 커밋마다 시각 · sha · 대화 id · 화면 주소 · 화면 제목 · 파일 · 확인 기록 | 화면을 만진 커밋만 남는다. 상한 500행이라 오래된 행은 버려진다(`screen-map.ts:17`). |
| 이번 작업의 화면 | `RepoStatus.cycleScreens` (`cycle-screens.ts`) | 사이클의 커밋 × 화면, 대화 id | 이번 사이클만이다. |
| 원장 | 프로젝트 데이터 `confluence/confluence.json`(2026-10-23 사본 이동 — 예전엔 클론 `docs/plans/`) | 페이지 id · 경로 · 제목 · 판 · 절 목록 | 기준 페이지를 바꾸면 비워진다(`resetLedgerOnRootChange`). |

잇는 열쇠는 대화 id 다. 근거 기록의 대화 id = 화면 지도의 대화 id 이면 "이 대화가 근거로 쓴 문서 ↔ 이 대화가 고친
화면"이 나온다. 대화 단위라 거칠다. 한 대화가 문서 셋과 화면 둘을 다뤘으면 여섯 짝이 모두 선다. 어느 문서가
어느 화면의 근거인지는 가리지 못한다. 2단계가 이 틈을 사람의 손으로 메운다.

## 4. 단계

### 1단계 — 근거 지도 보기

새 저장이 없다. 이미 있는 두 기록을 읽어 보여 준다.

- 데몬: 순수 함수 하나(`plan-trace.ts` 후보). 근거 기록 × 화면 지도를 대화 id 로 잇고
  (페이지 id · 판 · 절) ↔ (화면 주소 · 제목 · 시각) 목록을 낸다.
- 선로: 읽기 요청 하나를 선택 필드로 더한다. 프로토콜 버전은 올리지 않는다.
- 웹: 문서 보기(`PlanDocView.tsx`) 머리에 "이 문서를 근거로 고친 화면" 목록. 누르면 미리보기가 그 주소로 간다.
  화면 쪽은 이번 작업 목록의 화면 줄에 "근거 문서" 알약. 누르면 기획서 칸에서 그 문서 · 절이 열린다.
- 판 안내: 근거의 판보다 원장의 판이 새로우면 "화면을 만든 뒤 문서가 바뀌었어요"를 보인다. 판 숫자 비교라
  판정이 아니다. 무엇이 바뀌었는지는 사람이 본다.
- 완료 기준: 순수 함수 시험(대화 id 잇기 · 판 비교 · 깨진 줄 · 500행 밖). 격리 데몬에서 근거 보내기 → 화면 고침
  → 보관 → 문서 보기에 화면이 서는 사진.
- 의존: F3 의 근거 보내기. F3 인수 뒤가 권고다.

### 2단계 — 사람이 만드는 연결

- 문서의 절과 화면 주소를 사람이 잇고 끊는다. 1단계 목록의 줄에서 "연결로 남기기" 한 번으로도 만든다.
- AI 는 연결을 만들지 않는다. 제안도 이 단계에서는 하지 않는다(§5 "자동 관련 문서 매칭 없음").
- 열쇠: (페이지 id · 절 머리말 · 화면 주소). 같은 열쇠는 한 줄이다.
- 절 머리말이 바뀌거나 문서가 휴지통으로 가면 "절을 찾지 못함"을 보인다. 다른 절로 저절로 다시 잇지 않는다
  (A7 "대상 소멸을 다른 절로 치환하지 않는다"와 같은 원칙).
- 저장: 프로젝트 데이터 `plans/links.json` (클론 밖). 원장 안에 두지 않는 이유는 둘이다. 원장은 기준 페이지를
  바꾸면 비워진다. 2026-10-23 계약은 기획 작업 데이터를 클론 밖에 둔다. 쓰기는 같은 폴더의 임시 파일 → rename 이다.
- 이 컴퓨터에만 산다. 팀에 보이는 기록은 지금처럼 제출 본문의 기획 근거 절이 맡는다.
- 완료 기준: 연결 저장소 시험(합치기 · 고아 · 깨진 파일). 재시작 뒤 복구. 기준 페이지를 바꿔도 연결이 남고,
  새 원장에 없는 페이지의 연결은 고아로 서는 사진.

### 3단계 — 사람이 누르는 대조

- 사람이 문서(또는 절)와 연결된 화면에서 대조를 누른다. AI 가 실행 중인 미리보기를 열고 절의 규칙마다
  **맞음 · 어긋남 · 못 봄** 으로 답한다. 화면도 문서도 고치지 않는다.
- 실행 경계: 화면 세션은 bypassPermissions 이고 쓰기 도구가 있다. 사용자 설정도 싣는다
  (`session.ts:235` 의 `settingSources: ["user", "project", "local"]`) — 사용자 MCP 의 쓰기 도구까지 붙는다.
  "고치지 않는다"를 지시로만 막지 않는다. 대조는 `tools: []` · `settingSources: []` 인 실행으로 돌린다
  (`one-shot.ts` 와 같은 꼴).
- 화면을 보는 길: 앱은 화면 AI 에게 미리보기 도구를 주지 않는다 — 2026-10-20 내장 MCP 제거(DEVELOPERS 88행 · 670행 ·
  AGENTS.md). 그래서 도구 없는 실행은 스스로 화면을 열 수 없다. 길은 둘이다.
  - (가) 데몬이 미리보기 창 계약(`preview-driver.ts` 의 `open` · `snapshot` · `screenshot`)으로 그 주소를 열어
    접근성 줄과 사진을 찍고, 그것을 도구 없는 실행에 넣는다. 10-20 결정과 부딪히지 않고 쓰기가 원천적으로 없다.
    대신 한 상태만 본다 — 눌러야 나오는 예외 · 권한 · 상태 조건은 대부분 못 봄이 된다.
  - (나) 대조 실행에 미리보기 조작 도구를 준다. 여러 상태를 볼 수 있지만 10-20 "내장 MCP 미주입" 결정을 다시 열어야 한다.
  - 권고는 (가)로 시작하고, 못 봄이 너무 많으면 (나)를 사용자 결정으로 올리는 것이다.
- 입력: 절 스냅샷(근거 스냅샷과 같은 불변 규칙 — 판 · 개정 고정)과 화면 주소. 브리프는 첫 줄 표식
  `<!-- colonova-design:<새 kind> … -->` 로 카드가 된다. 파일 경로 · 컴포넌트 이름을 쓰지 않고 끝의 기준 한 줄로 닫는다.
- 출력: 항목마다 한 줄, 절 머리말이 앞에 선다. 점수 · 합격 · 불합격을 내지 않는다. 못 봄을 숨기지 않는다 —
  TBD · 권한 · 데이터가 없는 상태는 화면에서 볼 수 없다. 결과는 그 시점의 기록이고 구현 완료 표시로 쓰지 않는다.
- 다음 행동: 어긋남 줄에서 사람이 고른다. 화면 대화에 고치기를 요청하거나, 기획 대화에 문서 변경안을 요청한다.
  미결 큐는 만들지 않는다.
- 결과 저장: 프로젝트 데이터 `plans/audits/` (클론 밖). 로그 · 턴 통계에는 종류와 수(맞음 n · 어긋남 n · 못 봄 n)만 남긴다.
- 완료 기준: 견본 문서와 견본 화면으로 맞음 · 어긋남 · 못 봄이 각각 한 번 이상 나오는 사진. 대조 실행 중
  파일 쓰기 · git 쓰기가 일어나지 않음을 시험으로 보인다.

## 5. 보이는 모양 — 그래프가 아니라 이웃 보기

- 문서끼리의 링크는 1,122개다(2026-10-17 측정 · 10-19 설계 이력). 한 장에 그리면 읽을 수 없다.
- 문서끼리는 서로 가리킬 수 있어 전체가 DAG 라고 장담할 수 없다. 문서 → 화면 한 방향의 두 층만 그리면 DAG 다.
- 정본 §11 이 별도 대시보드를 막는다.
- 그래서 한 장 기준으로 보인다. 문서 쪽은 "이 문서를 근거로 고친 화면" 목록과 절 머리의 화면 알약이다. 화면 쪽은
  "근거 문서" 알약이다. 누르면 반대편으로 간다.
- 문서 층과 화면 층을 한 그림으로 보는 보기가 필요하면 2단계 뒤에 다시 정한다. 그때도 기획서 칸 안의 한 보기다.
- "그래프 · DAG · 노드" 같은 말은 사용자 문장에 쓰지 않는다.

## 6. 폴더 구조

코드가 만드는 모양이다. 이 컴퓨터는 2026-10-23 현재 Confluence 에 연결돼 있지 않다(`machine.json` 에 연결 값이
없다). 실제 SSOT 를 앱 자격으로 가져오는 검증(G0)도 아직이다. `+` 는 이 계획이 더하는 것이다.

```
~/.colonova-design/
├─ config/
│  ├─ projects.json            프로젝트 목록
│  └─ machine.json             confluenceSite · RootId · RootTitle:<slug> — 프로젝트별 연결
└─ projects/<slug>/
   ├─ repo/                    연결 레포 클론 — 기획서 파일이 들어가지 않는다(2026-10-23 사본 이동)
   ├─ confluence/              Confluence 사본 — 읽기 전용, 클론 밖이라 보관 · 제출에 타지 않는다
   │  ├─ confluence.json       원장
   │  └─ <공간키>/<기준 페이지>.storage.xml · .md
   │              <기준 페이지>/<하위 제목>/… 같은 꼴
   ├─ plans/                   기획 작업 데이터 — 클론 밖
   │  ├─ drafts/ proposals/ threads/ intents/ ops/ comment-ops/ trash.json
   │  ├─ refs.jsonl            근거 기록
   │  ├─ links.json          + 2단계 연결
   │  └─ audits/             + 3단계 대조 결과
   ├─ screen-map.jsonl         커밋마다 화면 주소 ↔ 파일
   └─ cycle.json · session-tape.jsonl
(키체인) confluence-pat         이메일 + 토큰 — 기계 하나에 한 벌
```

- 연결 · 대조는 프로젝트마다다. 화면이 그 프로젝트의 것이기 때문이다.
- 두 프로젝트가 같은 기준 페이지를 연결하면 사본 · 연결 · 대조가 두 벌이다. 페이지 id 는 프로젝트가 달라도 같아서
  나중에 묶을 수 있다(범위 밖).
- 알려진 충돌(이 계획과 별개 — 2026-10-23 닫힘): `colonova-cdp` 레포는 자기 `docs/plans/` 에 기획 문서 4개를 커밋해 두었다.
  예전 가드와 보관 거름이 연결 여부와 상관없이 `docs/plans/` 전체를 막아 AI 가 이 4개를 고치지 못하고 보관에서도 빠졌다.
  사본 이동으로 그 예외를 지워 이 4개는 보통 레포 파일이 됐다(7절 6번).

## 7. 사용자가 정할 것

1. 이 계획을 정본에 들일지. 들인다면 §5 "문서와 데모" 줄을 고치고 후속 단계(F6 후보 — F5 뒤, F4 처럼 전환 완료
   문턱 밖)로 둔다.
2. 1단계의 시기. 권고는 F3 인수 뒤다. 정본의 실측 순서(G0 → G2 → G1 · G3 · G4)를 앞지르지 않는다.
3. 연결의 저장 위치. 권고는 프로젝트 데이터 `plans/links.json` 이다(4절 2단계).

## 8. 같이 적어 두는 작은 틈 (이 계획과 별개)

같은 대화에서 확인한 것이다. Confluence 자격은 기계 하나에 한 벌이고 연결은 프로젝트마다다. 같은 계정이면
프로젝트 하나 ↔ Confluence 하나를 여러 짝으로 둘 수 있다. 다만 둘이 거칠다.

- 새 프로젝트를 연결할 때마다 이메일 · 토큰을 다시 넣어야 한다. 데몬은 저장된 자격을 다시 쓸 수 있지만 화면의
  연결 버튼이 막는다(`confluence-form.ts:164`).
- 토큰이 만료되면 모든 프로젝트가 같이 끊긴다. 한 프로젝트에서 다시 연결하면 그 프로젝트의 만료만 풀린다
  (`confluence-sync.ts:246`). 나머지는 하나씩 다시 넣거나 앱을 다시 켜야 한다.

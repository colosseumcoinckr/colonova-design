# 요청 결과·화면 확인·제출 검토 개선

2026-10-02 · 이전 단계: [P1 구현 결과](IMPLEMENTATION.md) · 근거: [수정 전 QA와 제안](REPORT.md)

요청별 결과 카드, 크기별 직접 확인, 제출 전 검토 화면을 구현했다. 오케스트레이터가 범위·검토·Computer Use 검증을 맡고, GPT-6.1-Sol이 제품 코드를 구현했다. 별도 Sol이 변경과 후속 수정을 검토했다.

## 달라진 흐름

| 흐름 | 현재 동작 |
| --- | --- |
| 요청 → 결과 | 변경이 기록된 요청에 관련 요청·답변의 변경 설명·당시 사진·현재 화면 열기·전후 비교·추가 수정이 함께 보인다. 자동 확인이 이어져도 같은 사용자 요청의 결과를 중복 생성하지 않는다. |
| 화면 → 직접 확인 | 최근 수정 화면을 목록에서 찾고 PC·태블릿·휴대폰별로 확인 표시를 남긴다. 결과 카드·화면 목록·미리보기·제출 창이 같은 상태를 읽는다. 사진 열람이나 자동 검사 통과는 직접 확인으로 세지 않는다. |
| 제출 → 최종 검토 | 넓은 검토 창에서 프로젝트 전체의 최종 변경, 확인 현황, 그 밖의 변경, 받을 개발자, 메모를 확인한다. 미확인 크기는 안내하되 제출을 막지 않는다. 목록이 오래됐거나 읽기에 실패하면 제출을 막는다. |

추가 수정은 기존 문장·첨부·핀을 유지한 채 편집할 요청을 준비한다. 화면 정보는 그 초안에 연결하며, 자동 전송하지 않는다. 제출 메모와 직접 확인 표시는 이 앱의 로컬 저장소에 보관한다.

확인 표시는 프로젝트·화면 주소·크기·변경 버전에 연결한다. 화면 밖의 공통 변경도 놓치지 않도록 제출 기준이나 최종 변경이 달라지면 모든 화면을 다시 확인 대상으로 삼는다. 주소의 선택 조건이 다른 화면은 별개로 취급한다. 저장된 변경과 연결할 수 없는 현재 화면에는 표시를 남길 수 없으며 그 이유를 안내한다.

## 실사용 중 발견해 고친 문제

제출 메모의 자동 초점 때문에 닫은 뒤 사라진 입력칸으로 돌아가던 문제를 수정했다. 제출 버튼을 복귀 대상으로 지정한다. 제출 위에 비교 창을 열 때 아래 창도 활성 모달로 선언돼 접근성 항목이 사라지는 문제는 최상위 창만 활성화하도록 고쳤다. 일반 앱에서 비교 창과 Esc 초점 복귀를, 격리 화면에서는 Tab·역방향 Tab의 초점 순환도 확인했다.

여러 화면 때문에 창이 화면 높이를 넘는 문제는 제목과 하단 버튼을 고정하고 본문·메모를 스크롤하도록 보완했다. 선택된 PC 버튼을 다시 눌러 확인 기능이 멈추는 문제와, 추가 수정의 화면 정보가 다른 초안으로 넘어가는 경합도 수정했다.

## 범위와 남은 한계

이번 변경은 [33개 제품 코드·테스트·안내 파일](ui-improvements/changed-files.txt)이다. QA 문서·증거는 별도다. 시작 상태 567개 파일은 로컬 `/tmp/colonova-ui-round2-20261002-191137/files/`에 보관했으며 `/tmp` 정리 뒤에는 남지 않을 수 있다. 기존 미커밋 작업을 취소하지 않았고 Electron 데스크톱 소스와 연결 프로젝트 코드는 수정하지 않았다.

- 실제 WMS 화면은 열린 뒤 센터 선택 조건이 주소에 붙는다. 현재 저장된 변경 주소와 정확히 일치하지 않아 직접 확인을 남길 수 없었다. 이유 안내를 검증했고, 확인 표시의 성공·크기별 독립성은 합성 화면에서 검증했다.
- 직접 확인은 사용자가 봤다는 표시이며 품질 통과 판정이 아니다. 로컬 저장소를 지우거나 다른 기기에서 열면 공유되지 않는다. 보수적으로 모든 확인을 다시 요구하므로 관련 없는 변경에도 재확인이 필요할 수 있다.
- 과거 기록에 요청 ID·사진이 없으면 요청별 결과나 전후 사진을 만들어 채우지 않는다. 실제 AI 편집→촬영→원격 제출 전체 흐름과 다중 프로젝트 전환의 네이티브 검증은 이번 단계에서 실행하지 않았다. 초안 간 늦은 실패·프로젝트별 상태 격리는 코드 회귀 검사로 검증했다.
- 즐겨찾기·검토 시나리오 저장·실행 단계와 홈의 전면 개편은 이번 범위 밖이다. 실제 제출·외부 메시지·복구·삭제·커밋·푸시는 하지 않았다.

다음 개선은 선택 조건이 붙는 화면을 저장된 변경과 연결하는 규칙을 먼저 정하는 것이다. 센터·탭·검색 조건을 같은 화면으로 묶을지 별도 결과로 둘지 명시해야 실제 WMS에서도 직접 확인을 사용할 수 있다. 이후 자주 확인하는 화면 모음과 반복 검토 시나리오를 확장할 수 있다.

## 0. 지키는 것

개선안은 아래 계약을 바꾸지 않는다. 바꿔야 하는 항목은 그 자리에 적었다.

- 셸은 세 자리다(2026-10-23). 연결 자리는 다시 세우지 않는다 — 연결은 쓰는 곳에서 생기고 보인다(2026-10-30).
- 사용자 말은 **보관 · 제출 · 반영됨**, AI 에게는 `보내기`. 문장은 `labels.ts` 의 `L` 에만.
- 으뜸 단추는 한 화면에 하나(`제출`). 포인트 색 바탕은 `보내기` 와 켜짐 상태에만.
- 크기 · 색은 `ui/tokens.css` · `next.css` 의 토큰. 읽는 글은 12px 아래로 내리지 않는다.
- 숨는 칸은 마운트를 지킨다(미리보기 입력 · 스크롤 · 핀, 쓰던 글).
- 프로토콜 버전은 올리지 않는다. 필요한 값은 선택 필드로 더한다.
- 결과 카드에 화면 사진 · 비교를 되살리지 않는다(2026-10-20 사용자 요청). 자동 재검사도 되살리지 않는다.

## 2. 목표 그림

**한 바퀴가 화면 한 장에서 끝난다 — 말한다 → 본다 → 찍는다 → 기획과 맞춘다 → 제출한다.**

원칙 여섯:

0. **화면이 가운데다.** 미리보기가 가장 넓은 자리를 쓰고, 대화 · 기획서 · 작업 기록은 오른쪽 칸 하나에 탭으로 선다(2026-10-31 사용자 요청).
   무엇을 열어도 화면 폭은 줄지 않는다.
1. **지금 하는 일은 한 곳에서 말한다.** AI 의 진행은 입력창 위 「작업 독」 하나가 말하고, 나머지 자리는 점 · 테두리 같은 신호만 낸다.
2. **상태 줄은 국면, 대화는 이야기, 미리보기는 실물.** 각자 한 가지만 말한다.
3. **답은 「바뀐 것」으로 끝난다.** 답 하나의 결과(바뀐 화면 · 같이 고친 기획서 · 되돌리기)를 한 띠로 묶는다.
4. **화면과 말은 양쪽에서 서로를 가리킨다.**
5. **기획 근거는 화면 곁에 선다.** 연결 자리 없이도 지금 화면의 기획서를 그 자리에서 읽고 보낸다.

### 2.1 넓은 창

```
┌ 상태 줄 ─ [대화 제목 ▾] ··························· (●) 제출 전 · 화면 3개 ▸   [제출]
├──────────────────── 미리보기 칸 (가장 넓게) ────────────────────┬──── 오른쪽 칸 420px ────┐
│ ← → ⟳  [▤ 회원 목록 ▾] 이 화면을 바꾼 말 ↗  [◎ 찍기] ··· [▭▯▮] ⋯ │ [대화|기획서 2|작업 기록] ▯ │
│                                                                  │ 보낸 말                  │
│   무대 — AI 가 고치는 동안 가장자리 빛만                             │ 답 본문                  │
│                                                                  │ ┌ 결과 띠 ─────────────┐ │
│                                                                  │ │ 바뀐 화면 · 회원 목록 ↗ │ │
│                                                                  │ │ 기획서 · 「…정책서」    │ │
│                                                                  │ │ 되돌리기 · ✓ 38초 · ⋯  │ │
│                                                                  │ └──────────────────────┘ │
│                                                                  │ ┌ 작업 독 ── 고치는 중 · │ │
│                                                                  │ │  할 일 2/5 · 12초 · 멈추기│
│                                                                  │ 입력창 [첨부][◎][모델] [↑] │
└──────────────────────────────────────────────────────────────────┴──────────────────────────┘
```

- 오른쪽 칸의 위쪽만 탭으로 바뀌고, 작업 독과 입력창은 어느 탭에서도 바닥에 남는다.
- `▯` 는 오른쪽 칸 접기 — 접으면 화면만 남고 칸 자리에 얇은 띠(대화 · 기획서 · 작업 기록 아이콘과 도는 표시)가 선다.

## 3. 개선안

항목마다 「무엇 · 왜(진단 번호) · 닿는 곳 · 크기」를 적는다. 크기는 S(하루 안) · M(며칠) · L(한 주 이상).

### A. 상태 줄 — 국면 하나와 제출

**S1. 여정을 「지금 국면 알 하나」로 접는다.** (D2 · M)
- 늘 서는 것: 대화 제목 · 지금 국면의 알(`제출 전 · 화면 3개` · `개발자 확인을 기다려요 · 2일째` · `반영을 기다려요` …) · `제출`.
- 세 점의 나머지 둘은 알을 누르면 여는 `이번 작업` 팝의 머리로 옮긴다 — 거기서 세 점을 크게 그린다.
- `받아오기 N` 은 알 안의 숫자 배지(`ui/Count`)로 붙인다. 누르면 `이번 작업` 의 `개발자 쪽 새 내용` 이 열린다.
- 프로젝트 이름은 상태 줄에서 걷는다 — 사이드바 전환기가 말한다. 사이드바가 접혔을 때만 제목 앞에 흐린 이름이 선다.
- 접힘 규칙이 「알 글자 → 배지」 두 단계로 줄어든다. 판정(`journey.ts`)은 그대로이고 그림만 바뀐다.
- 닿는 곳: `status/StatusLine.tsx` · `status/parts.tsx` · `status/WorkPopover.tsx` · `status-fixture`.

**S2. 도는 표시는 상태 줄에서 점 하나.** (D1 · S)
- `만드는 중 · 12초` 알약과 테두리 빛을 걷고, 알 왼쪽의 점이 포인트 색으로 숨 쉰다. 말과 시계는 작업 독(S4)이 맡는다.
- 다른 자리(기획서 · 홈)에 있을 때는 사이드바 `화면` 줄의 도는 표시가 지금처럼 말한다.

### B. 오른쪽 칸의 대화 — 이야기와 결과

**S3. 답의 꼬리를 「결과 띠」 한 판으로 묶는다.** (D4 · M)
- 화면을 바꾼 답의 끝에 띠 하나: 첫 줄 `바뀐 화면` 칩들(이름 · ↗ 열기, 셋을 넘으면 `외 N`), 둘째 줄 같이 고치기
  (`「회원가입 정책서」 초안도 같이 고쳤어요 · 보기 · 되돌리기`), 바닥 줄 `방금 한 것 되돌리기` · `추가 수정` · `✓ 38초` · 복사 · `⋯`.
- 고친 화면 카드(`ResultScreens`) · `PlanSyncLine` · 메타 줄을 띠의 칸으로 옮긴다. 화면을 바꾸지 않은 답은 지금처럼 메타 줄만 선다.
- 띠는 선 하나로 두르고 면을 깔지 않는다 — 베이지 면은 사용자 말풍선과 묻는 카드(`AI가 물어봐요`)에만 남긴다.
- `작업 과정 ▸` 은 본문 위가 아니라 띠의 `⋯` 옆 `과정 보기` 로 내린다. 답의 첫 줄이 곧 본문이 된다.
- 옛 기록의 확인 카드(`화면 확인`)는 띠 안의 얇은 한 줄로 그린다. 기록은 지우지 않는다.
- 닿는 곳: `chat/Thread.tsx` · `cards.tsx` · `ResultScreens.tsx` · `PlanSyncLine.tsx` · `chat.css` · `thread-fixture`.

**S4. 입력창 위를 「작업 독」 하나로.** (D1 · D3 · M)
- 입력창 바로 위 한 줄짜리 독. 한 번에 하나만 선다 — 차례는 ① AI 가 도는 중 ② 묻는 일 ③ 알림(힌트 · 길어진 대화) ④ 근거 띠.
- ① 도는 중: `화면 파일을 고치는 중 · ‘회원 목록’ · 할 일 2/5 · 12초` 와 `멈추기`. 누르면 할 일 · 보조 작업 목록이 위로 펼쳐진다
  (지금 `RunPlan` 의 팝). 대화 끝의 진행 줄(`RunLine`)은 걷는다 — 글이 흐를 때 접혀 자리를 내주던 까다로운 규칙도 함께 걷힌다.
- ④ 근거 띠(`PlanRefStrip`)는 기획서 칩으로 독의 오른쪽 끝에 접혀 선다(`기획서 1`). 도는 중에도 칩은 남는다.
- `맨 아래로` 는 독이 아니라 대화록 오른쪽 아래 떠 있는 둥근 단추로 옮긴다 — 줄을 차지하지 않는다.
- 판정은 순수 모듈 `lib/dock.ts`(새)로 뽑아 시험한다 — 무엇이 서는지 · 차례 · 몇 줄.
- 닿는 곳: `ChatColumn.tsx` · `RunLine.tsx` · `RunPlan.tsx` · `PlanRefStrip.tsx` · `lib/making.ts` · `lib/run-plan.ts`.

**S5. 빈 대화는 지금 화면에서 시작한다.** (D8 · S)
- 제목을 `‘회원 목록’에서 무엇을 바꿀까요?` 로 — 화면 이름을 모르면 `이 서비스에서 무엇을 바꿀까요?`.
- 아래에 홈의 시작점 칩(`home-starters.ts` 의 `startersOf`)을 같은 규칙으로 세운다. 칩은 입력창을 채우기만 하고 보내지 않는다.
- `수정할 곳 선택` 단추는 칩 줄의 첫 칸으로 합친다.
- 닿는 곳: `ChatColumn.tsx` 549 ~ 580행 · `labels.ts` `transcript` · `home-starters.ts`.

### C. 미리보기 칸 — 실물과 찍기

**S6. 막대를 「어디 · 무엇을 · 어떻게 보나」 순으로 다시 놓는다.** (D6 · M)
- 왼쪽: 뒤로 · 앞으로 · 새로 고침. 가운데: 화면 고르기(주소창). 그 바로 오른쪽: **`찍기`**(지금의 `수정할 곳 선택`) — 이 칸의
  가장 중요한 손이라 주소 곁으로 당긴다. 오른쪽: 기기 마디 · `⋯`. 작업 기록 단추는 막대에서 빠지고 오른쪽 칸의 탭이 된다(S10 · S15).
- 배율 알약은 100% 가 아닐 때만 `⋯` 단추 위의 숫자 배지로 접는다(지금은 막대에 따로 선다).
- 막대 높이 · 단추 크기(32 · 28px)는 그대로. 좁은 칸의 숨김 차례는 「작업 기록 글자 → ⌘L → 기기 마디를 한 단추로 → 앞으로」.
- 말 고침 제안: `수정할 곳 선택` → `찍기`(켜졌을 때 `찍는 중 2`). 사용 설명서의 「찍기」 · 「찍은 곳」과 같은 말이 된다.
  입력창의 같은 단추도 같은 말로 맞춘다. **결정 필요** — 라벨을 바꾸면 GUIDE 7절 · 단축키 시트 · 소개 페이지를 함께 고친다.

**S7. 찍은 곳의 글은 한 곳에 쓴다.** (D6 · M)
- 말풍선의 메모 칸을 걷고 `담기`(↵) 하나만 남긴다 — 담으면 초점이 입력창의 그 번호 칩으로 간다. 메모는 칩에만 쓴다.
- 대신 찍는 중에는 입력창이 포인트 색 테두리로 서고 자리 표시 글이 `찍은 곳 2 · 무엇을 바꿀지 한 줄 적어 주세요` 가 된다.
- `지금 보내기`(⌘↵)는 말풍선에 남긴다 — 한 곳만 빨리 고칠 때의 지름길.
- 위험: 말풍선에서 바로 메모하던 사용자의 손이 바뀐다. 베타 사용자 관찰 뒤 정한다. **결정 필요.**
- 닿는 곳: `preview/PinBubble.tsx` · `chat/Composer.tsx` · `GUIDE 7절`.

**S8. AI 가 고치는 동안 무대는 빛으로만 말한다.** (D1 · S)
- `LiveLayer` 의 글 줄(`AI가 지금 ‘회원 목록’ 화면을 고치는 중`)은 작업 독이 같은 말을 하므로 걷고, 무대 가장자리에 옅은 포인트 빛만 둔다.
- `‘회원 목록’ 화면으로 옮겼어요` 는 사용자가 놀랄 수 있는 일이라 무대에 몇 초 남긴다(되돌리는 길 `뒤로` 를 함께).
- 판정(`follow-edit.ts` 의 `pickLiveLine`)은 그대로다.

**S9. 지금 화면에서 그 말로 간다.** (D5 · M)
- 주소창 곁에, 이 대화에서 바뀐 화면을 볼 때만 `이 화면을 바꾼 말 ↗` 이 선다. 누르면 대화록이 그 답의 결과 띠로 굴러가고 띠가 한 번 빛난다.
  오른쪽 칸이 다른 탭이거나 접혀 있으면 대화 탭을 먼저 연다. 좁은 창은 대화 탭으로 옮긴 뒤 굴린다.
- 거꾸로 결과 띠의 화면 칩에 마우스를 올리면 주소창이 그 이름으로 잠깐 빛난다(옮기지는 않는다).
- 재료: 화면 칩은 이미 답마다 화면 경로를 안다(`latestResult` · `cycleScreens`). 화면 → 답의 거꾸로 표는 웹에서 대화록을 읽어 만든다 —
  선로는 바꾸지 않는다.

### D. 오른쪽 칸의 탭 — 대화 · 기획서 · 작업 기록

**S10. 오른쪽 칸의 위쪽을 세 탭으로 나눈다.** (D7 · D10 · L — S15 가 먼저)
- 오른쪽 칸(S15) 머리에 `대화 · 기획서 N · 작업 기록` 탭이 선다. 바뀌는 것은 칸의 위쪽뿐이고, 작업 독과 입력창은 어느 탭에서도 바닥에 남는다.
  미리보기 위에 겹쳐 서던 곁판 · 서랍이 없어지므로 무엇을 열어도 화면 폭이 줄지 않는다(2026-10-31 사용자 요청 「화면 중심」).
- **기획서 탭(새).** 지금 화면에 이어진 기획서(`plans-map.json` 의 연결 + 이 대화에서 근거로 보낸 문서)를 목록으로 보이고,
  하나를 고르면 이어진 절을 읽기 전용으로 보인다(기획서 자리의 `DocView` 를 칸 폭으로).
  - 손: `근거로 보내기`(바닥 입력창에 문서 칩으로 담는다) · `기획서에서 열기` · `끊기`. 같이 고친 초안이 있으면 맨 위에 `초안에서 바뀐 곳` 한 묶음.
  - 이어진 문서가 없으면 `이 화면에 이어진 기획서가 없어요 · 기획서 고르기` — 지금 곁줄의 고르기 손과 같은 길(`draft.syncPick` 의 연결 쓰기)을 쓴다.
  - 탭 이름 곁에 이어진 문서 수가 선다(`기획서 2`). 0 이면 숫자가 없다. 미리보기가 다른 화면으로 옮기면 목록도 따라 바뀐다.
  - 2026-10-30 결정과 맞다 — 연결 자리를 세우지 않고, 연결은 화면 곁에서 보고 끊는다. AI 는 연결을 만들지 않는다.
- **작업 기록 탭.** 지금 서랍의 내용(날 묶음 · 되돌리기 확인 · 초점 규칙)을 탭 안으로 옮긴다. `이번 작업` 팝의 `작업 기록 열기` 와
  결과 띠의 `방금 한 것 되돌리기` 는 이 탭을 연다. 좁은 창에서는 막대의 `⋯` 가 지금의 화면 덮는 시트로 연다(S12).
- **대화 탭이 아닐 때 온 소식.** AI 의 새 답 · 묻는 카드가 오면 `대화` 탭 곁에 점이 서고, 묻는 카드는 작업 독 ② 칸에도 선다 — 대화를 놓치지 않는다.
- 재료: 연결은 `map.read`, 문서는 기존 읽기 요청으로 된다. 절 단위 연결이 없으면 문서 첫머리부터 보인다. 선로 추가는 없을 것으로 본다 — 구현 전에 확인.
- 닿는 곳: `chat/ChatColumn.tsx`(탭 머리 · 위쪽 바꾸기) · `preview/HistoryDrawer.tsx`(서랍 → 탭 몸) · `preview/PreviewBar.tsx`(작업 기록 단추 걷기) ·
  새 `chat/PlanTab.tsx` · `plans/view/*` 재사용 · `lib/nav.ts`(오른쪽 칸 탭 상태) · `labels.ts`.

### E. 틀 · 좁은 창 · 손

**S15. 화면을 가운데로, 대화는 오른쪽으로.** (2026-10-31 사용자 요청 「채팅창 오른쪽으로 이동하자 화면 탭 화면 중심으로」 · M)
- 넓은 창의 차례를 `사이드바 | 미리보기 | 오른쪽 칸` 으로 바꾼다. 미리보기가 남은 폭을 다 쓰고, 오른쪽 칸은 기본 420px 이다.
- 오른쪽 칸 머리 끝의 `오른쪽 칸 접기` 로 화면만 볼 수 있다. 접으면 칸 자리에 얇은 띠(세 탭의 아이콘 · 도는 표시 · 새 소식 점)가 남고,
  누르면 그 탭으로 다시 펼친다. 단축키는 S11 의 ⌘\\ 와 함께 정한다.
- 상태 줄은 그대로 작업 자리 전체 폭에 걸친다. 대화 제목은 왼쪽, 국면 알과 `제출` 은 오른쪽 — 오른쪽 칸 바로 위라 대화와 제출이 가깝다.
- 2026-10-23 화면 전면 재설계의 「대화와 화면이 나란히」는 그대로다 — 좌우만 바뀐다. 숨는 칸의 마운트 규칙도 그대로다.
- 닿는 곳: `Workspace.tsx`(칸 차례 · 경계 위치) · `components/shell/Splitter`(끄는 방향이 거꾸로 — 오른쪽 칸 폭을 잰다) · `shell.css` ·
  GUIDE 2절(경계 끌기 문단 · 「대화는 320~640px」) · web README 「틀」.

**S11. 화면과 오른쪽 칸의 폭을 세 가지로 빨리 바꾼다.** (S)
- 경계 끌기는 그대로 두고(오른쪽 칸 320~640px), 경계를 두 번 누르면 「기본 420 → 화면 넓게(칸 320px) → 칸 넓게(640px) → 기본」으로 돈다.
  단축키 ⌘\\ 를 더한다.
- 찍기를 켜면 칸이 640px 일 때만 한 번 「화면 넓게」를 제안하는 토스트를 띄운다(`화면을 넓게 볼까요? · 넓게`). 사용자가 고른 폭은 기억한다.

**S12. 좁은 창은 화면 탭이 먼저, 화면 탭에도 접힌 입력창.** (D9 · M)
- 탭 차례를 `화면 · <이름> | 대화 | 기획서` 로 바꾼다 — 화면이 첫 탭이다(S15 와 같은 뜻). 작업 기록은 막대의 `⋯` 에서 연다.
- 화면 탭 바닥에 한 줄짜리 접힌 입력창이 선다 — 누르면 위로 펼쳐지는 시트다. 같은 `Composer` 를 쓰고 쓰던 글은 대화 탭과 하나다(같은 `draftKey`).
- 보내면 시트가 접히고 작업 독의 한 줄이 시트 위에 선다. 답을 읽으려면 대화 탭으로 간다.
- 찍기를 눌러도 입력창이 사라지지 않는다. 탭의 `②` 배지는 그대로다.
- 위험: 같은 입력창을 두 자리에 마운트하지 않는다 — 하나를 옮겨 그리는 방식으로 마운트를 지킨다(셸 규칙).

**S13. 칸 사이를 키보드로 건넌다.** (S)
- F6(⇧F6 거꾸로)이 상태 줄 → 미리보기 막대 → 무대 → 오른쪽 칸 탭 → 칸의 몸(대화록 · 기획서 · 작업 기록) → 입력창을 돈다. 단축키 시트(⌘/)의 `앱` 묶음에 적는다.

## 5. 완료 기준

견본(`dev/*-fixture`)과 실제 앱(`pnpm dev:desktop`)에서 각각 본다.

- 넓은 창에서 미리보기가 가장 넓은 칸이고, 오른쪽 칸의 어느 탭을 열어도 미리보기 폭이 바뀌지 않는다.
- AI 가 도는 동안 진행의 말(단계 · 시계 · 할 일)이 화면 자리 전체에서 **한 곳**에만 글로 선다.
- 상태 줄이 1024px 창에서 접힘 없이 제목 · 국면 알 · `제출` 을 다 보인다. 900px 미만에서도 알과 `제출` 이 남는다.
- 화면을 바꾼 답의 꼬리가 결과 띠 하나다. 같이 고치기 · 되돌리기 · 시간 · 복사가 그 안에 있다.
- 입력창 위에 서는 줄이 어떤 상태 조합에서도 한 줄을 넘지 않는다(`lib/dock.ts` 시험).
- 이어진 기획서가 있는 화면에서 오른쪽 칸의 기획서 탭이 그 문서를 열고, `근거로 보내기` 로 바닥 입력창에 문서 칩이 담긴다. Confluence 쓰기는 일어나지 않는다.
- 기획서 · 작업 기록 탭을 보는 동안 새 답이나 묻는 카드가 오면 `대화` 탭 곁에 점이 선다.
- 지금 화면에서 `이 화면을 바꾼 말` 로 그 답에 닿는다.
- 좁은 창의 화면 탭에서 찍고 → 쓰고 → 보내기가 탭을 건너지 않고 끝난다.
- `pnpm test`(`next-labels` · `vocab-sweep` 포함) · `pnpm typecheck` 가 통과하고, GUIDE · web README 가 같은 변경에서 바뀐다.

## 6. 결정이 필요한 것

1. 상태 줄의 세 점을 국면 알 하나로 접을지(S1). 세 점이 「앞으로 무엇이 오나」를 늘 보여 주는 학습 효과를 버리는가.
2. `수정할 곳 선택` → `찍기` 로 라벨을 바꿀지(S6).
3. 말풍선의 메모 칸을 걷을지(S7).
4. 오른쪽 칸의 기획서 탭(S10)을 3단계로 둘지, 기획 올인원 목표에 맞춰 S15 와 함께 먼저 할지.
5. 대화 끝의 진행 줄(`RunLine`)을 걷을지(S4) — 2026-10-06 UX 점검에서 세운 줄이다.
6. 오른쪽 칸을 접었을 때 얇은 띠를 남길지, 완전히 숨기고 상태 줄의 단추로만 다시 열지(S15).

화면을 가운데 두고 대화를 오른쪽으로 옮기는 방향(S15)은 2026-10-31 사용자 요청으로 정했다 — 예상 화면도 이 배치다.

## 7. 위험

- **한 번에 많이 바꾸면 익숙한 손이 깨진다.** 베타 사용자에게는 단계마다 무엇이 옮겼는지 `방금 있던 일` 이나 토스트로 한 번 알린다.
- **좌우가 바뀌면 손이 헤맨다.** 대화가 왼쪽이던 손(입력창 · 경계 끌기 · 좁은 창의 첫 탭)이 바뀐다. 처음 한 번 `대화가 오른쪽으로 옮겼어요`
  토스트를 띄우고, 저장해 둔 대화 폭은 오른쪽 칸 폭으로 옮겨 읽는다.
- **기획서 탭은 기획서 자리와 겹친다.** 읽기 전용 · 이어진 절만으로 좁히고, 고치기는 기획서 자리(초안)에서만 한다.
- **탭이 대화를 가린다.** 기획서 · 작업 기록을 보는 동안 흐르는 답이 안 보인다 — 작업 독은 늘 바닥에 남고, 새 소식은 탭의 점이 말한다.
- **작업 독은 여러 판정(`making` · `run-plan` · `follow-edit` · 근거 띠)을 한데 모은다.** 순수 모듈로 차례를 시험하지 않으면 다시 흩어진다.
- **결과 띠로 옮길 때 옛 대화록의 카드 종류를 빠뜨리기 쉽다.** `thread-fixture` 의 모든 사례를 띠 전후로 찍어 견준다(`scripts/web-fixture-shot.mjs`).

# UI 전면 개선 — 고친 것과 남긴 것 (2026-11-12)

2026-11-12 사용자 요청 — «조사에서 나온 것을 판단해서 고칠 것은 모두 고쳐라.»
조사는 같은 날의 [UI 전면 개선 조사](ui-audit-2026-11-12.md)(요약)와
[발견 224건](ui-audit-2026-11-12-findings.md)(`U-…` 번호)이다. 이 문서는 그 뒤의 **고침의 기록**이다 —
조사 문서가 «무엇이 문제인가»를 말했다면 이 문서는 «무엇을 고쳤고 무엇을 남겼는가»를 말한다.

## 한 일과 방법

- 발견 224건을 감독자가 정한 번호 목록으로 작업자들(0단계 W0 · 영역 PLANS-A · PLANS-B · CHAT · SHELL-A ·
  SHELL-B · LEGACY · LEGACY2 · COPY · DESKTOP)와 꼬리(TAIL) · 토큰(TOKENS) 단계에 나눠 얹었다.
- 얹는 차례: 0단계(공통 조각) + 영역 + 검토 반영(S1) → 문장 · 남은 셋(S2) → 토큰(S3) → 문서(S4) → 데스크톱(맨 끝).
- 검토자 여섯이 모든 패치를 읽고 실제 결함을 찾았다(막음 6건 포함 — 코멘트 결과 오인 · 편집 잠금 우회 · 미확정 재전송 ·
  팝 안 Esc · 단추 초기화 특이도 등). 검토 반영(`-R` 단계)으로 고친 뒤 얹었다 — 찾기만 하고 넘긴 것이 아니다.
- 판정 전체는 아래 [번호별 표](#번호별-판정-224건)다 — 고침 202 · 안 고침 14 · 재현 안 됨 3 · 기타(부분 · 넘김 · 범위 밖) 3 ·
  토큰 단계 2.

## 고친 것 — 묶음별

### 틀린 것을 믿게 하는 것(상태 · 실패)

- **실패한 작업을 성공으로 말하던 것** — 작업 과정 머리가 실패 도구를 성공에 섞어 세지 않는다
  (`일부가 실패했어요` · `실패 있음`, U-037). 끝나지 않은 할 일은 `할 일 k/n · m개 남아요` 로 세고, 모두 끝났을 때만
  `할 일 N개를 마쳤어요` (U-038). 도구의 긴 입력 · 결과는 `전체 보기` 로 펼치고 실패의 끝은 꼬리가 먼저 보인다(U-041).
- **발행 창을 그냥 닫으면 실패로 표시되던 것** — `됨 · 그만둠 · 실패` 를 가르고, 닫기는 무표시 복귀다(U-029).
- **결과를 모를 때 새 번호로 다시 보내던 것** — 코멘트 쓰기는 결과 모름에 `다시 확인` 으로 같은 명령을 같은
  commandId 로 다시 묻는다. 적용 확정만 입력을 비우고 목록 비교는 성공 증거로 쓰지 않는다(U-076).
- **늦게 온 답이 다른 범위를 덮던 것** — 공통 `latest-request` 가 요청 순서와 대상을 함께 본다(U-013 · U-047 ·
  U-113 · U-114 · U-223 등). 기획 대화의 진행 자료는 문서 · 대화 · API 범위에 귀속된다.
- **첨부 읽기가 다른 대화로 넘어가던 것** — 읽기가 끝나면 시작한 대화에만 붙고, 읽는 중에는 보내기가 잠기고,
  실패 파일은 이름과 다시 붙이기가 남는다(U-045 · U-046). 같은 대화의 근거 재조회는 읽어 둔 칩을 지키고
  읽는 중 줄을 다시 세우지 않는다(CHAT-R).
- **입력 재료가 실패 · 이동에서 사라지던 것** — 보내기 실패 뒤에는 말 · 첨부 · 고른 글 · 근거가 남고, 다른 문서로
  이동하면 새로 시작한다(U-030 · U-109 · U-112 · U-116).
- **직접 고치는 중의 발행 · 판 · 견주기** — 편집 칸을 연 동안 그 밖의 변경 손이 잠기고, 편집 대상이 바깥 고침으로
  사라지거나 종류가 바뀌면 쓰던 글은 복사할 수 있게 남는다 — 초안을 닫았다 열어도 남고 `닫기` 로 걷는다(U-098 · U-095 · U-096 · U-097).

### 뿌리 — 두 벌의 스타일 · 선언 없는 변수 · 특이도

- **단추 초기화는 둘로 나뉘었다** — 글자(`font` · `color`)는 `.nx button`(0-1-1), 상자(`background` · `border` ·
  `padding` · `cursor` · `text-align`)는 `:where(.nx) button`(0-0-1). 앱과 견본의 CSS 적재 순서가 다르므로 부품이
  단추의 글자 · 색을 정할 때는 `.nx .클래스`(0-2-0)로 쓴다(U-185 · NOTE-1). 옛 `styles.css` 의 요소 선택자와 같은
  특이도로 겨루는 새 규칙은 쓰지 않는다.
- **선언 없는 변수** — 카드 · 선택 · 호버가 `--card` · `--nx-selected` · `--nx-hover` 로 정리됐고, 미선언 참조는
  시험(`next-css-variables.test.ts`)이 잡는다(U-092 · U-163 · U-166 · U-171).
- **토큰 단계(TOKENS)** — 같은 값 치환(591선언)과 반 픽셀 · 굵기 정리가 끝났다. 보이는 모양은 바꾸지 않는 것이
  원칙 — 그물 측정에서 strict 차이 0, 실제 계산값 차이는 이니셜 11.5 → 12px 와 기획 대화 줄의 위아래 여백 4px
  (감독자가 합치며 고침)뿐이다. 미치환 22선언과 굵기 650 유지는 보고서에 이유가 있다.

## 검증

- **빌드 · 시험** — 고치기 전 전체 시험 3,046 통과 → 합친 뒤 **3,135 통과 · 실패 0 · 건너뜀 5**(2차 수리까지 얹은 마지막 사본).
  브라우저 시험 넷은 마지막 사본에서 **24개 통과 · 실패 0**.
  브라우저를 띄우는 시험 넷(`next-chat-browser` · `next-chat-review-browser` · `next-plans-a-regression` ·
  `next-doc-comments-resolve`)은 `packages/web/test/cold/` 로 옮겨 기본 수에서 빼고 별도로 돌린다(TAIL).
  이 사본에서는 `pnpm` 을 돌리지 않고 `./build.sh` · `./test.sh` 로 확인했다.
- **그물(`net/`)** — 견본 393사례 × 밝게 · 어둡게 = 786회를 전후로 잰다. 누름 면 24px 아래 172 → 136곳,
  글자 12px 아래 152 → 148곳, 줄어든 누름 면은 없다. 수치는 결정적이고 PNG 바이트 일치는 보장하지 않는다(레포 규칙).
- **그림** — 견본 전 · 후를 작업자가 그리고 눈으로 본 것은 각 보고서(`reports/`)의 `shots/` 에 남는다.
- **실제 앱(개발 실행)** — 조각을 얹을 때마다 띄워 둔 Electron 을 찍어 화면이 정상으로 서는지 봤다(S1 · S3 뒤). 원본의 웹 · 데몬 파일은
  시험을 통과한 사본과 바이트까지 같다(924 파일 대조). 데스크톱 조각을 얹은 뒤 앱이 다시 켜졌고, 미리보기 안을 누른 뒤의 `⌘K` 가
  앱의 찾기 창을 열고 `Esc` 가 닫는 것을 실제 앱에서 눌러 확인했다(U-180 의 키 넘김 길 — 한글 조합 중의 키는 눌러 보지 못했다).
  데몬 쪽 고침(본문 검색의 HTML 기호 풀기 — U-063)은 개발 실행을 다시 띄워야 실린다.
- **리뷰** — 여섯 검토자(REVIEW-*.md)가 패치를 읽고 막음 6건 · 고쳐야 함 · 사소를 찾았고, `-R` 단계에서
  고친 뒤에야 합쳤다. 수리 패치 가운데 위험이 큰 셋(PLANS-A-R · PLANS-B-R · TAIL)은 **한 번 더** 다른 검토자에게 읽혔다 — 코멘트 결과 확인(같은 명령 번호로 다시 묻기 · PLANS-B-R · TAIL)은
  막음 없음, 초안 편집 잠금 · 복구(PLANS-A-R)는 막음 1건 · 고쳐야 함 2건(종류 전환에서 쓰던 글 유실 · 마지막 블록 뒤 `직접 쓰기` 사라짐 · 복구 글이 `Esc` 한 번에 소멸)이
  나와 한 번 더 고쳐 얹었다(PLANS-A-R2). 그 밖의 수리 패치(CHAT-R · SHELL-A-R · SHELL-B-R · LEGACY-R · COPY-R)와 PLANS-A-R2 자신은 다른 검토자의 2차 검토를 받지 않았다 — 시험과 감독자의 대조만 거쳤다
  (PLANS-A-R2 는 견본과 Chromium 시험 · 감독자가 그림과 코드를 읽음 — 복구 카드의 `복사` · `닫기` 높이와 간격은 감독자가 재서 맞췄다. 실제 앱에서는 보지 못했다).

## 확인 못 한 것

- **실제 Electron** — 미리보기 키 넘김의 실제 조합 취소 Esc(`isComposing`), 되돌린 미리보기 틀(U-019 · U-020 ·
  U-021), 얹지 않은 창 머리(U-173)는 단위 시험 밖이다.
- **실제 Confluence 쓰기 · 실제 GitHub 제출** — 코멘트 · 발행 · 문서 관리 · 제출의 실제 서비스 확인은 아니다.
- **실제 한글 입력기** — 조합 취소 Esc 가 `isComposing: true` 로 오는지는 문구(문서 · 코드)가 근거다.
- **화면 낭독기** — 접근 이름 · 초점 · 읽기 순서는 코드와 Chromium 의 접근 트리로만 확인했다.
- **Windows** — 데스크톱의 트레이 · 종료 · 키 수정자는 코드와 시험으로만 확인했다.
- **브라우저 시험 넷** — `cold/` 로 옮겼고, 기본 `test.sh` 의 수에는 들지 않는다. 견본 서버 · Chromium 을 띄운다.

# UI/UX 해체 검토와 개선

2026-11-12 사용자 요청. 전면 재설계를 허용한 범위에서 실제 작업을 방해하는 문제를 우선 수정했다. Confluence 원본, 초안 보관, 사람의 발행, 기획서·화면 두 자리의 제품 계약은 유지한다.

## 범위와 검토 방식

Herdr의 GLM-5.3은 기획서, GLM-5.3-Flash는 공통 셸·설정, SWE-2는 화면 입력창을 맡았다. 감독자는 결과를 대조하고 문서 읽기·검색·목록을 수정했다. 네트워크 DNS 오류로 세 작업자가 중단된 것을 재개 시 확인했고, 기존 변경을 보존해 이어갔다. Flash의 일시적 SWE-2 자동 대체와 GLM 복귀를 실제 실행 표시로 확인했다.

| 관점 | 읽고 확인한 범위 | 한계 |
| --- | --- | --- |
| 접근성 | Composer·PlanChat·InlineConfirm·문서 서랍·CommentComposer·Switch, 키보드 닫기와 초점 | 화면 낭독기 전체 여정은 미실행 |
| 배치 | 기획서 문서/대화, 문서 상단, 설정 테마, 좁은 화면 입력창 | 모든 운영 데이터 길이 조합을 검사한 것은 아님 |
| 문구 | labels.ts의 오류·읽기·삭제·근거 절 안내 | 기존 전체 문구를 새로 쓰지는 않음 |
| 글자 | 본문/보조 글자 토큰과 폼 안내, 320·800·1440px 견본 | 모든 운영체제의 글꼴 렌더링은 미검증 |
| 색 | 6개 팔레트의 상태 배지·설정 선택 글자 합성 대비 | 전체 화면의 모든 색 조합에 대한 인증은 아님 |
| UI 동작 | 시트 상태 보존, 서랍, 팝, 스위치 클릭 영역, 호버 | 실제 터치 장치 검증은 미실행 |

기준 문서는 AGENTS.md, GUIDE.md, DEVELOPERS.md, FEATURES.md와 next/README.md다. `better-interface`와 여섯 하위 관점의 기준으로 검토했다. 실제 앱은 `pnpm dev:desktop`으로 열린 Electron이며, 실패·파괴 동작은 가짜 데몬을 쓰는 견본에서 검증한다.

## 채택한 개선

| 우선순위 | 문제와 근거 | 반영 |
| --- | --- | --- |
| HIGH | 포털 대상 교체가 입력창을 다시 마운트한다. `chat/ChatColumn.tsx`, `lib/composer-sheet.ts` | 하나의 포털 대상 DOM 상자를 이동해 글·첨부 상태 유지 |
| HIGH | 시트 접근성이 단축키 창 상태에 묶여 있고 닫기 손이 없다. `preview/PreviewColumn.tsx`, `chat/Composer.tsx` | 실제 열림 상태 공유, 접기 단추·Esc·초점 복귀 |
| HIGH | 기획 대화 머리의 삭제가 확인 없이 실행된다. `plans/draft/PlanChat.tsx` | 확인판, 취소 기본 초점, 진행 잠금, 실패 내용 유지 |
| HIGH | 연결 읽기 실패를 빈 목록으로 바꿨다. `plans/PlanDocView.tsx` | 두 출처의 로딩·실패·성공 분리, 부분 성공 유지, 재시도 |
| HIGH | 새 문서 초안에 `slice(0, 5)`가 있어 여섯 번째부터 숨긴다. `plans/PlansList.tsx` | 전체 초안 표시 |
| HIGH | 일부 팔레트의 작은 상태 글자가 대비 4.5:1에 못 미쳤다. `ui/ui.css`, `settings/settings.css` | 글자에 잉크색 혼합. 계산 최솟값: 선택 설정 4.64, 새 버전 4.89, 포인트 배지 4.62, 초록 4.98, 빨강 4.83 |
| MEDIUM | 인라인 편집이 다른 곳을 누르면 자동 저장되어 취소 의도가 불분명하다. `plans/draft/DraftEditor.tsx` | 적용·취소 단추, 명시 적용만 저장, 단축키 안내의 aria-hidden 제거 |
| MEDIUM | 근거 절을 이름으로 직접 입력한다. `plans/draft/PlanChat.tsx`, `thread-model.ts` | 실제 절 체크목록, 전체 문서 선택, 읽기 재시도, 범위가 바뀐 뒤 늦은 답 폐기 |
| MEDIUM | 문서 관리 메뉴 중복, 긴 본문 뒤의 부가 기능. `PlansHeader.tsx`, `PlanDocView.tsx` | 관리 메뉴 하나, 코멘트·화면 서랍 상단 배치, 서랍 초점 이동과 Esc |
| MEDIUM | 본문 검색 결과를 눌러도 문서 맨 위만 보인다. `PlansWorkspace.tsx`, `PlanDocView.tsx` | 첫 일치 글로 이동·표시, 문서 새로 읽기 때 반복 이동 방지 |
| MEDIUM | 기획 대화 목록 읽기 실패가 사라지고 프로젝트 이전 응답이 섞일 수 있다. `PlansWorkspace.tsx`, `PlansSidebar.tsx` | 오류·재시도, 요청 번호와 프로젝트/API 확인, 문서 없는 대화 안내 |
| MEDIUM | 실패 코멘트 알림·작은 스위치 과녁·터치 호버 마스크. `comments/*`, `settings.css`, `sidebar.css`, `plans.css` | 오류 알림 역할, 클릭 영역 확장, 호버 가능 장치에서만 마스크를 적용하는 CSS 조건 |

경로는 `packages/web/src/next/` 기준이다. 색 수치는 팔레트 선언값과 반투명 바탕을 합성한 계산값이다. 터치 호버는 소스상 위험을 완화한 것으로 실제 장치에서 재현했다고 주장하지 않는다.

## 검증

- `pnpm typecheck`: 전체 패키지 통과.
- `pnpm test`: 빌드 포함, 3,001개 통과·실패 0개·건너뜀 5개.
- 기획서 견본: 화면 연결 부분 실패에서 성공 목록 유지, 재시도 복구, 새 초안 8개, 기획 대화 목록 실패 복구, 본문 검색 일치 위치 표시 통과.
- 배치 견본: 320·800·1440px에서 문서 로딩 완료 후 주요 버튼의 가로 넘침 없음.
- 실제 Electron: 문서 상단과 연결 서랍, 테마 카드, 좁은 화면의 탭 이동·입력 보존·Esc 닫기와 초점 복귀 확인.
- 기획서 편집 견본: 삭제 확인의 취소 기본 초점·취소 후 목록 유지, 실제 절 체크 후 근거 담기, 인라인 취소 시 저장하지 않고 기존 글 유지 확인.
- 실제 Electron 추가 확인: 접기 단추를 눌러도 접힌 한 줄로 초점이 돌아오며, 검증용 입력은 비웠다.
- `pnpm build`: 전체 패키지 통과. 기존 큰 번들 안내는 남는다.
- `node packages/web/test/cold/plans-ux.cjs`: 가짜 데몬을 쓰는 10개 시나리오 통과. 개발 웹 서버 기본 주소는 29173이다.
- `FIXTURE_URL=http://127.0.0.1:29173/dev/composer-sheet-fixture.html node packages/web/test/cold/composer-sheet.cjs`: 34/34 통과. 탭·접기·크기 전환 뒤 입력/첨부 DOM 동일성, 내용 보존, 초점, 시트 접근성 속성을 검사했다.
- 마지막 보완 뒤 웹 빌드를 다시 수행하고 `node --test packages/web/test/*.test.ts` 1,027개 통과·실패 0개를 확인했다.
- 변경 UI 파일 Biome 검사와 `git diff --check` 통과.
- 독립 검토자가 보고서만 읽고 검증 증거 누락과 낭독 표현을 지적했다. 확인한 편집 시나리오를 추가하고, 화면 낭독기 실행과 ARIA 코드 변경을 구분했다.

## 채택하지 않은 후보와 경계

- 테마 이름이 붙어 보인다는 초기 관측은 865px/100% 실제 앱에서 재현되지 않아 바꾸지 않았다.
- 발행 확인의 ‘남은 AI 고침’ 수를 현재 대화에서만 전달하는 변경은 철회했다. 다른 발행 진입점과 일관되지 않기 때문이다. 문서 전체의 수를 지원하려면 발행 미리보기 계약에서 집계해야 한다. 기존 블록의 남은 고침 UI는 유지한다.
- 검색으로 연 접힘 영역은 읽을 수 있도록 펼친 채 둔다. 검색 해제 때 자동으로 다시 접지 않는다.
- 실제 Confluence 발행·문서 삭제·화면 AI 실행·외부 제출은 이 검토에서 수행하지 않았다. Windows·설치 패키지 검증, 모든 초기 설치 상태와 모든 원격 오류 조합도 포함하지 않는다.

판정: 위 범위에서 확인한 결함을 수정했으며, 전체 제품의 모든 환경에 결함이 없다는 뜻은 아니다. 사용자 설명은 GUIDE, 지원 기능은 FEATURES, 상태 처리 계약은 DEVELOPERS가 계속 정본이다.

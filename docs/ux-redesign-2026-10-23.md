# 화면 전면 재설계 — 현관 하나에 작업실 둘

2026-10-23 · 사용자 요청 「전체 ui ux 처음부터 재설계해도 되니까 고민 많이 해라, 사용성 관점에서 고민 많이 하자」.
같은 날 앞선 요청은 「모든 ui 를 몇 가지 경우로 나누어 보고, 그 작은 요소들을 각각 개선」 이다.
이 문서는 둘을 함께 받는다. 3절이 구조를 다시 짜고, 4절이 경우마다 작은 요소를 고친다.

정본은 [최종 구현 계획](confluence-sync-plan-2026-10-18.md)이다. 이 문서가 고치는 정본 문장은 7절에 줄 번호와 함께 적는다.

## 0. 결정 요약

- 앱의 자리는 셋이다 — **홈 · 기획서 · 화면**. 사이드바의 세 줄이 곧 세 자리다.
- **기획서 작업실은 Confluence 처럼** 선다. 사이드바가 문서 트리가 되고 본문은 문서 한 장이다. 화면 대화 칸과 제출 여정은 이 자리에 없다.
- **화면 작업실은 Claude 처럼** 선다. 지금의 대화 + 미리보기 + 상태 줄 + `제출` 을 지키고 다듬는다.
- **홈은 현관이다.** 기다리는 일이 맨 위, 그 아래 `기획서` · `화면` 두 시작 카드가 같은 무게로 선다.
- **두 작업실은 정해진 길로만 잇는다** — `화면에서 확인`(근거 보내기) · 근거 칩 · ⌘K.
- **시각 체계를 하나로 모은다** — 정보 글자 12px 이상, 읽는 글 15px, 으뜸 단추는 한 화면에 하나, 초점 고리 하나.

## 1. 누가 무엇을 하려고 여는가

쓰는 사람은 개발자가 아니다 — 기획자 · 디자이너 · 운영. 기획의 정본은 Confluence 다(SSOT 216쪽 — 정책서 87 · 기능설계서 73).

| 일 | 누가 · 얼마나 | 지금 어디서 |
| --- | --- | --- |
| 기획서를 찾아 읽는다 | 기획자 · 매일 | 오른쪽 칸의 목록 → 문서 |
| 기획서를 AI 와 고치고 발행한다 | 기획자 · 매일 | 문서 → `고치기` → 초안 + 기획 대화 |
| 기획을 실제 화면으로 확인한다 | 기획자 · 디자이너 · 자주 | 근거 보내기 → 화면 대화 + 미리보기 |
| 화면을 말로 고친다 | 디자이너 · 운영 · 기획자 · 매일 | 홈 입력창 · 대화 + 미리보기 |
| 개발자에게 넘기고 따라간다 | 모두 · 가끔 | 상태 줄의 여정 · `제출` · 이번 작업 |
| 무엇이 나를 기다리는지 본다 | 모두 · 하루의 시작 | 홈 받은 편지함(페이지 맨 아래) |

핵심 고리는 둘이다. **문서 고리**(찾기 → 읽기 → 고치기 → 채택 → 발행)와 **화면 고리**(말하기 → 보기 → 찍기 → 제출)다.
기획자는 두 고리를 하루에도 여러 번 오간다. 디자이너 · 운영은 주로 화면 고리에 산다.

## 2. 지금 구조에서 막히는 곳

틀은 「왼쪽 화면 대화 + 오른쪽 결과물」 하나다(GUIDE 「알아 둘 말」 — Claude Desktop 배치). 기획서는 2026-10-18 에
그 오른쪽 칸의 두 번째 얼굴로 들어왔다. 아래는 실제 셸(합성 Confluence · 1440×900)과 견본에서 본 것이다.

- **M1 잘못된 AI 에게 말하기 쉽다.** 문서를 읽는 동안 왼쪽 대화 칸의 입력창(`만들거나 고치고 싶은 것을 말해 주세요`)이
  보인다. 그 입력창은 화면 AI 다. 「이 정책서의 부분 취소 조건을 바꿔 줘」 를 치면 문서가 아니라 화면 코드가 고쳐진다.
  기획 대화는 `고치기` 를 누른 뒤에야 나온다. 정본 §6 「현재 AI가 문서를 제안하는지 코드를 고치는지 알아야 한다」 를
  초안 밖에서는 아직 어긴다(2026-10-23 기획자 화면 손질 F3 은 초안 안만 고쳤다).
- **M2 문서를 열면 목록이 사라진다.** 목록과 문서가 같은 칸을 번갈아 쓴다. 문서 사이를 오가려면 매번 `Esc` 로
  목록에 돌아가야 한다. 칸 폭도 776px(1440 창 · 대화 400px)이라 문서가 카드 안의 카드로 좁게 선다.
- **M3 상태 줄이 엉뚱한 일을 말한다.** 문서를 읽는 중에도 위 줄에 화면 작업의 여정(`제출 전 — 개발자 확인 — 개발자
  반영`)과 `제출` 이 선다. 초안을 고칠 때만 접힌다(D13). 기획서 칸의 길 표시는 `← 미리보기 › 기획서 › 문서` 로 시작한다 —
  기획서의 부모가 미리보기가 아니다.
- **M4 대화 칸의 빈 화면이 맥락을 놓친다.** 기획서를 연 채로 대화 칸이 「무엇을 만들까요?」 와 `수정할 곳 선택` 을 크게 보인다.
- **M5 홈의 순서가 거꾸로다.** 화면 입력창 · 시작점 · 기획서 묶음 · 세 걸음이 먼저 서고, 내 손이 필요한 일은 맨 아래다.
  머리의 `현재 프로젝트 · 화면 열기` 는 사이드바의 전환기와 같은 말을 한 번 더 한다.
- **M6 찾기(⌘K)가 문서를 모른다.** 대화 · 프로젝트만 찾는다. 기획 올인원에서 가장 많이 찾는 것은 문서다.
- **M7 글자가 작고 크기가 흩어졌다.** 셸 CSS 의 글자 크기가 39가지다(12 · 12.5 · 13 · 13.5 … 11 · 11.5 가 30곳).
  간격 값 200가지 · 반경 39가지 · 그림자 67가지. 비개발자가 읽는 메타 줄 · 칩 · 안내가 11.5–12.5px 에 몰려 있다.
- **M8 으뜸 단추의 색이 셋이다.** 검정(`초안 이어 쓰기` · `제출` · `업데이트`), 포인트 색(보내기 · 켜기), 옅은 베이지(꺼진 `제출`).
  꺼진 `제출` 은 누를 수 없는데 커다란 덩어리로 선다.

## 3. 새 구조 — 현관 하나에 작업실 둘

### 3.1 세 자리

| 자리 | 하는 일 | 본문 | 사이드바 목록 | 머리 줄 |
| --- | --- | --- | --- | --- |
| 홈 | 기다리는 일 · 시작 | 홈 한 장 | 화면 대화 | 없음(홈의 제목) |
| 기획서 | 문서 고리 | 문서 한 장(초안이면 문서 + 기획 대화) | 문서 트리 | 길 표시 + 문서 단추 |
| 화면 | 화면 고리 | 대화 + 미리보기 | 화면 대화 | 상태 줄(여정 · 받아오기 · `제출`) |

- 자리를 바꾸는 길은 사이드바의 세 줄 · ⌘K · 잇는 길(3.7)이다. 자리를 바꿔도 각 자리의 상태는 그대로 남는다 —
  미리보기 · 대화 칸 · 기획서 칸은 지금처럼 마운트된 채 숨는다(정본 §11 · Workspace 의 계약).
- `화면` 을 누르면 마지막 대화가 미리보기와 함께 선다. 대화가 없으면 새 대화의 빈 화면이 선다.
- `기획서` 를 누르면 마지막으로 본 문서가 선다. 처음이면 기준 페이지(목록의 뿌리 문서)가 선다. 별도 대시보드는 만들지 않는다(정본 §11).
- 기획서를 연결하지 않은 프로젝트도 `기획서` 줄은 선다. 본문은 지금의 연결 안내(설정 열기)다. 홈 · 화면은 예전과 같다(정본 §5).

### 3.2 사이드바

위에서부터:

1. **머리** — 앱 이름 · 접기(⌘B). 그대로.
2. **프로젝트 전환기** — 맨 위로 올린다. 프로젝트가 문서와 화면을 모두 담는 가장 바깥 맥락이라서다.
3. **자리 셋 + 찾기** — `홈`(기다리는 일 수 배지) · `기획서`(`초안 N` 흐린 글씨) · `화면`(AI 가 도는 동안 도는 표시) · `찾기 ⌘K`.
   지금 자리는 진한 바탕과 `aria-current="page"` 로 선다.
4. **목록 머리** — 목록의 이름과 만들기 단추. 화면 · 홈: `대화` + `+ 새 대화`(⌘T). 기획서: 기준 페이지 이름 + `+ 새 문서` +
   `⋯`(`새로 가져오기` · `휴지통` · `Confluence 에서 열기`). 지금 맨 위의 `새 대화` 큰 단추는 이 자리로 내려온다.
5. **목록** — 화면 · 홈: 지금의 날짜별 대화 목록 · 다른 프로젝트 줄 · 접힌 `도구가 한 일`. 기획서: 찾기 칸 · `작성 중인 초안`
   묶음(새 문서 초안 포함) · 문서 트리 · 맨 아래 가져온 때 한 줄(`3분 전 가져왔어요 · 문서 27개`).
6. **바닥** — `기능 제안` · 작성자와 설정. 그대로.

- 폭은 자리마다 기억한다. 홈 · 화면은 지금처럼 264px(220–420). **기획서는 320px(260–480)** 이다. 500개 · 깊이 6 · 긴 제목
  견본(`plans-fixture?case=big`)을 320px 에서 그려 보고 정했다 — 판 번호 칸(약 30px)을 빼고 들여쓰기를 단계당 12px 로 줄이면
  깊이 6 에서도 제목에 230px 가 남는다.
- 트리 줄에는 판 번호를 두지 않는다. 판은 문서 머리가 말한다. 잘린 제목은 손을 올리면 전체가 뜬다. 깊이는 옅은 세로 안내선으로 읽힌다.
- 기획서 자리에서는 다른 프로젝트 줄을 숨긴다 — 트리가 세로 자리를 쓴다. 다른 프로젝트의 급한 일은 전환기의 점 · 홈이 말한다.

### 3.3 머리 줄

모든 자리의 맨 위는 같은 높이(52px) · 같은 아래 선이다. 왼쪽은 「어디」, 오른쪽은 「지금 할 일」이다.

- **화면** — 지금의 상태 줄. 대화 제목(눌러 이름 바꾸기) · 여정 · `받아오기 N` · `제출`.
- **기획서 · 읽기** — 길 표시(`기획서 › 폴더 › 문서` — 가운데 폴더는 말줄임) · 오른쪽에 `Confluence 에서 열기`(아이콘 링크) · `화면에서 확인`(근거 보내기) ·
  으뜸 `고치기`(초안이 있으면 `초안 이어 쓰기`) · `⋯`(`복제` · `위치 옮기기` · `휴지통으로 옮기기`).
- **기획서 · 초안** — 길 표시와 `초안` 알약. 초안의 단추(`화면에서 확인` · `발행` · `닫기` · `초안 버리기`)는 바로 아래 초안
  머리의 오른쪽에 선다(2026-10-23 D3 의 두 줄 머리 그대로). 읽을 때와 같은 오른쪽 위 자리다.
- **홈** — 머리 줄이 없다. 사이드바를 접으면 지금처럼 펴기 단추와 프로젝트 이름이 선다.
- 사이드바가 접혀 있으면 어느 자리든 머리 줄 왼쪽 끝에 펴기 단추가 선다.

### 3.4 기획서 작업실

- **읽기** — 본문은 종이 한 장이다. 카드 속 카드를 걷는다. 글 폭은 760px 까지, 가운데 정렬. 제목 26px, 메타 한 줄
  (`판 12 · 3일 전 고침 · 초안 있음`), 읽는 글 15px · 줄 간격 1.7. 표 · 목록 · 제목은 화면에서 읽히고, 매크로 자리는
  옅은 점선 상자에 종류를 단다. 코멘트는 본문 아래 절이다.
- **초안** — 초안 편집기와 기획 대화가 나란히 선다(본문 폭 820px 이상 — 2026-10-23 D2 그대로). 기획 대화는 오른쪽이다
  (U1 「가운데로 옮기지 않는다」 그대로). 이제 화면 대화 칸이 처음부터 없으므로 초안이 열려도 배치가 튀지 않는다.
- **AI 입력창은 자리마다 하나다.** 기획서 자리의 입력창은 기획 대화의 것뿐이고, 읽는 동안에는 입력창이 없다.
  읽다가 AI 와 고치려면 `고치기` 다. M1 이 닫힌다.
- **빈 · 실패 · 만료** — 지금의 안내(연결 없음 · 가져온 문서 없음 · 읽기 실패 · 연결 만료)를 본문 가운데 한 장으로 세운다.

### 3.5 화면 작업실

구조는 지금 그대로다 — 상태 줄 · 대화 칸(400px · 320–640) · 미리보기. 고치는 것은 작은 요소다(4절 E · F · G).

- 대화 칸의 빈 화면은 화면 작업만 말한다. 기획서가 숨은 채 열려 있어도 「오른쪽이 기획서」 문장은 더 쓰지 않는다 — 오른쪽은 늘 미리보기다.
- 미리보기 칸의 오른쪽 얼굴이 기획서로 바뀌는 일은 없다. 기획서는 자기 자리를 쓴다.

### 3.6 홈

```
정인권님, 무엇을 만들까요?                          ← 인사(26px · 문장은 그대로 — 2026-10-23 U4)
스모크 서비스 · 기획서 8.8 ColoNova                 ← 한 줄(흐림)

[기다리는 일]                                        ← 있을 때만. 지금의 `답을 기다려요` 카드

┌ 기획서 ─────────────────┐ ┌ 화면 ──────────────────────┐
│ 작성 중인 초안(셋까지)    │ │ 입력창 · 첨부 · 모델        │
│ + 새 문서 · 기획서 열기    │ │ 시작점 칩                   │
└─────────────────────────┘ └────────────────────────────┘
(처음인 프로젝트만) 기획서 쓰기 → 화면 만들기 → 발행 · 제출하기

지금 진행 중 · 이어서 하기 · 방금 있던 일 · 반영된 일      ← 지금의 묶음 · 접기 그대로
```

- 두 카드는 본문 폭 1000px 이상에서 나란히, 그보다 좁으면 위아래로 선다. 순서는 일의 흐름대로 `기획서` → `화면` 이다.
- 기획서를 연결하지 않은 프로젝트는 `화면` 카드가 폭을 다 쓴다(지금 홈과 같다).
- 머리의 `현재 프로젝트 · 화면 열기` 는 걷는다. 프로젝트는 인사 아래 한 줄과 사이드바가, 화면은 `화면` 카드의 `화면 열기` 가 말한다.
- 받은 편지함의 묶음 · 셈 · 접힘 · 거둠 규칙은 바꾸지 않는다(GUIDE §3). 순서만 바꾼다 — `답을 기다려요` 가 맨 위다.

### 3.7 두 작업실을 잇는 길

| 길 | 어디서 | 무엇이 일어나나 |
| --- | --- | --- |
| `화면에서 확인` | 기획서 머리 줄 · 초안 머리 | 근거 범위를 고르는 판 → 화면 자리로 옮기고 입력창에 근거가 붙는다(지금의 근거 보내기) |
| 근거 칩 | 화면 대화의 `기획 근거` 줄 | 기획서 자리로 옮기고 그 문서(초안이면 편집기)가 선다 |
| ⌘K | 어디서나 | 문서 · 대화 · 프로젝트를 한 판에서 찾는다. 줄마다 종류 표시가 선다 |
| 홈의 두 카드 | 홈 | 초안 줄 → 기획서 자리, 입력창 → 화면 자리 |

`화면에서 확인` 은 지금 단추 이름 `화면 작업에 근거로 보내기` 를 줄인 것이다. 판 안의 설명과 `입력창에 담기` 는 그대로 둔다.

## 5. 시각 체계

토큰은 `packages/web/src/next/ui/tokens.css` 가 `.nx` 뿌리에 건다. 색은 지금처럼 활성 팔레트(`styles.css` 의 `html[data-theme]`)에서 온다.
앱 전체 크기는 데스크톱의 확대(⌘= · ⌘- · ⌘0 — `app-zoom.ts`)가 맡으므로 px 토큰이 그대로 함께 커진다.

| 무리 | 토큰 | 값 |
| --- | --- | --- |
| 글자 | `--fs-cap` · `--fs-sm` · `--fs-ui` · `--fs-read` · `--fs-lg` · `--fs-h3` · `--fs-h2` · `--fs-h1` · `--fs-hero` | 12 · 13 · 14 · 15 · 16 · 18 · 20 · 26 · 30 px |
| 줄 간격 | `--lh-tight` · `--lh-ui` · `--lh-read` | 1.3 · 1.45 · 1.7 |
| 굵기 | `--fw-regular` · `--fw-medium` · `--fw-semi` · `--fw-bold` | 400 · 500 · 600 · 700 |
| 간격 | `--sp-0_5` · `--sp-1` · `--sp-1_5` · `--sp-2` · `--sp-3` · `--sp-4` · `--sp-5` · `--sp-6` · `--sp-8` · `--sp-10` · `--sp-12` | 2 · 4 · 6 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 px |
| 반경 | `--r-sm` · `--r` · `--r-md` · `--r-lg` · `--r-xl` · `--r-pill` | 6 · 8 · 10 · 12 · 16 · 999 px |
| 높이 | `--h-xs` · `--h-sm` · `--h-md` · `--h-input` · `--h-lg` · `--h-row` · `--h-nav` · `--h-bar` | 24 · 28 · 32 · 36 · 40 · 32 · 34 · 52 px |
| 그림자 | `--elev-1` · `--elev-2` · `--elev-3` | 카드 · 팝 · 모달 |
| 초점 | `--focus` | 포인트 색(불투명 — 밝은 팔레트에서도 대비 3:1) |
| 글 폭 | `--w-read` · `--w-home` | 760 · 1040 px |

규칙:

- 사람이 읽는 글은 12px 아래로 내리지 않는다. 키캡(`kbd`)만 예외다.
- 반 픽셀 크기(12.5 · 13.5)를 새로 쓰지 않는다. 손대는 파일의 것은 가까운 토큰으로 옮긴다.
- 한 화면에 으뜸 단추는 하나다. 으뜸은 잉크 바탕이다. 포인트 색 바탕은 AI 에게 `보내기` 와 켜짐(토글 · 찍기 켜짐)뿐이다.
- 상태는 색만으로 말하지 않는다 — 글이나 아이콘이 함께 선다(정본 §11).
- 움직임 규칙(README 「움직임」 — `--nx-t-touch` · `--nx-t-move` · 등장은 새 줄에만)은 그대로다.

## 6. 바꾸지 않는 것

- 사용자 문장은 `labels.ts` 의 `L` 에만 있다. 사용자 단어는 보관 · 제출 · 반영됨 · 보내기 · 초안 · 변경안 · 채택 · 발행 안에서 쓴다.
  새 자리 이름(`홈` · `기획서` · `화면`)은 이미 앱에 있는 말이다.
- 숨는 칸은 마운트를 지킨다 — 미리보기 게스트(입력 · 스크롤 · 찍기), 화면 대화의 쓰던 글, 기획서 칸의 열린 문서 · 초안.
- 데몬 · 선로 · 프로토콜은 그대로다. 이 재설계는 `packages/web` 안의 일이다.
- 받은 편지함 · 여정 · 이번 작업 · 근거 · 초안 · 발행 · 코멘트의 판정과 문장 규칙(GUIDE)은 그대로다. 자리와 모양만 바뀐다.
- 겹판 계약(README 「겹판」 — `ModalFrame` · `Popover` · `InlineConfirm` · 토스트 한 길)은 그대로다.
- 키보드 · 초점 · 좁은 창의 기존 패턴(↑ ↓ 걷기 · Esc 층 · 서랍)은 그대로다.

## 7. 앞선 결정과의 관계

- **정본 §11 첫 문장(241줄)** 「기존 사이드바·대화·오른쪽 기획서/미리보기 구조를 확장한다」 → 「사이드바의 세 자리(홈 · 기획서 · 화면)로
  나눈다. 기획서 자리는 문서 트리와 문서, 화면 자리는 대화와 미리보기다」 로 고친다(2026-10-23 사용자 「처음부터 재설계해도 된다」).
  같은 줄의 「별도 대시보드나 두 번째 프로젝트 체계를 만들지 않는다」 와 「미리보기의 입력·스크롤·찍기 상태를 유지한다」 는 그대로 지킨다.

- **D4(홈의 기획서 묶음)** — `기획서` 카드로 남고 `화면` 카드와 나란히 선다.
- **U1(기획 대화를 가운데로 옮기지 않는다)** — 그대로다. 기획 대화는 문서 오른쪽이다.
- **D11 · U3(좁은 칸의 바닥 판)** — 그대로다.

## 11. 구현 결과(2026-10-24)

이 절은 S · H · D · C · P · F 구현과 S · D 후속 결함 수정이 합쳐진 코드의 결과다. 앞 절의 설계 당시 기록은 그대로 둔다.

자리를 옮겨도 미리보기 · 화면 대화 · 기획서는 마운트를 유지한다.

| 경우 | 구현 결과 |
| --- | --- |
| A. 틀 | 프로젝트 전환기 아래에 홈 · 기획서 · 화면 · 찾기를 놓고, 자리별 목록과 사이드바 폭을 나눴다. 찾기는 문서 제목 · 폴더 · 초성도 읽으며, 기획서 목록의 더보기는 자리 이탈이나 사이드바 숨김 때 닫힌다. |

| C. 기획서 읽기 | 트리와 문서를 함께 놓고, 본문은 최대 760px · 15px/1.7, 머리는 길 표시와 문서 단추로 정리했다. 첫 문서는 기준 페이지를 우선하며, 선택 줄은 본문 문서나 초안을 따라가고 근거 담기 뒤에는 화면 자리의 입력창으로 이동한다. |
| D. 기획서 쓰기 | 두 줄 초안 머리와 32px 단추, 아이콘 손잡이, 충돌의 세로 비교, 변경안의 전후 보기와 발행 확인 순서를 정리했다. 문서 관리의 자리 재확인 중에도 선택 초점을 지키고, 초안 버리기를 취소하면 더보기 단추로 돌아간다. |
